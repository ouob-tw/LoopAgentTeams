# 介面底線

每個畫面都要過的底線：照規格、守尺寸、交付前在手機寬度親眼看過。

資訊用圖形還是文字呈現、介面文字怎麼寫，照 `ui-copy`。畫面要在電子紙上用時，加套 `eink-ui`。

## 動手前

1. **讀設計規格。** 找專案根目錄的 `DESIGN.md`，或它指向的 CSS 變數、Tailwind 設定。顏色、字級、間距、圓角只用規格裡的值。
   沒有規格時，從既有畫面整理出正在用的值寫成 `DESIGN.md`（全新專案就提一份精簡版），給使用者確認後再照著做。
2. **列狀態表。** 每個畫面列出會出現的狀態，不適用的寫明原因：載入中、沒有資料、出錯、資料很多、文字很長、送出中、沒有權限。狀態表寫進票或回報，驗收照它逐項截圖。

## 尺寸底線

規格沒寫或寫得比這裡小時，以這裡為準：

- 畫面上所有文字至少 16px，包括欄位標籤、提示與錯誤訊息。
- 手機上可點的東西（按鈕、輸入框、選單）至少 44×44 px。
- 內文行高 1.6–1.8。
- 字重只用 400 與 700。多數中文系統字型沒有 500、600，瀏覽器會退回最接近的粗細，畫面上看不出層級。

## 驗收

用 agent-browser 打開真實頁面截圖並親眼看過，全部通過才算完成：

- [ ] 寬度 375 與 1280（`set viewport`），各自截淺色與深色（`set media dark|light`；專案只有一種主題就只截那種）。
- [ ] 狀態表每一項各截一張。正常操作觸發不到的狀態，用 `network route` 攔截請求回傳空資料或錯誤，或用 `set offline on` 做出來；真的做不出來的列在回報裡。
- [ ] 每張圖逐一檢查：文字沒有被切掉或溢出、頁面沒有左右捲動、對齊與間距照規格、深色主題沒有看不見的字或框線。
- [ ] 375 寬的表格與並排欄位：短名稱沒有被擠成一字一行，使用者要看的欄位不必左右滑才看得到。放不下時改成卡片或收起次要欄位，不靠表格內左右捲動。
- [ ] 用 `accessibility` 技能在頁面上跑一次檢查，用 `web-design-guidelines` 審查這次改到的檔案。
- [ ] 修完重截、重跑，直到上面都通過。

## Gotchas

- `Intl.NumberFormat('zh-TW', { style: 'currency', currency: 'TWD' })` 顯示成 `$1,280`，看不出是台幣。金額寫成 `NT$1,280`。
- 輸入框字級小於 16px 時，iPhone 點進去會自動放大整頁。
- 手機全高用 `100dvh`；`100vh` 在手機瀏覽器會被網址列蓋掉一截。
- `web-design-guidelines` 有幾條是英文介面的規則，中文介面不適用：英文字首大寫、彎引號、`...` 改 `…`（中文刪節號用 `……`）。按鈕與錯誤訊息的措辭，兩邊說法不同時以 `ui-copy` 為準。
