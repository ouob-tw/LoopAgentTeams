# 參謀

每個 LAT 主控配兩位參謀（一位 Claude、一位 Codex）。主控要對使用者發出 `DECIDE:` 或 `HELP:` 前，先交給兩位參謀各自判斷：在既有授權內可以定案的事由參謀定案、主控照辦；確實超出授權或只有使用者能提供的事，才照 SKILL.md「使用者待決事項」問使用者。參謀不能放寬授權。

## 適用範圍

- 主控準備對使用者發出的 DECIDE 與 HELP 都先諮詢參謀。
- 以下例外直接問使用者，不諮詢；待決紀錄照常狀態 `pending`，並寫參謀行 `- advisor: exempt <類別>`：

  | 類別 | 適用 |
  |---|---|
  | `spec-confirmation` | Spec 確認題，含確認後實質改版的再確認。 |
  | `requirement-discussion` | Spec 確認前的需求討論題。 |
  | `account-quota` | 沒有可用訂閱帳號、Claude 額度用完等規則明定由使用者決定的事。參謀本身缺一家時依「模型與降級」自動處理，不屬此例外。 |

- 參謀只處理原本要問使用者的事。執行 Agent 卡住回報給主控、主控在授權內本可自行裁決的事，仍由主控處理，不諮詢。

## 待決紀錄的狀態與參謀行

諮詢的事照樣在共用待決目錄 `.lat/decisions/<ID>.md` 建立紀錄，欄位同 SKILL.md「先記錄再問」。狀態行之外另有一行參謀行，緊接在狀態行下方；紀錄內其他行不得以 `- advisor:` 開頭，兩位參謀的意見寫在 `## 參謀意見` 段落。

| 狀態 | 意義 | 參謀行 |
|---|---|---|
| `advising` | 諮詢中，尚未問過使用者。不是 `pending`：遺漏檢查不要求面板題目，`lat-watch wait --for <ID>` 也不接受。 | 尚無 |
| `advisor-resolved` | 參謀定案或主控依參謀指示查證成功，已結案，主控照辦。 | `- advisor: resolved` 或 `- advisor: self-check` |
| `pending` | 交給使用者，只有真人答覆能解除。 | `- advisor: needs-human`、`- advisor: exempt <類別>` 或 `- advisor: late <結論>` |

- 參謀行讀法比照狀態行：取第一行以 `- advisor:` 開頭的行，鍵名與值都不分大小寫；第一個字決定結論，`exempt`、`late` 的第二個字決定類別或結論，其後可接註記。同家降級時在結論後加 `same-family-degraded`，例如 `- advisor: needs-human same-family-degraded`。
- 結束回合的 DECIDE 檢查要求每個寫出的題號都有 `needs-human`、`exempt <spec-confirmation｜requirement-discussion｜account-quota>` 或 `late <needs-human｜resolved｜self-check>` 參謀行；缺少或寫錯就攔下，補做順序見 [主控恢復程序](recovery.md) 的「回合結束檢查」。HELP 沒有題號，不受工具檢查，仍須先諮詢。

`## 參謀意見` 每位參謀一行：`<HCOM 名稱>（<client> <模型>）：<結論>；<理由與引用>`；再議時另起一行寫第二輪。`advisor-resolved` 紀錄另寫 `- authority:` 行，列出引用的授權來源。

## 諮詢流程

1. **記錄**：建立或更新待決紀錄，狀態 `advising`，寫明問題、選項、授權缺口與受阻工作。
2. **開參謀**：兩位參謀不在時依下方「生命週期」開啟。
3. **送出**：同一份諮詢訊息分別傳給兩位參謀；兩位各自回覆，不先看對方意見。
4. **等待**：其他工作做完後，以 `lat-watch wait --for <先需要回音的參謀名稱>` 聲明等待（另一位寫在 `--reason`）。
5. **合併**：依下方「意見合併」處理，更新待決紀錄。

### 諮詢訊息模板

```markdown
你是 LAT 主控 <主控 HCOM 名稱> 的參謀。請判斷下列事項是否已在既有真人授權內，或真的需要使用者。

- 題號與版本：<ID> r<版本>（待決紀錄：<決策目錄絕對路徑>/<ID>.md）
- 問題與選項：<問題>；A. … B. …
- 授權缺口：<為什麼主控認為可能超出授權，或缺什麼資訊>
- 受阻工作：<哪些 Ticket／步驟在等>
- Spec／tracker：<Spec 位置>；<tracker 設定位置>
- 待決目錄：<決策目錄絕對路徑>（含先前參謀的結論與真人答覆）
- 授權規則：<LAT 技能目錄絕對路徑>/SKILL.md 的「確認與自動推進」「使用者待決事項」；結論格式見同目錄 references/advisors.md 的「參謀結論」
- 限制：只讀不改，不修改程式、Spec、待決紀錄或任務卡；不聯絡使用者；只回覆主控。
- 回覆格式：第一行 `<ID> r<版本>: resolved <選項或做法>`、`needs-human` 或 `self-check`，下一行起寫理由；resolved 必須引用已確認 Spec 的具體段落，或含真人答覆證據的待決紀錄 ID 與版本。以 `hcom send` 回覆主控時一律用 `--intent inform`：結論不需主控回覆，主控需要更多時會再諮詢；用 `--intent request` 而主控沒回，HCOM 會送來「未回應」通知，讓你的待命被提前解除並被催促。
- 回覆後：以 `lat-watch wait --workspace <主控工作區> --agent <你的完整 HCOM 名稱> --for <主控完整 HCOM 名稱> --reason '<一句>'` 聲明待命再結束回合；完整名稱含 tag，短名會依 `hcom list --json` 唯一解析，撞名或查無名稱時拒絕寫入，清單讀取失敗時會警告並沿用輸入。
```

再議時在同一模板後附「另一位參謀的完整理由」；補做諮詢時註明「已問過使用者，題目維持 pending」。

## 參謀結論

- **`resolved`（定案）**：選某個選項或明確做法，並引用授權來源：已確認 Spec 的具體段落，或含真人答覆證據的待決紀錄 ID 與版本。引用不到就不能定案，只能判 `needs-human`。
- **`needs-human`（需要真人）**：寫明超出授權之處（改需求、擴大範圍、花錢、動帳號一律屬此），或為何只有使用者能提供。
- **`self-check`（可以自己查，主要針對 HELP）**：寫明去哪裡查。

## 意見合併

| 兩位結論 | 處理 |
|---|---|
| 都 `resolved` 同一做法 | 狀態改 `advisor-resolved`，參謀行 `- advisor: resolved`，寫 `- authority:` 與兩位意見，主控照辦。 |
| 都 `needs-human` | 狀態改 `pending`，參謀行 `- advisor: needs-human`，附兩位意見，依「使用者待決事項」寫面板、發 DECIDE／HELP。 |
| 都 `self-check` | 主控查證。查到 → 狀態改 `advisor-resolved`，參謀行 `- advisor: self-check`，寫明「自行查證」、查到的內容與位置；查不到 → 在紀錄寫明查證過程，再諮詢一次，參謀不能再回同一處 `self-check`。 |
| 不一致（含都 `resolved` 但選項不同） | 把另一位的完整理由轉給對方，再議一輪。仍不一致 → 視為需要真人，參謀行 `- advisor: needs-human`，附雙方說法交給使用者。 |

## 與真人授權的關係

- 參謀定案不是真人核准，而是「這件事已在既有真人授權內」的判斷；`advisor-resolved` 的效力完全來自它引用的授權來源。
- 主控與執行 Agent 的「雙方核對」：引用的是已確認 Spec 段落，或確有真人答覆證據的待決紀錄，就視為既有授權內，可以放行。引用缺失、引用的紀錄沒有真人答覆，或該事項先前已是送交真人的 `pending`，都停止相依工作並回報。
- `advising` 只用於還沒問過使用者的事。已寫進面板，或已用 DECIDE／HELP 問過使用者的 `pending` 事項，只有真人答覆能解除；參謀意見不能把它改成 `advisor-resolved` 或其他狀態。

### 補做諮詢

主控漏了參謀就先寫面板或發出 DECIDE（例如被 DECIDE 檢查攔下）時，仍須補做諮詢，但題目維持 `pending`，參謀行寫 `- advisor: late <結論>`：

- `late needs-human`：照常重列題目。
- `late resolved`／`late self-check`：題目不撤回；重列時在 `➡️` 行附參謀的建議做法與引用的授權來源，讓使用者可以直接採納，仍以真人答覆為準。
- 兩位不一致：照「意見合併」再議一輪；仍不一致記為 `late needs-human`，附雙方說法。
- 不得因為已經問過就直接填 `needs-human` 或改稱例外；`late` 行必須記下兩位參謀實際諮詢後的結論。

## 生命週期

- **第一次需要時才開**：依 /hcom-spawn 啟動與核對兩位參謀，tag 以主控名稱開頭、每次重開用新 tag。依 [任務卡](task-cards.md) 為每位建卡，orchestrator 欄填主控，由停住監控照常監控。主控在進度索引記錄目前參謀的 HCOM 名稱與 tag。
- **常駐待命**：參謀每次回覆後以自己的完整 HCOM 名稱（含 tag）執行諮詢訊息模板中的 `lat-watch wait` 指令，聲明待命再結束回合；短名依 `hcom list --json` 解析為唯一完整名稱並儲存，撞名或查無名稱時拒絕寫入，清單讀取失敗時在 stderr 警告並沿用輸入；聲明在收到新諮詢時失效，回覆後重新聲明。
- **階段交界關閉**：Spec 確認後、每批票整合完成後關閉兩位參謀，下次需要時再開全新參謀；任務交付或取消時一併關閉。
- **關閉順序**：先把任務卡 status 改為 `completed`、deliverable commit 填「無（參謀無提交）」並移到 `.lat/tasks/done/`，再依 /hcom-spawn 以 tag 關閉 Agent。順序反過來，停住監控可能把它當成意外消失而通知主控。
- **新參謀接手**：從 Spec 與待決紀錄（含先前參謀的結論）接手，不另寫交接摘要。
- **主控交接**：寫明目前參謀的名稱、tag 與狀態（待命、諮詢中哪一題、已關閉），接手主控據此沿用或關閉。

## 參謀失效

參謀停住、額度用完、模型滿載或意外消失時，[停住監控](stall-watch.md#主控處理監控通知) 通知主控，同時讓主控對它的等待聲明失效。主控依序處理：

1. 依 /hcom-spawn 查證存活。
2. 能接回 → 接回同一位，重送同一份諮詢訊息。
3. 不能接回 → 依「關閉順序」關閉它，開同家（不可用時依「模型與降級」）全新參謀，以同一份諮詢訊息重新諮詢。另一位已回覆的結論保留，不重問。
4. 重新聲明等待。

## 模型與降級

- Codex 參謀：`gpt-6-astra`，effort `medium`。Claude 參謀：依 /hcom-spawn 預設。
- Codex 額度用完先依 /hcom-spawn 換帳號。某一家仍不可用時，主控不問使用者，直接改用兩位同家參謀，參謀行加註 `same-family-degraded`。這是 [Agent 設定](agents.md)「不同家模型不可用時問使用者」的例外，只適用參謀。
- 兩家都不可用時才屬 `account-quota`：只就帳號、等待或替代方案問使用者；原本要諮詢的事維持 `advising` 並受阻，不改為直接問使用者。參謀恢復後照常諮詢。

## 回報

- 參謀定案不即時通知使用者。主控在批次成果與交付回報列出參謀定案清單：每項一行題號與一句結論，含自行查證結案的項目。
- 使用者推翻時，依 [待答問題面板](question-panel.md#聊天答覆與更正) 的更正流程新增更正紀錄，舊結論標為「已由更正項目取代」；沒有面板時同樣適用。
