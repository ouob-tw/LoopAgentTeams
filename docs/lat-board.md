# LAT 看板：安裝與使用

LAT 看板是跑在主機上的網頁服務。電腦與手機用同一個網址，就能看到所有專案的 LAT 主控目前做到哪、收它們的交付與求助回報、回答待決題、看完整的對話紀錄、直接傳話給主控，也可以新建主控、喚醒閒置或已關閉的主控，並切換主控的模型與思考強度。

它不顯示終端畫面，也不做手機推播。LAT 主控以外的 Agent 在「Herdr」分頁查看清單與對話紀錄，也可以傳話、中斷與關閉，有接 HCOM 的還可以切換模型與思考強度。Herdr 的待答面板照舊可用，兩邊可以同時使用。開發者與設定細節見 [board/README.md](../board/README.md)。

## 需要什麼

- 一個執行環境，Bun 或 Node 擇一即可，兩個都有也行：
  - **Bun**（實測 1.3.14）：安裝、建置、啟動、設定密碼都只用 Bun，主機不需要 Node。
  - **Node 22.17 以上**（實測 22.17.0）：用 npm 安裝與建置；`board` 指令改用 `node --experimental-strip-types src/cli.ts <指令>`（Node 22.18 以上可省略 `--experimental-strip-types`）。以下的 `bun install` 換成 `npm install`、`bun run build` 換成 `npm run build`、`bun run board <指令>` 換成上面那行。
  - 兩者都有時，伺服器用 Node 執行；只有 Bun 時由 Bun 執行。
- 已安裝的 LAT 技能，以及它一直在用的 `uv` 與 Python：看板不自己讀寫問題檔，一律呼叫技能裡的面板輔助工具。
- 傳話要用到 `hcom`。新建主控與喚醒還要用到 `herdr`（新建另需 `git`），而且看板要連得到正在執行的 Herdr（它的 socket）。

## 安裝與建置

```bash
git clone https://github.com/ouob-tw/LoopAgentTeams.git   # 已有本地工作區就略過
cd LoopAgentTeams/board
bun install
bun run build
```

## 啟動

```bash
bun run board start
```

預設監聽 `0.0.0.0:7100`。用 `--host`、`--port` 改位址與連接埠，例如 `bun run board start --host 127.0.0.1 --port 7200`；也可以用環境變數 `HOST`、`PORT`。之後在主機上用 `http://127.0.0.1:7100` 開啟。其他設定（狀態目錄、技能位置等）都是環境變數，見 [board/README.md](../board/README.md) 的設定表。

預設只接受主機自己（`127.0.0.1`、`::1`）的連線；其他機器連進來，連登入畫面都看不到，只會得到 403。要從其他機器用，見「[連線來源與反向代理](#連線來源與反向代理)」。

在某個 Agent 的終端機或 Herdr 窗格裡啟動看板也可以：看板新建、喚醒或接回主控時，不會把那個 Agent 的身分（hcom 名稱、client 的 session 等環境變數）和那個窗格的位置傳給 hcom，所以新主控不會變成那個 Agent 的子 Agent，第一則訊息也不會多出「把結果回傳給它」的句子，新主控也不會被記成跑在看板所在的窗格，效果與背景服務相同。萬一 hcom 記的主控窗格就是看板所在的窗格，切換 Codex 模型時看板會拒絕停止主控，不會關掉看板自己的窗格。

## 登入

看板登入分兩步：先輸入密碼，再用 passkey，或輸入手機驗證器 App 上的六位數字（TOTP）。兩步都通過才算登入；沒登入的瀏覽器只看到登入畫面，什麼資料都拿不到。密碼要先在主機上設定，passkey 與 TOTP 至少要有一種（兩種都設最方便：passkey 不能用時改輸入數字）。

**設定密碼**：在主機的 `board` 目錄執行

```bash
bun run board password
```

輸入時畫面不顯示，要輸入兩次且一致才生效。還沒設定密碼時，登入畫面會提示這個指令，任何人都無法登入。

**設定 TOTP（第二道驗證）**：在主機的 `board` 目錄執行

```bash
bun run board totp
```

終端機會顯示一個 QR code、一個 `otpauth://` 網址與金鑰。用手機的驗證器 App（Google Authenticator、Microsoft Authenticator、1Password 等）掃描 QR code，不能掃描時手動輸入金鑰；接著在終端機輸入 App 上現在顯示的六位數字，對了才生效（有 3 次機會，都不對就什麼都不改）。金鑰存在看板狀態目錄的 `totp.json`，只有擁有者能讀寫；QR code 和金鑰等同第二道驗證，不要截圖或傳給別人。還沒設定 TOTP 時，任何人都無法用密碼登入，登入畫面會提示這個指令。

**設定看板網址（passkey 要用）**：passkey 綁在網址上，看板要知道自己從哪個網址開。在服務設定加上 `LAT_BOARD_URL`，例如經反向代理從 `https://lat.ouob.net` 開時：

```ini
Environment=LAT_BOARD_URL=https://lat.ouob.net
```

passkey 只在這個網址能登記與使用（它的主機名稱就是 passkey 的網域，即 RP ID；要讓 passkey 屬於上一層網域時另設 `LAT_BOARD_PASSKEY_RP_ID`，例如 `ouob.net`）。從其他網址、內網位址或 http 開看板時，登入畫面會說 passkey 只能在哪個網址用，這時改輸入 TOTP 數字；只登記了 passkey、沒設 TOTP 時就要改從那個網址開。沒設 `LAT_BOARD_URL` 時不能用 passkey，只能用 TOTP。`LAT_BOARD_URL` 要是 https 網址（http 的，連 localhost 也不行，看板與主機指令都不會啟動）；看板本身不加密，https 由前面的反向代理負責，代理要設成信任代理。

**登記 passkey**：每把 passkey 都要一組主機產生的登記碼，只知道密碼的人沒辦法自己登記。

1. 在主機的 `board` 目錄執行 `bun run board passkey code`，終端機會印出一組登記碼（例如 `K7MXQ-2RHWP`）。它 10 分鐘內有效，登記成功一次就失效；再產生一組新的，舊的那組也隨即失效。
2. 在要登記的裝置上從看板網址打開登入畫面，按「登記 passkey」，輸入密碼與登記碼，按「建立 passkey」，照瀏覽器或手機的提示（指紋、臉部、螢幕鎖或安全金鑰）建立。
3. 畫面顯示「已登記 passkey」後就可以登入。

手機、電腦各登記一把時，每把都要一組新的登記碼。同一個裝置不能重複登記。看板的 passkey 與 pd 的 passkey 是分開登記的：在 pd 登記過的 passkey 不能登入看板，看板的也不能核准 pd 的請求。

**列出與刪除 passkey**：

```bash
bun run board passkey list              # ID、登記時間、最後使用時間、登記時的瀏覽器
bun run board passkey delete <ID>       # 刪除後那把 passkey 不能再登入
```

**登入**：在任何瀏覽器打開看板，輸入密碼按「下一步」。登記過 passkey、又從看板網址開時，第二步是「使用 passkey」，按下後照瀏覽器提示完成；要改輸入數字時按「改用驗證碼」，輸入 App 上現在顯示的六位數字按「登入」。輸入密碼後 5 分鐘內要完成第二步，超過就回到密碼那一步重來。每組數字只能登入一次，兩台裝置要一起登入時，第二台等 App 換下一組數字。登入後這個瀏覽器保持登入 30 天，重新載入或關掉瀏覽器再開都不必再輸入；但連續 7 天沒開看板，或登入滿 30 天，就要重新登入。換瀏覽器或清掉網站資料後也要重新登入。測試用登入不需要第二步，照它自己的到期時間，不受這兩條限制。

**變更密碼**：再執行一次 `bun run board password`。新密碼立即生效，舊密碼不能再登入，不必重啟看板。已登入的裝置不會因此登出；要讓某台登出，用下面的 `revoke`。

**忘記密碼**：看板不能從登入畫面重設密碼，也查不回原本的密碼（只存加鹽的雜湊）。到主機上執行 `bun run board password` 設一組新的即可。

**更換 TOTP**：再執行一次 `bun run board totp`，掃描新的 QR code 並輸入一次數字。確認後舊金鑰立即失效，App 裡舊的那一筆產生的數字不能再登入，可以刪掉。已登入的裝置不會因此登出。

**清除 TOTP**：`bun run board totp clear`。清除後只能用 passkey 登入；也沒有 passkey 時，任何人都無法用密碼登入，直到重新執行 `bun run board totp` 或登記 passkey。已登入的裝置不會因此登出。

**手機遺失或換手機**：看板沒有備用碼，要到主機上處理：

1. 執行 `bun run board totp`，用新手機掃描，舊手機上的那一筆隨即失效。
2. 遺失的手機登記過 passkey 時，用 `bun run board passkey list` 找出它（看登記時間與瀏覽器），`bun run board passkey delete <ID>` 刪掉；新手機用新的登記碼再登記一把。
3. 遺失的手機本身登入過看板時，用 `bun run board devices` 找出它（看瀏覽器與登入時間），再 `bun run board revoke <裝置 ID>` 讓它登出。
4. 懷疑密碼也外流時，再執行 `bun run board password` 換一組密碼。

**輸錯密碼或數字**：同一個來源位址輸錯 5 次後（passkey 驗證沒通過、登記時密碼或登記碼不對也各算一次），1 分鐘內一律拒絕（密碼與數字正確也一樣），畫面會顯示要等幾秒；期滿後恢復。密碼錯與數字錯算在同一個計數裡，只有兩步都通過、真的登入時才歸零；只答對密碼不會歸零，所以反覆「密碼對、數字錯」一樣會被鎖。計數與鎖定存在看板的狀態目錄，重啟看板後仍有效。每次鎖定會在服務紀錄留一行 `login_locked`，帶被鎖的位址。看板放在反向代理後面時，要把代理設成信任代理（見「[連線來源與反向代理](#連線來源與反向代理)」），才會依瀏覽器真正的位址計算；否則經過代理的連線共用代理位址的計數。

**管理已登入的裝置**：

```bash
bun run board devices            # 列出已登入的裝置（ID、登入時間、瀏覽器；測試裝置另標標籤與到期時間，登入已失效的另標出來）
bun run board revoke <裝置 ID>   # 撤銷一台裝置，它會回到登入畫面
```

**升級到兩步登入的版本**：之前登入的裝置（含配對碼版本配對的）都要重新登入一次，`devices` 清單裡標為登入已失效；測試用登入不受影響。升級後先在主機上執行 `bun run board totp`（或設好 `LAT_BOARD_URL` 再登記 passkey），否則誰都登入不了。`bun run board pair` 已移除；狀態目錄裡留下的 `pairing-codes.json` 不再使用，可以刪掉。

## 測試用登入

讓 QA 或 Agent 在看板上做端到端測試，又不必給它密碼：測試用登入看得到全部，只能操作它自己建立的 Agent，到期自動登出。

**發一組**：在主機的 `board` 目錄執行

```bash
bun run board test-login --hours 4 --label qa-498 --url http://<主機>:7100
```

- `--hours` 預設 4、最多 24；`--label` 是之後在看板與操作紀錄上看到的名稱；`--url` 是對方打開看板用的網址（預設用主機名稱與 `PORT`）。
- 印出一個登入網址，只能用一次：用瀏覽器打開、按「以測試裝置登入」，這台瀏覽器就是**測試裝置**。網址再用一次、或到期後才用，都會被拒絕。

**測試裝置能做什麼**：

- 看得到所有分頁與資料：名冊、待辦、Herdr 分頁、對話紀錄、終端、額度。畫面上方有一條「測試裝置」標記，整個視窗加框。
- 用「新建主控」或 Herdr 分頁的「開新 Agent」建立的 Agent（含主控），它可以傳話、按鍵、中斷、切換模型、暫停／恢復通訊、關閉、改分頁名稱與排序。這類 Agent 在 Herdr 分頁標「自己建立」。
- 對其他 Agent，上面這些按鈕都停用並寫明「測試裝置只能操作自己建立的 Agent」；就算直接呼叫 API，看板也回 403 與原因。
- 不能回答待決題或看板提問、不能改設定裡的全局設定與預先授權、不能標已讀或未讀、不能核准或拒絕 pd 請求、不能接回已關閉的 Agent、不能搬移或關閉工作區、不能切換權限模式。主題、字體這些只記在這台瀏覽器的個人設定照常可改。
- 它做的每個動作在操作紀錄（送出紀錄）裡都記下是哪台測試裝置、標籤是什麼。

**查看與收回**：`bun run board devices` 會在測試裝置那一列標明「測試裝置「標籤」到期 時間」，還沒用過的網址標「網址尚未使用」，過期的標「已到期」並列出它建立、仍在執行的 Agent。`bun run board revoke <裝置 ID>` 立即收回，同時列出它建立、仍在執行的 Agent。看板不會自動關掉這些 Agent，由你決定要不要關。

## 在背景常駐

範例檔 [board/lat-board.service](../board/lat-board.service) 是 systemd 使用者服務，登出與重開機後都會自動恢復。

1. 先確認 `bun run build` 已完成，並用 `command -v node uv hcom herdr git` 查出這些指令所在的目錄（只有 Bun 的主機把 `node` 換成 `bun`，並把範例檔的 `ExecStart` 改成 `/usr/bin/env bun build/index.js`）。
2. 複製範例檔並把 `<...>` 換成實際值：`WorkingDirectory` 填專案裡的 `board` 目錄；`PATH` 要含上面查到的目錄，因為服務的 PATH 很短，找不到 `uv` 或 `hcom` 時，待決題與傳話會失敗；找不到 `hcom`、`herdr` 或 `git` 時，新建主控會失敗。Herdr 的 socket 不在預設位置時，另外加一行 `Environment=HERDR_SOCKET_PATH=<socket 路徑>`（在 Herdr 分頁裡執行 `echo $HERDR_SOCKET_PATH` 可以查到）。

   ```bash
   mkdir -p ~/.config/systemd/user
   cp lat-board.service ~/.config/systemd/user/   # 在 board 目錄執行
   ```

3. 啟用，並讓它在沒登入時也跑：

   ```bash
   systemctl --user daemon-reload
   systemctl --user enable --now lat-board
   loginctl enable-linger "$USER"
   ```

4. 查狀態與紀錄：`systemctl --user status lat-board`、`journalctl --user -u lat-board`。

要改位址或連接埠，改已複製的 `~/.config/systemd/user/lat-board.service` 裡的 `HOST`、`PORT`（改專案裡的範例檔不會生效）；其他設定（例如允許來源與信任代理）用同樣方式加一行 `Environment=`，改完 `systemctl --user daemon-reload && systemctl --user restart lat-board`。

### CPU 群組：測試不拖垮看板

主機上測試與看板搶同一份 CPU 時，過載會讓看板逾時。`scripts/install-cpu-slices.sh` 做兩件事，可重複執行：

- 建立使用者層的 `lat-tests.slice`（`CPUWeight=30`、`CPUQuota=2000%`，即全部測試加起來最多 20 核心）。`suite-gate.py` 與 host-guard 建議的 `systemd-run` 指令都用 `--slice=lat-tests.slice` 把測試放進去。
- 替 `lat-board.service` 加 `~/.config/systemd/user/lat-board.service.d/cpu-weight.conf`（`CPUWeight=500`），搶 CPU 時看板優先。

```bash
scripts/install-cpu-slices.sh      # 第一次執行會寫出設定檔，之後讀它
systemctl --user show lat-tests.slice -p CPUWeight -p CPUQuotaPerSecUSec
systemctl --user show lat-board.service -p CPUWeight
```

**調整數值**：改 `~/.config/lat-cpu/slices.conf` 的 `TESTS_CPU_WEIGHT`、`TESTS_CPU_QUOTA`、`BOARD_CPU_WEIGHT`，再執行一次腳本。權重只在真的搶 CPU 時才生效；`CPUQuota` 設太低，測試會被節流而變慢，用 `cat /sys/fs/cgroup/user.slice/user-$UID.slice/user@$UID.service/lat.slice/lat-tests.slice/cpu.stat` 看 `nr_throttled`。腳本內的 `daemon-reload` 會讓執行中的看板立刻套用新權重，不必重啟（以 `show` 的結果為準）。（單位名稱裡的 `-` 會讓 systemd 把它放在 `lat.slice` 底下，所以路徑多一層。）

**移除**：`scripts/install-cpu-slices.sh --remove` 刪掉 slice 與看板的設定並重新載入（設定檔保留）。沒有 `lat-tests.slice` 時測試照常執行，只是沒有上限。已在跑的測試會留在原來的限制裡直到結束。環境變數 `SUITE_GATE_SLICE` 可改 suite-gate 使用的群組名稱，設成空字串就不放進任何群組。

套用在主機上的 cgroup 限制需要使用者層 systemd 已委派 `cpu`（`systemctl show user@$UID.service -p DelegateControllers`）。這台主機沒有委派 cpuset，所以 `AllowedCPUs` 不會生效，限核心數請用 `taskset` 或 `CPUQuota`。

用背景服務時，主機上的 `password`、`totp`、`devices`、`revoke` 仍照「登入」一節手動執行。若你改了狀態目錄（`LAT_BOARD_STATE_DIR`）或其他設定，這些指令與 `inbox`（含部署後印出的那次）要用相同的環境變數，否則改到或讀到另一份資料。

## 待辦與已處理

待辦只列還要你處理的：還沒回答的待決題、還沒讀過的交付與求助回報，以及還沒結束的看板提問（見「在看板回答 Agent 的提問」）。

- 點開一筆交付或求助回報，會打開該主控的資訊頁、停在對話紀錄裡那則訊息（以回報的樣式顯示，上下標出較新、較早的訊息）；主控已不在名冊上時照舊只顯示回報內容。
- 點開一筆回報就算已讀，所有裝置一起同步；畫面還停在它時它留在待辦，打開別項或回到列表後才移到「已處理」。想晚點再處理時，按回報下方的「標為未讀」，它就回到待辦；畫面還停在這筆回報時它會維持未讀，下次點開才又變成已讀。
- 按待辦上方的「已處理 N」切換到已處理清單，新到舊列出已讀的回報、發出滿 7 天的回報（不論已讀未讀）與答過的題目，依處理的時間排。未滿 7 天的回報可以在這裡「標為未讀」移回待辦；滿 7 天的仍可打開看全文，但不能再改已讀狀態，也不能移回待辦。
- 答過的題目以卡片顯示：選的選項打勾並標上顏色，「其他」與備註另外列出；主控的對話紀錄裡也是同樣的卡片。
- **看板提問**：每筆還沒結束的看板提問是待辦的一筆。標題寫 Agent 名稱、種類（提問／權限確認）、第一題（權限確認寫工具名稱），等待中的另顯示剩餘時間。點開到該 Agent 的頁面，停在那張題目卡；主控的權限確認點開是主控資訊頁。在待辦點進去作答與在 Agent 頁面作答是同一份狀態，任一邊作答另一邊跟著變。已填回、已逾時、已傳話、結果不明、已中斷、Agent 已不在的提問移到「已處理」並標結果，與其他項目一起依結束時間排，滿 7 天連同提問紀錄一起消失。已逾時的從「已處理」點進去仍可作答，答案當訊息傳給它。
- 待辦可以依時間或依專案排序，選擇記在各自裝置的瀏覽器裡。看板提問依時間排時，還能作答的排在最前面；依專案排時，排在 Agent 工作資料夾所屬的專案底下（查不到資料夾的歸「（未知）」）。
- 清單一次載入 50 筆，捲到底會自動載入更早的，也可以按「載入更早」；載入失敗時按這個按鈕重試。
- 只保留一個月：發出滿 30 天的回報、提問滿 30 天的題目不再列出；一個對話的回報最新一筆也滿 30 天時，看板會把整個回報檔刪掉，**刪掉的回報救不回來**。閒置或已關閉的主控回報被刪掉後，就不會再出現在看板上，也無法從看板喚醒；還在運作的主控照常顯示。

## 回答待決題

在待辦點開待決題，直接在內容區作答：單選、複選、純文字，選擇題可改填「其他」，每題都可以加備註。送出後由看板寫入問題檔並通知主控，效果與在 Herdr 待答面板作答相同；兩邊可以同時使用，同一題先送出的答案算數。

- **題目怎麼顯示**：進入該主控的對話紀錄，題目卡片出現在主控提問的那則訊息的位置，答覆、記錄、重新整理或主控之後再提到同一題都不會移動，依序是說明、選項、推薦與詳細資訊，畫面停在被打開的那一張。同一則訊息一次問了好幾題時，那則訊息的位置會一張接一張顯示所有仍在待辦的題目，其他題同樣可以作答，答過的以唯讀卡片顯示。主控還在提問的那一回合、訊息還沒出現時，卡片先放在對話最新的位置。實在找不到提問的訊息時，只顯示卡片並註明「找不到提出這題的原訊息」。
- **送出後**：該題顯示「已送出，等主控記錄」；主控記錄後從待辦移到「已處理」，標「已回答」。在主控的送出紀錄裡，狀態會變成「已記錄」；送出後題目被主控改版則顯示「題目已改版」。在 Herdr 面板作答的不在這份紀錄裡。
- **答過的題目**（唯讀卡片）：選中的選項加勾號與強調色（複選每個選中項都有），答「其他」時多一列「其他：<內容>」，純文字題的答覆也是一列，備註顯示在選項下方的淺色框「你的備註：…」（沒有備註就不顯示），「已處理」與對話紀錄用同一個版面。
- **題目被改版**：你開始作答後主控改了題目（升版或改內容），畫面改顯示目前的版本並提示，送出會被拒絕、問題檔不會被寫入；你填的文字與備註保留，選項要重選。
- **不能作答的情況**：已經送出過的題目（例如在 Herdr 面板）、閒置與已關閉主控的待決題都不能作答。答覆不符合題型或寫入失敗時，畫面顯示原因，你填的內容留著。
- **通知主控失敗**：答案已寫入但通知主控失敗時，顯示「已送出，但通知主控失敗」與「重新通知」按鈕，所有裝置都看得到。按下才會重送，看板不會自己重送，重送也不會改寫答案；仍送不到時，請在聊天告訴主控。
- **主控停用 LAT 後**：還在等記錄的答覆，看板會再讀一次它留下的問題檔，顯示「已記錄」、「題目已改版」、「主控已停用 LAT，沒有記錄這份答覆」，讀不到時顯示「主控已停用 LAT，無法確認這份答覆有沒有被記錄」。

## 傳話給主控

在底部的指令列輸入文字（`@名稱 訊息`；不寫名稱時送給目前開著的主控）。名稱帶 tag 的主控（hcom 名稱如 `dipo-latpstack-tevu`）在看板各處只顯示最後一段 `@tevu`，滑鼠停留可看到完整名稱；`@tevu` 與 `@dipo-latpstack-tevu` 都能指定它，實際傳話仍用完整名稱。最後一段對到不只一個主控時不送出，提示「名稱重複，請打完整名稱」並列出候選。看板把文字打進該主控 client 的輸入框並送出，不經過 HCOM 訊息，所以主控把它當成你本人在那個分頁打的字。

- **對象與失敗**：送出前看板會重讀資料、確認主控仍啟用；對象是閒置或已關閉的主控時改為喚醒（見下節）。失敗時以通知顯示原因，文字留在輸入框，不會自動重試，也不會改走別的管道。
- **不要同時在那個分頁打字**：兩邊的文字可能混在一起送出。
- **多行**：多行文字以一則訊息送出。
- **Enter 與送出鈕**：畫面寬度 760px 以下，或只有觸控、沒有滑鼠或觸控板的裝置，Enter 換行、按按鈕送出；其他情況 Enter 送出、Shift+Enter 換行。輸入法選字時的 Enter 不會送出。
- **skill 名稱提示**：對象是 Claude 時，在行首或空白後打 `/`；對象是 Codex 時打 `$`，就會跳出它能用的 skill（它已安裝的，加上它工作資料夾裡的專案 skill；不列 `/model` 這類 client 內建指令，也不混列另一種 client 的），每項附描述的第一句，依打的字篩選。上下鍵移動、Enter 或 Tab 插入（Claude 寫成 `/名稱`、Codex 寫成 `$名稱`）、Esc 關閉且不改文字，手機直接點選。清單開在輸入框上方，上方放不下而下方較寬時才開在下方；看得到的範圍以螢幕鍵盤上方為準，手機鍵盤打開時清單不會落在鍵盤後面。對象依指令列的 `@名稱`、開著的主控或 Agent 判斷。路徑或字中間的 `/`、輸入法選字中都不會跳出；讀不到清單時只是不提示，照樣可以送出。Claude Code 內建的 skill（如 `/simplify`）與 claude.ai 帳號帶來的 skill 沒有可讀的檔案，不會出現在清單裡。
- **手機**：同一個指令列固定在畫面底部（在螢幕鍵盤上方），分成兩行：第一行只有輸入框（送出鈕在框內右側）；第二行由左到右是模型與思考強度、迴紋針、麥克風、選項按鈕（有權限可切換或要喚醒時才有），第二行永遠只有一行，內容放不下（例如模型名稱很長）時這四項可以左右滑動，最右邊的 ▾ 固定不動，把指令列收成右下角的圓鈕，選擇記在裝置上。在頁面上其他輸入框打字（例如新建主控的第一句話、提問卡的答覆框）而螢幕鍵盤開著時，指令列先收起、不蓋住那個框，連圓鈕也不顯示；鍵盤收起或游標離開那個框就恢復，打到一半的草稿還在。手機不顯示收件對象，只有用 `@名稱` 指定開著的主控以外的對象時，輸入框上方顯示「→ @名稱」。
- **權限切換**：開著 Claude 或 Codex 的 Agent 頁，或 Herdr 清單上找得到的主控頁時，點輸入列右側的選項按鈕，「權限」段列出三種模式並標出目前的；點另一種就直接切換（Claude 由看板先把它的分頁捲到最下方再按 Shift+Tab，所以分頁捲在上方時會被帶到最下方，切換沒成功也一樣，Codex 會停止它再接回同一段對話），結果以浮動通知顯示。不能切換時段裡寫出原因，模式不能點。
- **紀錄**：每次傳話不論成敗都記下來，在該主控的資訊頁可以看到，所有已登入裝置看到的相同。

## 名冊收合

電腦版面（寬度超過 760px）的名冊可以收成窄直條：按名冊上的收起鈕收起，按直條頂端的展開鈕展開（鍵盤也能操作）；點名冊或直條的空白處不會收起或展開。收起的狀態重新整理後仍會記得。手機版面不受影響。

## 主控職責

主控記下自己負責做什麼之後，看板在這些地方顯示：

- **名冊卡片**：目前階段下面多一行職責，放不下時截斷；手機的名冊標籤顯示在名字下面。
- **說明框**：滑鼠停在名冊卡片或收起名冊的圓點上，或在手機上長按名冊標籤，會跳出說明框：上面是狀態與目前階段，下面是完整職責與結果。長按不會打開主控，輕點才會。目前階段（主控最新回報的摘要）與主控資訊頁上的同一段文字，裡面 `[文字](網址)` 形式的 http／https 連結會顯示成可點的連結、在新分頁開啟，其餘字照原樣；說明框可以把滑鼠移上去點連結（離開卡片後約 0.2 秒內移進框裡就不會消失），手機長按出現後也能點。連結以外的 Markdown 不處理，`javascript:` 等非 http／https 連結只顯示原文。
- **主控資訊頁**：「詳細資料」的第一列。
- **Herdr 分頁**：卡片上不顯示。滑鼠停在卡片上會跳出說明框（取代原本瀏覽器的小提示），主控的會加上職責；按右鍵或長按跳出的選單最上面也有。

結果一欄在交付前是主控寫的「預期結果」；記下職責之後有了交付（DONE）回報，就換成最近一則的摘要，標「已交付結果」。還沒記下職責的主控照舊顯示，不會出現「未填」。

職責、預期結果與已交付結果同樣支援 `[文字](網址)` 形式的 http／https 連結：說明框、主控資訊頁與 Agent 清單顯示成可點連結（新分頁開啟），名冊卡片因整張卡可點，只顯示連結文字、不放連結。職責的 40 字上限算顯示出來的字數，連結只算「文字」。

回報與題目的標題同樣支援 `[文字](網址)` 形式的 http／https 連結：卡片內容的大標題與送出紀錄裡的題目標題顯示成可點連結（新分頁開啟），標題裡的裸網址照舊是連結；收件匣列表、待決提示條與名冊卡片上的最新回報摘要因整列（整張卡）可點，只顯示連結文字、不放連結，點列的行為不變；`board inbox` 指令輸出的標題也只含連結文字。連結以外的 Markdown 不處理，`javascript:` 等非 http／https 連結照原文顯示、不可點。看板提問（Agent 的提問與權限確認）的標題是 Agent 自己問的話或工具名稱，不是回報標題，不處理連結。

主控啟用 LAT 時會拿到記錄指令（`lat-session.py duty`），任務改變時再執行一次就會覆蓋。還沒記下就發出 DECIDE、HELP 或 DONE 時，回合結束檢查會攔下一次，提醒它先記下。職責存在回報紀錄目錄的 `<session>.duty.json`，回報檔滿 30 天刪除時一起刪。

## 新建主控

按名冊頂端的「新建」（收起的名冊是底部的 ＋ 圖示），表單由上而下是資料夾、Herdr 工作區、第一句話、一列設定（client：Claude 或 Codex、模型、思考強度）、送出鈕，最下面是最近新建的紀錄。資料夾預先帶入最近用的那個，只打第一句話就能送出。看板會在該專案的 Herdr 工作區開一個新分頁，用 hcom 在那個資料夾啟動 client，第一則訊息是 LAT 啟動指令加上你的話：Claude 是 `/lat 你的話`，Codex 是 `$lat 你的話`。「模型」「思考強度」兩欄的第一項寫出不選時會用的值（例如「預設：Opus 5.5（claude-opus-5-5）」「預設：medium」），是看板從該 client 的設定檔讀到的，Claude 會疊上所選資料夾的專案設定；讀不到時寫「讀不到 client 設定，交給 client 內建預設」。不選就不帶參數，用該 client 平常的設定（選項見[模型與思考強度](#模型與思考強度)）。主控啟用後會自動出現在名冊上。從看板新建的 Claude 主控會以 `--dangerously-skip-permissions`（bypass permissions）啟動。喚醒、換模型或從「已關閉」接回 Claude 時，看板保持它接回前的權限模式（以對話紀錄最後一則使用者訊息的模式為準），不在看板啟動的主控也一樣。以 `--dangerously-skip-permissions` 啟動（例如從看板新建）、後來在對話裡改成別的模式的主控，接回後維持那個模式，但這段對話之後就不能再用 Shift+Tab 切回免確認模式。Codex 不受影響。

- **skill 名稱提示**：第一句話（開新 Agent 是第一則訊息）的輸入框和指令列一樣會提示 skill，對象是表單選的 client 與資料夾（見[傳話給主控](#傳話給主控)的「skill 名稱提示」）。
- **資料夾**：一個輸入框，輸入完整路徑（`~` 代表執行看板的使用者的家目錄）。游標在這個框裡時，底部的指令列先收起（手機上收成的圓鈕也一樣），離開後恢復，打到一半的草稿還在。還沒改過時點進去，下拉列出最近用過的 5 個專案（從主控回報紀錄整理）。一開始打字就即時列出：名稱或路徑含有輸入文字的已知專案，以及輸入路徑所在那一層、名稱含有最後一段的子資料夾（不分大小寫，開頭符合的在前；最後一段以「.」開頭時才列隱藏資料夾；指向資料夾的符號連結也列出）。每列寫出名稱、路徑、是否在 Git 專案裡，已知專案另寫最近使用時間，或「資料夾已不存在」。上下鍵移動、Tab 把該資料夾補進輸入框並加上 `/` 繼續往下一層找、Enter 或滑鼠點選選定、Esc 關閉下拉；選定不會送出表單。
- **等搜尋結果時**：新結果回來前，清單繼續顯示上一次的結果，按鍵照常操作這些列；只是 Tab、Enter 要選的那列不符合現在打的字時，Tab 不動作、Enter 只收起清單，打的字不會被換掉。真的沒有符合時清單不收起，顯示「沒有符合的資料夾」；搜尋或專案清單讀取失敗時顯示「讀不到資料夾清單」。
- **資料夾還不存在時**：輸入框下方寫「這個資料夾還不存在，送出時會建立並 git init」，送出時看板建立它（中間缺的層一起建），再 `git init`、啟動主控（建在既有 Git 專案裡也一樣，新資料夾自成一個專案）。只會建在家目錄底下，以真實路徑判斷，經符號連結跑出家目錄也不行；家目錄以外的路徑不能送出，並寫明原因。建立失敗時不啟動主控，這次建出的空資料夾會移除；資料夾建好但 git init 失敗時，資料夾留著、不啟動主控。紀錄會標示「已新建資料夾」。
- **不在 Git 專案裡的資料夾**：主控在那裡不能啟用，所以選定這種現有資料夾時才出現「不在 Git 專案裡：先 git init 再開」，勾選才能送出。勾選後看板先在該資料夾執行一次 `git init`，成功才啟動主控；失敗會顯示原因，不會啟動。Git 專案裡的子資料夾可以直接開，主控在該子資料夾啟動。
- **開在哪個 Herdr 工作區**：資料夾下方的「Herdr 工作區」選單預設「自動」，也可以改選 Herdr 目前列出的任一工作區，或「新建工作區…」：選了會出現名稱欄，預設是所選資料夾的名稱、可以改，送出時才建立並把主控開在裡面。選了的工作區在送出前被關掉、或新建失敗時，通知寫明原因、表單內容保留，不會改開到別的工作區。「自動」以專案為準，Git 專案看整個專案（根目錄），不在 Git 專案裡的看資料夾本身。看板找出已經有分頁停在這個專案裡的工作區，有好幾個時取分頁最多的、再取編號最小的；都沒有就以專案資料夾的名稱新建一個工作區（不會切換你的畫面）。
- **送出後**：新建主控頁下方列出最近的新建紀錄與狀態，所有已登入裝置看到的相同，重新載入後仍在。狀態有：啟動中、已啟用、「已開分頁，但主控尚未啟用，請到 Herdr 分頁查看」（等了 3 分鐘還沒啟用時）、「結果不確定，請到 Herdr 分頁查看」（看板沒拿到新主控的名稱時），以及失敗與原因。新主控的分頁一出現在 Herdr，這筆紀錄就多一個「看這個 Agent →」按鈕，按下打開看板上這個 Agent 的頁面，不必等主控啟用；主控啟用、出現在名冊上後，按鈕改成「看主控資訊 →」。看板不會自動換頁，也不會切換 Herdr 的焦點。主控啟用後，這筆紀錄也會出現在它的資訊頁的送出紀錄。新主控出現在 Herdr 的清單上後，看板會把它的分頁移到該工作區最前面；移動失敗不影響主控啟動，紀錄裡會寫明原因。同一時間只跑一個新建（與 Herdr 分頁的開新 Agent 共用），後送的會等前一個出現在 Herdr 或逾時後才開始。
- **失敗時**（資料夾無法建立、讀不到面板綁定登記、Herdr 或 hcom 執行失敗）：畫面顯示原因，表單內容保留，可以修正後再送。看板不會自動重試。
- **要留意**：每次新建都會在 Herdr 多開分頁，主控開始後就會用到額度。第一次在某個資料夾開 Claude 時，Claude 可能先問「是否信任這個資料夾」，這要到 Herdr 分頁按；看板只會在等太久時提示你去看。

## 喚醒閒置或已關閉的主控

不在工作的主控依「對話還在不在」（看 hcom 的 Agent 清單）分兩種：

- **閒置**（名冊上的標記是空心圓）：LAT 這一輪已停用，對話還開著。
- **已關閉**（空心菱形）：對話已經不在 hcom 清單上，不論 LAT 有沒有正常停用。

兩者處理方式相同：只在還有發出未滿 7 天的回報（已讀的也算）時留在名冊，待決題不再列出也不能作答，送話都走以下的喚醒。名冊依「等你、進行中、已交付、閒置、已關閉」分組，組內最近回報的在前；閒置或已關閉、最後回報超過 1 天的收在名冊最後的「閒置／已關閉 N ›」，點開依最後回報時間分成 3 天內、1 週內、更早。看板每次重讀資料時才判斷，主控關掉後最慢要等保底重讀（預設 60 秒）才會改成已關閉；LAT 還沒停用的主控之後又在 hcom 清單上出現（例如你在終端機接回）就恢復為啟用中，已停用的則回到閒置。hcom 清單讀不到時會跳出錯誤通知，並沿用上一次讀到的結果；看板剛啟動、還沒讀到過時，LAT 還沒停用的照常顯示為啟用中，已停用的顯示為閒置。

閒置的主控在主控資訊頁有「關閉」按鈕，進行中的主控有「關閉 Agent」，作用都與 Herdr 分頁的「關閉 Agent」相同：先確認一次，關掉它的對話與 Herdr 分頁，成功或失敗都跳出通知；之後它顯示為已關閉，仍可從資訊頁喚醒接回。按鈕只在 Herdr 的清單上找得到它時出現；看板自己所在的分頁不能關，HCOM 連線無法確認時按鈕停用。看板不會自己關掉主控。

進行中的主控若在 Herdr 的清單上、而且有接 HCOM，主控資訊頁在「關閉 Agent」旁還有「暫停通訊」（暫停中變成「恢復通訊」）與說明圖示，作用與 Herdr 分頁的相同（見下方 Herdr 分頁的說明）。暫停中的主控在名冊與資訊頁標「暫停通訊」，仍算進行中、不會變成已關閉，待決題照常列出可以作答；你從看板傳的話照樣打進它的輸入框。

用底部的指令列（電腦與手機相同）：對象是閒置或已關閉的主控時（開著它的資訊頁，或用 `@名稱` 指定），送出按鈕會變成「喚醒」，旁邊的選項按鈕裡多出額度提醒；模型與思考強度在指令列的模型標籤上選。

- **開新一輪 LAT**：自己在訊息開頭打 `/lat 你的話`。送給 Codex 主控的訊息若以 `/lat` 開頭（後面是空白、換行或結尾），看板送出前換成 `$lat`（Codex 用 `$lat` 叫出技能）；`/latest`、句中的 `/lat` 與送給 Claude 的訊息都照原文。一般傳話、喚醒與接回都一樣，送出紀錄顯示實際送出的文字。
- **喚醒後**：送出紀錄記「已喚醒」；主控沒有開新一輪就仍顯示閒置，開了新一輪、重新啟用後在名冊上變回啟用中，回覆與待決題照常回到看板。
- **怎麼送**：看板先問 hcom 這段對話的 client 還在不在。還在（分頁還開著）就像傳話一樣打進它的輸入框；不在（分頁已關）就用 hcom 把同一段對話接回來，在該專案的 Herdr 工作區開新分頁，你的話當作第一則訊息，只送一次。工作區的選法與新建主控相同。
- **接回的結果**：hcom 回報就緒時記「已喚醒」；hcom 還在等啟動或指令逾時，記「已開始接回，結果尚未確定，請到 Herdr 分頁查看」，不算失敗也不會自動重試；其他失敗顯示原因，文字留在輸入框，可以再按一次。接回 3 分鐘後還沒出現時，那筆紀錄補上「接回後仍未出現，請到 Herdr 分頁查看」。
- **不會接回兩次**：前一次接回還沒確定結束時，再按喚醒會先查證：對話已經回來就改成打進輸入框；hcom 還看得到它，或前一次開的分頁還在，就擋下並說明「前一次接回還沒結束，請到 Herdr 分頁查看」；確定前一次的分頁已經不在，才再接回一次。看板重啟後也照樣擋。
- **放棄前一次接回**：看板連前一次開在哪個分頁都不知道時，會擋下並出現「放棄前一次接回」按鈕。按下後會先跳出確認：請先到 Herdr 關掉前一次的分頁；這個按鈕不會幫你關，沒關就再接回可能出現兩份對話。確認後那筆接回記為「使用者放棄」，之後就能再喚醒；取消則什麼都不變。
- **無法確認時不送**：讀不到 hcom 的 Agent 清單時，看板不接回也不送出，顯示「無法確認主控是否還在，沒有送出」，文字留在輸入框。
- **順便換模型**：看板確認主控的 client 已經不在時，指令列的模型標籤（例如「Opus 5.5・M」）可以點開選模型與思考強度，預設「保持目前」；選了就在接回時一起帶上。client 還在時標籤停用並說明原因。當初指定過模型的 Codex 主控，模型同樣停用、只能改思考強度。
- **切換沒完成時不喚醒**：這個主控有一次切換還沒確認已經停掉時，喚醒會被擋下，請先按模型標籤旁的 ⚠ 再按「繼續切換」，以免同一段對話跑出兩份。
- **新分頁的位置**：接回開的新分頁會移到該工作區的最前面，其他分頁的先後順序不變；移不動時留在最後面，不影響喚醒。
- **要留意**：接回會在 Herdr 多開分頁，也會開始消耗額度。

## 中斷主控這一回合

在 Herdr 有窗格、而且這一回合正在跑的主控，指令列的送出鈕左邊會多一顆和 Herdr 分頁 Agent 頁面相同的紅色停止鈕，有沒有打字都一樣，可以中斷它這一回合：按一次就直接對它的窗格按一次 Esc，等同在終端機按 Esc，沒有確認框；送出還沒有結果前停止鈕停用，連按不會送第二次。通知會寫出中斷的是哪個主控。回合有沒有在跑看的是 HCOM 的狀態（工作中或等待輸入才算在跑；HCOM 沒有這個主控時改看 Herdr 的狀態，和一般 Agent 相同），不是名冊上的處理中、等你、已交付：回合自然結束、主控閒著等回報時，停止鈕在 5 秒內消失、只剩送出鈕，不用重新整理，名冊上的狀態照舊。按 Esc 中斷（在看板或在終端機按都一樣）的情況，HCOM 常常不知道回合已經結束、一直回報工作中，所以看板在 HCOM 說工作中、Herdr 卻連續兩次讀取（相隔約 1 秒）都說閒置或已完成時，改當作閒置，停止鈕在 5 秒內消失；只有一次讀到閒置（例如回合剛開始、Herdr 還沒跟上）不會讓停止鈕消失。打字不會讓停止鈕消失，按停止鈕也不會清掉打好的文字；停止鈕只中斷目前頁面的這個主控，指令列用 `@名稱` 指定別人時照樣如此。閒置、已關閉的主控沒有停止鈕。按 Esc 失敗（窗格已不在、Herdr 指令出錯或逾時）時通知寫出原因，看板不會重試。成功或失敗都記在它的送出紀錄裡。中斷後看板不會自動傳話或喚醒。

## 模型與思考強度

底部指令列送出按鈕旁的標籤顯示對象主控上一回合使用的模型與思考強度，以縮寫表示（例如「Opus 5.5・M」，強度 L／M／H／XH／MX；滑鼠停留看完整名稱），是從主控自己的對話紀錄讀出來的；讀不到時顯示「模型」「強度」。

- **選項**：Claude 有 `claude-opus-5-5`、`claude-sonnet-5-5`、`claude-haiku-5-5`、`claude-fable-5-2`，Codex 有 `gpt-6.1-sol`、`gpt-6.1-terra`、`gpt-6-astra`，思考強度都是 `low`、`medium`、`high`、`xhigh`。清單可用環境變數 `LAT_BOARD_MODEL_OPTIONS` 改（見開發者說明）；看板只照清單顯示選項，不檢查模型是否真的能用。
- **修改**：點標籤的模型或思考強度選新值，改過的部分變成強調色，再按 ✓ 一次套用（模型與強度一起改只會重開一次），✕ 取消。只改你選的那一項，不能選「回到 client 預設」。
- **怎麼換**：Claude 與 Codex 主控都一樣：看板會停掉它（`hcom kill`，原本的 Herdr 分頁會被關掉），確認停掉後再用新設定把同一段對話在新分頁接回來（Claude 用 `--model`、`--effort`，Codex 用 `-c`），和傳話排在同一個隊伍。只有 hcom 顯示它在等待（`listening`）時才會動手，正在工作、等你處理或狀態不明時，看板會請你等這回合結束再改。
- **不在對話裡打指令**：看板不會在 Claude 對話裡打 `/model` 或 `/effort`，因為 Claude Code 會把這兩個指令的選擇存成你之後新對話的預設，還可能跳出確認框。用接回時的參數換，只影響這一個主控，不會改你的設定檔。
- **只換模型時**：思考強度選「保持目前」時，看板會把上一回合用的思考強度一起帶上，免得換模型後變回該模型的預設；切換與喚醒都一樣。讀不到上一回合的思考強度時就不帶，送出前會提示「無法確認目前的思考強度，換模型後可能改用該模型的預設」。
- **主控不在時**：有沒切完的切換時，標籤旁出現 ⚠，點開有那筆切換與「繼續切換」「放棄切換」；沒有的話標籤停用並提示「主控目前沒有在跑，請在喚醒時一起選」。
- **當初指定過模型的 Codex 主控**：啟動參數裡有 `--model`、`-m` 或 `--oss` 時，接回後模型換不過去，所以標籤的模型會停用並說明原因，只能改思考強度。看板讀不到當初的啟動參數時，會提示「無法確認這個主控能否換模型」，照樣讓你試，再以下一回合核對結果。
- **沒切完的切換**：停止失敗、停止逾時，或停止後還看得到主控或原本的分頁，看板都不會接回，這筆「切換嘗試」會讓模型標籤旁出現 ⚠（看板重啟後也在），點開寫著舊設定、新設定與目前卡在哪一步。到 Herdr 看過後按「繼續切換」，看板會先查證：確定已經停掉就接回；主控還在而且在等待就重新停止；主控還在而且正在工作就拒絕；仍無法確認就保留並請你到 Herdr 查看。接回失敗時同樣按「繼續切換」再接回一次；接回後主控出現在 hcom 清單上，這筆嘗試就結束。不想繼續時按「放棄切換」，先確認一次，會結束這整次切換，看板之後不會再停止或接回它，放棄本身也不執行任何指令。
- **有沒有換成**：送出後標籤先顯示新設定並加虛線底線（「已送出切換，等下一回合確認」；主控資訊頁與 Herdr 分頁的 Agent 頁面都一樣），等新設定實際送出（打入或接回）之後的下一個回合再比對：和你選的一樣就清掉提示（隨模型一起帶上的思考強度不算你選的，不比對）；不一樣就在標籤旁出現 ⚠，點開顯示「切換沒有生效」和實際使用的值。Codex 的規劃模式另有自己的思考強度設定，看板不改。
- **要留意**：切換會關掉原本的分頁、再開一個新分頁（移到該工作區最前面），也會用到額度。

## 對話紀錄

點開主控（啟用中、閒置或已關閉都可以），標頭一行顯示狀態、專案、名稱與最後回報時間（還沒有回報時不顯示；client 與模型看指令列的模型標籤），職責、專案路徑與 Herdr 位置收在「詳細資料」；有待決題時標頭下方出現黃色提示條，點「作答」直接打開題目。下方分成「對話紀錄」「回報」「送出紀錄」三個分頁，預設是對話紀錄，最新的在最上面，列出你打的每句話和主控的每段文字回覆，包括回合中途的回答；文字以 Markdown 顯示。

- 待辦裡的交付或求助回報在對話中那則訊息加上綠框與「完成／求助」標籤。
- 主控在兩段文字之間做的事合成一行灰字「⋯ 做了 N 個操作」，點一下展開成每個操作一行的摘要，例如「🔧 執行指令：git status」；失敗的操作前面有「✗」。不會顯示指令輸出或檔案內容。
- hcom 通知、hook 提示這類自動塞進對話的內容不算你說的話，只算成操作（「📨 收到 hcom 通知」「🪝 hook 提示」）。
- 一開始顯示最近 50 段，往下捲到底會自動再往前取 50 段，也可以按底部的「載入更早」。
- 頁面開著時，主控寫下新內容 5 秒內會出現。剛開的 session 還沒有紀錄時只顯示「還沒有對話」，不跳通知；其他讀不到紀錄的情況會跳出通知說明原因，其他區塊照常。
- 往下捲在讀較舊的段落時，最上面接上新內容、上方的回覆翻譯完成或圖片載入而變高，畫面中間正在讀的那段都留在原位；停在最上面時，新內容照常出現在最上面。
- 紀錄來自 Claude 或 Codex 自己存的對話檔。你改過 `CLAUDE_CONFIG_DIR` 或 `CODEX_HOME` 時，背景服務也要加上相同的 `Environment=`。
- **我說過的話**：主控頁與 Agent 頁的對話紀錄右側有「我說過的話」清單，列出整段對話裡你自己打的話（看板傳話、終端機打字都算；hcom 通知與 hook 提示不算，判斷和對話紀錄相同），每則一行：只有第一行文字（太長就截斷，不顯示時間），最新的在最上面，不只已載入的 50 段。對話裡新說的話 5 秒內出現在最上面（清單打開時）。對話很長時先顯示最新的部分，更早的在背景讀完後補上。清單平常完全不出現，沒有常駐按鈕也沒有遮罩：電腦把滑鼠移到視窗最右邊緣（約 8px）清單就直接出現（沒有動畫），貼齊右邊緣、上下置中，內容少時只有內容那麼高，內容多時最高為視窗全高並在清單內捲動；滑鼠在清單上或清單周圍約 24px 內都保持打開，離開才收回，所以不會來回抽動；後面的對話照樣看得到也點得到。手機從右邊緣往左滑叫出同一份清單，點選一則或點清單外就收回。點一則，對話紀錄捲到那一則並短暫標亮，清單收回；那一則還沒載入時，自動往前載入直到出現，載入中在右側邊緣顯示「載入中…」，失敗時說明原因並有「重試」。其他分頁（回報、送出紀錄等）沒有這份清單。
- 讀不出來的行會略過，這一區上方註明「有 N 行紀錄讀不出來，已略過」；client 還在寫的最後一行不算。
- 操作摘要只顯示安全的內容：寫檔與改檔只顯示路徑，讀檔與搜尋顯示路徑或搜尋字串，讀網頁只顯示網址（不含 `?` 之後的參數）；指令只有整段是一行、而且只用英文字母、數字、空白與少數符號時才完整顯示（最多 80 字），其他指令只顯示程式名稱（例如「git …」），連程式名稱都看不出來時只顯示「執行指令」。

### 對話翻譯

分頁列（對話紀錄／終端／回報／工作總表／送出紀錄／預先授權／操作紀錄）最右邊的翻譯圖示：按下亮起，畫面上的英文回覆顯示成繁體中文，再按一下回到原文。只在選中「對話紀錄」分頁時出現（已關閉 Agent 的頁面也一樣）；主控資訊頁與 Herdr 分頁的 Agent 頁都有。分頁放不下時（例如手機上把最小字級調大），分頁列可以左右滑動，選中的分頁會自動捲到看得見的位置，翻譯圖示固定在最右邊。

- **設定**：設定裡的「對話翻譯」可選「自動翻譯」或「手動切換」（預設手動），所有已登入裝置共用。自動翻譯時打開對話就顯示中文；手動切換時顯示原文，圖示不亮。
- **圖示只改目前這個對話**：換到別的對話或重新整理後，又回到設定的偏好；沒按過圖示的對話會跟著偏好的變更即時改變，按過的維持按的結果。手動切換且沒按圖示時，看板不會翻譯任何內容，關閉翻譯時還沒回來的翻譯也會中止。手機寬度時分頁照樣平分寬度，圖示固定在最右。
- **翻哪些**：只翻主控或 Agent 的文字回覆，而且要是英文為主（程式碼、行內程式碼、網址與路徑不算）。你的訊息、操作行、以題目卡或回報卡顯示的訊息都不翻（列在對話紀錄裡、帶「完成／求助」標記的回報照常翻）；只翻已載入到畫面上的段落。
- **顯示**：還沒翻好的段落顯示原文並在標頭標「翻譯中」，翻好原地換成中文，下方「看原文」可展開或收起英文原文。程式碼區塊、行內程式碼、網址與路徑與原文完全相同。
- **失敗**：留著原文，下方小字「翻譯失敗，顯示原文（原因）」，不跳通知；換到別的對話再回來、重新整理，或關閉再開啟翻譯會重試，同一段失敗後 5 分鐘內再被要求會得到同一個失敗。
- **花費與存放**：翻譯由主機上的 Codex 執行，會用到 Codex 額度；譯文存在看板的狀態目錄、所有裝置共用，同一段文字只翻一次，30 天沒用到的清掉。

### 用量與快取

主控還在跑時，目前階段下方有一行小字，例如 `上下文已用 62% • 5 小時額度剩 40% • 7 天額度剩 25% • 快取命中 70% 20 分鐘後失效 • 權限：自動模式`：上下文已用多少、訂閱額度還剩多少、快取命中率與幾分鐘後失效、權限模式。Claude 主控的數字跟它終端機的狀態列相同。設定裡的「用量列」可改成「精簡」，這行改用狀態列的英文縮寫，例如 `Ctx 62% • 5h 40% • 7d 25% • Cache 70% ⏳ 20 min • Auto mode`（Codex 權限寫成 `approval on-request`）；隱藏與變色規則不變，資訊圖示的說明與「詳細資料」裡的執行狀況仍是中文全稱。預設「詳細」；這個設定存在看板的狀態目錄，所有已登入裝置共用，在任一台改了其他裝置立刻跟著變，不必重新整理。

- **只顯示需要留意的**：在安全範圍的項目會隱藏：上下文已用 10% 以下、5 小時額度剩超過 45%、7 天額度剩超過 30%、快取命中超過 80%、倒數超過 30 分鐘、權限是免確認。全部都隱藏時整行（連同資訊圖示）不顯示。快取還沒建立時顯示 `快取尚未建立`，已失效顯示紅色的 `快取已失效`，這兩個一定會顯示。
- **看全部數值**：行尾的資訊圖示，滑鼠停留或手機點一下，會列出所有數值；點別處關閉。主控資訊頁的「詳細資料」裡也有一列「執行狀況」，是完整的一行、什麼都不隱藏。
- **變色**：上下文已用到 80%、額度剩不到 20%、快取剩 5 分鐘以內會變黃；倒數每分鐘自動更新，主控有新回合後整行也會自動更新。Codex 主控沒有失效倒數，額度依它回報的期間標示（例如只有週額度時只有 `7 天額度剩`）。
- **權限模式**：放在最後。Claude 取自對話紀錄裡最後一則使用者訊息當時的模式，所以用 Shift+Tab 切換後，要等下一則訊息才會更新；Codex 顯示 rollout 裡的核准與沙箱設定。

Claude 主控的這些數字只有狀態列拿得到，要先在 `~/.claude/settings.json` 的 `statusLine.command` 原本的指令前面串上看板附的記錄程式，沒裝之前 Claude 主控不顯示這一行（Codex 主控不需要）。它需要 `bash` 與 `jq`，只記下用量數字，不存訊息、路徑或憑證，記錄失敗時不影響狀態列。

**安裝**：在原本的指令前面加上 `bash <看板目錄>/scripts/usage-recorder.sh `，其餘不動。例如原本是

```json
"statusLine": { "type": "command", "command": "bash ~/.claude/statusline-command.sh" }
```

改成

```json
"statusLine": { "type": "command", "command": "bash /path/to/LoopAgentTeams/board/scripts/usage-recorder.sh bash ~/.claude/statusline-command.sh" }
```

後面的指令照樣由 shell 拆成程式與參數，引號寫法不用改。但原本的指令若以環境變數設定開頭（例如 `FOO=1 cmd`），或用了 `|`、`&&`、`;` 這類組合，要整段包成 `bash -c '<原指令>'` 再接在後面，否則狀態列會變空白。只想記錄、不要狀態列時，後面可以不接指令。新的設定在下一次狀態列更新時生效，不用重啟 client。你改了 `LAT_USAGE_DIR` 時，狀態列與看板服務都要設定相同的值（見 [board/README.md](../board/README.md) 的設定表）。

**移除**：把 `statusLine.command` 前面加上的那段刪掉，再視需要刪除 `$XDG_STATE_HOME/lat/usage`（沒設定 `XDG_STATE_HOME` 時是 `~/.local/state/lat/usage`）。

### 工作總表

主控資訊頁的「工作總表」分頁一張票一行，每行有：

- 票號連結、標題與進度條。
- 現在在做什麼。
- 各階段用的模型與思考程度。
- 用時；修過的票接著寫「修 N 輪」（結案後補交新版本與接續的 Agent 列各算一輪）。
- 找到的問題：依發現階段寫件數，例如「審查 2（乙 1）・驗收 0」。
  - 審查、驗收、上線後（使用者）這三個階段做完後，沒有問題也寫 0，和「還沒做」分得開；其他階段有問題才出現。
  - 有甲或乙級的階段用紅色粗框標出。

點開一行會列出：

- 時間花在哪：草稿、每一輪實作（其中跑測試另列一行，畫在實際跑的時間）、審查、等實作、QA 實測、等合併、等上線、等使用者，各段畫在同一條時間軸上，重疊的段看得出重疊。
  - 預設一段一行；按「三條」改成做事、QA、等待三條，放得下的色塊上寫段名與分鐘數，下面列各段分鐘數。這個選擇記在這台裝置上。
  - 每種段的顏色與花紋不同，在 e-ink 上也分得出。點一段（色塊或段名）在下方顯示它的開始、結束時間與分鐘數，再點一次收起；仍在進行的段畫到現在，結尾有箭頭，寫「進行中」。
  - 查不到的時間寫「不明」，不畫色塊（只知道一端時在那一端畫一條短線），不拿其他時間代替。例如審查者不是由 HCOM 開的，或在聊天中問使用者的題目。
  - 最下面一行是做事與等待的總時間（重疊只算一次），括號內是其中跑測試與等使用者的時間。
  - 窄螢幕上段名與分鐘數放在色塊上方，時間軸用滿整個寬度，不會左右捲動。
- 組成這張票的各個 Agent 列與它們的證據。結案的列另有結案時間、改動大小（程式、測試、文件各改幾檔幾行）與測試執行時間（實際跑測試的時間與次數；沿用先前結果的另計次數；排隊等候沒有紀錄，不算在內）。在這些數字出現前結案的列，這幾格留空不顯示。
- 這張票的每一筆問題：級別、一句話內容、發現階段、發現者、第幾版候選、記錄時間、有沒有被測試抓到，以及處理結果。

總表最下面的「哪個階段找出多少問題」，每個發現階段一列，列出甲、乙、丙、合計與其中測試抓到的件數。這裡每筆問題只算一次，也包含透過這份總表記下的、上線後才發現的問題（造成它的票不在本輪，或查不出是哪張票）。

問題由 Agent 與主控用 `lat-ledger.py` 記下，看板只顯示，不能在這裡新增或修改。記下新問題後，頁面會自動更新。

## Herdr 分頁

中間欄上方有「待辦」「Herdr」與「額度」三個分頁（額度見下方「額度分頁」），點「Herdr」（舊稱「所有 Agent」）改列出 Herdr 所有工作區裡的每一個 Agent，包括 LAT 主控、主控派出的 Agent，以及你在其他專案自己開、沒有接 HCOM 的 Claude 與 Codex。看板記得你上次看的是哪一個分頁；主控名冊、待辦與主控資訊頁不受影響。這個分頁可以開新 Agent、檢視、傳話、中斷、關閉、切換模型，以及調整 Herdr 的分頁順序與改分頁名稱。

- **列出哪些**：以 Herdr 的 Agent 清單為準，依 Herdr 工作區分組，組內照 Herdr 裡的分頁與窗格順序排列，狀態改變不會讓位置移動。Herdr 的每個工作區都會列出標題，沒有 Agent 的工作區在標題下寫「沒有 Agent」。只在 hcom 裡、不在 Herdr 裡的 Agent（例如 tmux 裡的或子 Agent）不列出；Agent 從 Herdr 消失後也會從清單消失。
- **每一筆顯示什麼**：標題是 Herdr 分頁名稱，後面以小字接著 HCOM 名稱（例如「2 · sema」；分頁名稱已含 HCOM 名稱時省略，分頁名稱太長放不下時也省略），以及狀態、client 種類與專案資料夾；LAT 主控（綁定中，包括 client 已關閉、回報都已封存而不在主控名冊上的；或已停用 LAT 但還有未封存回報）旁標「主控」，點開是主控頁。沒有分頁名稱時用 HCOM 名稱，沒接 HCOM 的只顯示分頁名稱（沒有時用終端機標題）。Agent 頁面的標題是名稱，後面以小字接著「· 分頁名稱」。
- **狀態從哪裡來**：有接 HCOM 的 Agent 顯示 HCOM 回報的狀態，沒接的顯示 Herdr 回報的狀態，因為 Herdr 對接了 HCOM 的 client 回報的狀態有時不準。
- **HCOM 連線無法確認**：讀不到 hcom 的 Agent 清單時，看板沿用上次讀到的結果，原本有接或沒接的照舊顯示。看板剛啟動還沒讀到過，或讀不到期間才出現的 Agent，會標「HCOM 連線無法確認」，名稱與狀態暫用 Herdr 的；之後讀到清單就恢復正常。
- **讀不到 Herdr 的清單時**：會跳出錯誤通知說明原因，畫面沿用上一次讀到的清單。
- **什麼時候更新**：只要有頁面開著，看板預設每 2 秒（閒置與工作中相同）單獨讀一次 HCOM 與 Herdr 的 Agent 清單，狀態有變才推到畫面，所以 Agent 的狀態（工作中、閒置）、Herdr 分頁清單、Agent 卡片與停止鈕通常 5 秒內更新；從看板傳話或中斷後約 2 秒內會多讀一次。沒有頁面開著時不讀，一次讀不到或太慢（超過 4 秒就放棄）時沿用上次的結果，不影響其他資料。Agent 開啟、關閉等其他變化與其他資料仍照整批重讀（保底預設最慢 60 秒），按重新整理會立即整批重讀。
- **點進 Agent**：版面與主控資訊頁相同：上方一行是狀態、名稱、專案資料夾與 HCOM 連線，下面是和主控一樣的用量小字；專案路徑、Herdr 位置（例如「LAT（工作區#1）・2（分頁#2）」）、狀態來源與 Session ID 收在「詳細資料」裡，開合與主控資訊頁共用同一個設定。再下面是對話紀錄，顯示方式與主控相同：最新的在最上面，往下捲到底載入更早的內容，頁面開著時自動接上新內容。剛開的 session 還沒寫下紀錄時只顯示「還沒有對話」，寫下後自動出現；其他讀不到的情況跳出通知說明原因。
- **點進主控**：標「主控」的 Agent 點開後仍留在 Herdr 分頁，顯示的是主控資訊頁的全部內容：狀態與目前階段、詳細資料、用量、每個待答題目的提示列，以及對話紀錄、回報、送出紀錄分頁；另外多了「關閉 Agent」與「操作紀錄」分頁，分頁順序是對話紀錄、畫面、回報、送出紀錄、操作紀錄（終端分頁見下方）。對話紀錄裡，DECIDE 與 HELP 題目在提出它的訊息處顯示題目卡，可以直接作答；DONE 回報顯示回報卡，可以標已讀或標未讀；NO REPLY 照舊是一般文字。作答與已讀狀態和待辦分頁是同一份，在哪一邊做另一邊都會跟著變。點待答題目的提示列或回報分頁裡的一則，會切到對話紀錄並捲到那張卡片，不會離開 Herdr 分頁；和待辦一樣，點開未讀的回報就會標為已讀。指令列的模型與思考強度用主控那一套（與主控資訊頁相同）。模型切換未完成、已不在 Herdr 裡的主控，照下面「切換未完成」的方式顯示。
- **還不能點開的 Agent**：Herdr 還沒回報 session ID 的 Agent 照樣列出，但不能點開，清單上會註明原因；等 Herdr 回報後就能開啟。
- **傳話**：開著 Agent 頁面時，畫面下方的指令列就是傳給這個 Agent 的輸入框（以 `@名稱` 開頭的仍傳給那個主控；每個 Agent 的草稿分開保存）。打字送出後，文字會打進它的輸入框並送出，效果跟你在終端機親手打字一樣，Agent 會當成是你本人說的話。失敗時跳出通知說明原因，文字留在輸入框，看板不會自動重送。沒接 HCOM 的 Agent 正停在需要核准的確認畫面時，Herdr 會拒收，通知裡是 Herdr 給的原因。HCOM 連線無法確認時指令列停用並說明原因，讀到 hcom 清單後恢復。開著主控頁時，指令列和主控資訊頁完全相同：執行中的主控把文字打進它的輸入框，閒置或已關閉的就喚醒它（送出鈕變成「喚醒」；前一次接回卡住時，選項裡有「放棄前一次接回」），都記在它的送出紀錄裡；草稿是所有主控共用的那一份，所以在這裡打到一半、換到待辦分頁的主控資訊頁還在。看板升級前在 Herdr 分頁打給主控、還沒送出的草稿，第一次在這裡打開該主控時會移進共用草稿：共用草稿是空的就直接帶入，兩邊都有字就接在後面、中間空一行；移過一次就不再移，也不會自動送出。
- **中斷**：一般 Agent 正在工作時，指令列送出鈕左邊會多一顆紅色的停止鈕，有沒有打字都一樣，按停止鈕不會清掉打好的文字；按一次就直接對它按一次 Esc，沒有確認框，送出還沒有結果前停止鈕停用，等同在終端機按 Esc；有沒有接 HCOM 都可以，HCOM 連線無法確認時也可以。開著主控頁時照主控的規則（見[中斷主控這一回合](#中斷主控這一回合)），記在它的送出紀錄裡。
- **關閉**：按「關閉 Agent」，確認後看板關掉這個 Agent 和它的 Herdr 分頁。確認畫面會寫明關閉後能不能接回：LAT 主控可以從主控資訊頁喚醒；有接 HCOM 的其他 Agent 有對話紀錄的話，7 天內可以從清單底部的「已關閉」接回；沒接 HCOM 的看板沒辦法把那段對話接回來，只能你自己在終端機操作。關閉成功時跳出通知，Agent 隨即從清單消失，操作紀錄也不再提供；開著的頁面在它列入「已關閉」後換成已關閉 Agent 的頁面；失敗或結果不明時通知說明原因，請到 Herdr 查看。看板不會關閉它自己所在的分頁；HCOM 連線無法確認時關閉按鈕停用。關掉的是工作區裡最後一個窗格時（看板不顯示的一般終端機分頁也算），看板會先在那個工作區開一個名為 CMD 的空白終端機分頁，工作區的名稱與順序因此保留；還有其他 Agent 或分頁時不會多開。CMD 分頁開不成、或讀不到 Herdr 的窗格清單時不關閉，通知說明原因；CMD 分頁開好後關閉卻失敗時，通知也會說 CMD 分頁留在工作區裡。
- **暫停通訊**：確認不了暫停中的 Agent 是否經 hcom 啟動時，「恢復通訊」會拒絕，不打接回指令。有接 HCOM 的 Agent（含主控；沒有經 hcom 啟動的除外，見「重新啟動並接回 HCOM」）在「關閉 Agent」旁有「暫停通訊」，再旁邊是說明圖示：點一下（手機輕觸）列出暫停的重點，再點一次或點別處收起。按下「暫停通訊」就執行、不再確認，處理中按鈕顯示「處理中…」；看板讓它離開 HCOM，但視窗與對話都保留，不是關閉；暫停沒成功時通知寫明原因，看板讀不到 HCOM 清單而無法確認時標「HCOM 連線無法確認」，讀到後自動判斷。暫停中它標「暫停通訊」，按鈕變成「恢復通訊」；這段期間其他 Agent 傳給它的訊息會直接傳送失敗、不會排隊等它回來，LAT 監控也不會往它的輸入框打字。你在看板傳的話照常送進它的輸入框，不會因此自動恢復。按「恢復通訊」也是按下就執行，看板在它的輸入框打入接回指令，它會因此跑一個很短的回合；用原本的名稱接回後才算成功。它正在工作或停在確認畫面時不能恢復，要等它停下再按；恢復失敗時通知寫明原因，暫停狀態保留，可以再按一次。看板自己所在的分頁不能暫停；HCOM 連線無法確認時兩個按鈕都不顯示；暫停中不能切換模型。
- **重新啟動並接回 HCOM**：沒有經 hcom 啟動的 Claude、Codex（例如 Herdr 重啟後自己開回來的程序）沒有 hcom 的 hooks，打指令也接不回。看板看程序本身認得出這類 Agent，頁面寫明原因並提供這個按鈕，不提供「暫停通訊」。按下後舊程序結束、在原分頁重開，對話、HCOM 名稱和權限模式不變（Codex 的權限模式看最近一回合，之後才用 `/permissions` 改的看不到），別人傳來的新訊息和先前的未讀訊息會自動送達。它在工作、停在確認畫面、有背景 subagent 在跑、輸入框裡有還沒送出的文字（讀不出來也算）、讀不出權限模式，或 hcom 記著會放寬權限的舊參數時，看板拒絕並說明原因，原程序不受影響；新程序沒連上時會寫明原因，不當成已接回。這類主控不算已關閉，傳話照常送到它的輸入框，也不能喚醒接回（會多開一個程序；Herdr 還在跑它、hcom 清單卻沒有它的主控也一樣），要接 HCOM 請按這個按鈕。一次一個 Agent，一律由你按。
- **已關閉**：清單底部摺疊的「已關閉 N」列出 7 天內關掉、有對話紀錄可以接回的 Agent，展開後依停止時間分今天、昨天、近 7 天。點一列就在右側（手機是新的一頁）打開它的頁面，網址與返回和一般 Agent 頁相同：資訊卡寫「已關閉」、分頁名稱與 HCOM 名稱、資料夾、原工作區與停止時間；資訊卡下方是「接回」，下面是它關閉前的對話紀錄，可以往前翻頁。一般 Agent 按「接回」就在原工作區開新分頁接回同一段對話；主控按「接回」先展開喚醒選項（模型與思考強度、第一則訊息，前一次接回卡住時另有「放棄前一次接回」），再按「喚醒接回」。接回中與失敗原因顯示在按鈕上方，清單那一列也會顯示；接回成功、它出現在 Herdr 後，頁面自動換成一般 Agent 頁（主控則是主控頁）。開著已關閉 Agent 的頁面時，指令列停用並說明「已關閉，先接回才能傳訊息」。
- **切換模型**：在指令列送出鈕旁的模型與思考強度，和主控一樣顯示它最近一回合的設定（還沒做完第一回合時顯示「模型／強度」）。只有接 HCOM 的 Agent 可以切換，選項與切換主控相同；沒接 HCOM 或 HCOM 連線無法確認時停用，滑鼠停留可看原因。選好後按 ✓，確認後看板停止它，再以新設定在新分頁接回同一段對話，原分頁會關掉。Agent 還在工作時不能切換，要等它這一回合做完。還沒有對話（開好後一則訊息都還沒送）的 Agent 沒有可接回的內容，看板改成以新設定重新啟動它：同樣的資料夾、工作區與啟動參數，新分頁沿用原分頁的名稱與位置，HCOM 名稱會換新（原分頁名稱若就是舊 HCOM 名稱，新分頁也沿用它）。接回或重新啟動後，要看到它真的在 Herdr 分頁裡執行才算切換完成；一啟動就結束、或一直沒出現時，切換會標為失敗並寫明原因，Agent 留在清單上標「切換未完成」，可以繼續切換或放棄。當初以 `--model`、`-m` 或 `--oss` 指定模型啟動的 Codex 只能改思考強度，模型欄停用並說明原因；從看板新建時選的模型不受此限。
- **切換未完成**：切換做到一半失敗時（例如已停止但接回失敗），這個 Agent 會留在清單上並標「切換未完成」，即使已不在 Herdr 裡、看板重新啟動也一樣。按指令列模型旁的 ⚠ 可以「繼續切換」或「放棄切換」，兩者都先確認一次；在處理完之前不能傳話、中斷或關閉。從主控資訊頁切換到一半的主控也一樣列在這裡。繼續切換會先查證它停到哪裡，再停止或接回，不會重複接回。放棄切換會結束這整次切換，看板之後不會再停止或接回它，放棄本身也不執行任何指令；它若還在 Herdr 裡就照常列出，已不在就從清單消失。看板正在停止或接回它時，要等那個步驟做完才會放棄。
- **操作紀錄**：Agent 頁面的「操作紀錄」分頁列出從看板對它做過的傳話、從終端分頁按的鍵、中斷、沒關成的關閉、切換模型（含放棄的），以及在它的卡片上調整分頁順序與改分頁名稱，成功或失敗都記，所有登入的裝置看到的相同。Agent 從 Herdr 清單消失後，頁面與紀錄就不再提供（切換未完成的除外）。
- **調整分頁順序**：按住卡片最右邊的把手（六個點）拖到同一個工作區的另一張卡片上放開，Herdr 裡的分頁順序就跟著改；拖曳中會在卡片上方或下方畫一條線，標出會放在哪裡。往上拖會放在那張卡片的分頁前面，往下拖放在它後面；看板不顯示的一般終端機分頁也照樣算在 Herdr 的順序裡。只有按住把手才會拖曳，點卡片其他地方照舊開啟 Agent；手機上用手指按住把手拖曳。拖到別的工作區時卡片變淡並提示「不能拖到別的工作區」，放開後回到原位，什麼都不會改。拖到同一個分頁的另一張卡片上也不會動。工作區的卡片多到一個畫面放不下時，把卡片拖到清單的上緣或下緣（約 48 像素內），清單會自動往那個方向捲，越靠近邊緣捲得越快；離開邊緣、放開或捲到頭就停，畫出的位置線與放開後的結果仍然一致，手機上則捲整頁。排序失敗時跳出通知說明原因，清單照 Herdr 實際的順序顯示。
- **調整工作區順序**：按住工作區標題右邊「＋」旁的把手（六個點）拖到另一個工作區上放開，Herdr 裡的工作區順序與編號就跟著改；拖曳中會畫一條線標出會放在哪裡，往上拖放在那個工作區前面，往下拖放在它後面。工作區多到一個畫面放不下時，同樣可以拖到清單上下緣讓清單捲動。排序失敗時跳出通知說明原因，清單照 Herdr 實際的順序顯示。
- **關閉工作區**：在工作區標題上按右鍵（手機上長按約半秒）開選單，選「關閉工作區」，標題下方出現確認框，寫明會一起關掉裡面幾個 Agent 和幾個分頁（含看板不顯示的終端機分頁）；按「確認關閉」才關，按「取消」什麼都不做。關閉前看板會再數一次，數量和確認時不同就不關，請重新確認。看板自己所在的工作區不提供關閉：選單裡的項目停用並說明原因。關閉成功時工作區從清單消失，失敗時跳出通知說明原因。
- **改分頁名稱**：在卡片上按右鍵（手機上長按約半秒）開選單，選「改分頁名稱」，卡片標題變成填好目前名稱的輸入框。按 Enter 儲存，按 Esc 或點別的地方取消；名稱空白不會送出。成功後清單顯示新名稱，失敗時跳出通知說明原因，名稱維持原樣。
- **排序與改名要留意**：作用在整個 Herdr 的分頁；你在 Herdr 把某個分頁切成多個窗格、裡面有好幾個 Agent 時，會一起移動或改名。看板自己所在的分頁也可以排序與改名，看板不會因此關掉。看板不提供分割窗格、搬到新分頁、搬到別的工作區或關閉整個分頁。
- **開新 Agent**：按工作區標題右邊的「＋」，右側（手機是新的一頁）出現「在 <工作區> 開新 Agent」表單。「Herdr 工作區」選單預設「當前工作區」，就是按下「＋」的那個；也可以改選「自動」、別的工作區或「新建工作區…」，選法與失敗處理和新建主控相同，表單標題跟著寫出要開的工作區。表單和新建主控相同：資料夾（預設是上次在這個工作區開新 Agent 用的資料夾，從開新紀錄查（紀錄保留 30 天），重新整理或重啟看板後仍記得；那個資料夾已不存在、或還沒在這裡開過時，改用這個工作區裡 Agent 最常用的資料夾，沒有 Agent 時用最近用過的資料夾；自己打過或選過的資料夾不會被預設值換掉；點進還沒改過的輸入框時，這個工作區 Agent 在用的資料夾排在最前面，再補上最近的專案，共 5 個）、第一則訊息、設定列（client、模型、思考強度、分頁名稱），分頁名稱與第一則訊息都可以留空。和新建主控不同的地方：不送 LAT 啟動指令、不需要 Git 專案（看板不會 git init）；資料夾不存在時同樣在家目錄底下建立，但只建資料夾、不 git init。按「開新 Agent」後看板經 HCOM 在所選的工作區開一個新分頁（Claude 一樣略過權限確認），所以開好後就能在這裡看即時狀態、傳話與切換模型。下方「最近開新的 Agent」顯示進度：「啟動中」→「已出現在 Herdr」；Agent 出現在 Herdr 後，有填分頁名稱就改成那個名稱，再把分頁移到它所在工作區的最前面，清單上的新卡片也就在那一組最上面；紀錄寫出實際開在哪個工作區，新建的標「（新建）」。等了 3 分鐘還沒出現時顯示逾時與原因；開不成時表單內容保留著，可以改了再送。改名或移到最前面失敗時 Agent 仍然開好了，紀錄會寫明是哪一步失敗。同一時間只跑一個開新（與新建主控共用），後送的會等前一個出現在 Herdr 或逾時後才開始。每次開新都會留下紀錄，所有登入的裝置看到的相同。
- **留意**：直接對 LAT 派出的 Agent 傳話、中斷或關閉，可能打亂主控的安排，主控不會知道你做了什麼。

### 終端分頁

Agent 頁與主控頁的分頁列在「對話紀錄」後面有「終端」（舊稱「畫面」）。打開頁面時仍先顯示對話紀錄；點「終端」才看得到。

- **看到什麼**：這個 Agent 的 Herdr 窗格最底下的內容，保留顏色，和你在終端機看到的一樣。畫面不再包在框裡：沒有框線、圓角與框外邊距，內容直接鋪滿分頁列以下、指令列（手機是按鍵面板）以上，左右貼齊內容區邊緣，只在文字左右各留約半個字寬，免得字貼邊；最底下一列貼齊底部；框比窗格高時，往上補窗格更早的內容填滿（最多 120 列，可以在框裡往上捲），內容比框短時上方才留空白。更早的內容請看對話紀錄。你在電腦的 Herdr 裡往上捲時，看板仍顯示最底下。看板不會捲動窗格，也不改窗格大小。視窗改變大小或手機螢幕鍵盤彈出時，畫面框跟著調整，指令列不會被推出畫面。
- **字與顏色**：文字預設 16px 等寬字型，大小由設定裡的「終端字體」決定（10 到 28px，見下方設定按鈕），不受整體大小與最小字體影響，行距較緊，框線才接得起來。過長的行不換行，在畫面框裡左右滑動，頁面本身不橫向捲動；畫面更新時停在原本滑到的位置。深色主題是深底；淺色主題不做任何反轉，底色是看板淺色主題的白（#fff，與頁面一致），預設文字色用 Herdr 淺色主題的配色（看板伺服器讀 Herdr 設定檔 `[theme]` 的 `name`，支援 catppuccin-latte、gruvbox-light、one-light、solarized-light；讀不到、不是淺色系或名稱不認得時用 catppuccin-latte，字 #4c4f69），16 個基本色用該主題的對應色（紅綠黃藍洋紅青與灰階），程式自己指定的 256 色與真彩色照原值畫；所以程式為淺底畫的顏色（例如 Claude Code 在 Herdr 淺色主題裡的樣子）在看板淺色主題下一致。Herdr 的窗格自己的 16 色是跟著它所在的終端機走，看板用的是 Herdr 主題的命名色，兩者可能有小差異。換了 Herdr 的主題要重新載入看板才會跟著換；切換看板的深淺色立即生效。
- **狀態卡收成一行**：切到終端分頁時，頁面上方的狀態卡收成一行：狀態、名稱、每個警告一個 ⚠ 記號（例如未接 HCOM、待決題數），最右邊「展開」。點「展開」才看得到完整狀態卡、警告說明與按鈕（關閉 Agent 等），再點「收回」收起。切到其他分頁恢復原樣。
- **手機隱藏頂端列**：手機（手指觸控為主）開著終端分頁、狀態卡收成一行時，頂端列不顯示，畫面框往上延伸佔用空出的高度；收成一行的狀態卡最左邊多一個「←」，作用與頂端列的「←」相同（系統返回照舊）。浮動通知改顯示在頁面最上方，左右兩端留出「←」與「展開」的位置，不蓋住它們。切到對話紀錄等其他分頁，頂端列（含重新整理與設定按鈕）恢復。Agent 頁、主控頁與已關閉 Agent 頁都一樣（已關閉的卡片收成一行，展開後有接回按鈕）；電腦（滑鼠或觸控板）與視窗很窄的電腦不變，頂端列照舊、卡片沒有「←」。這個 Agent 不在 Herdr 的清單上、狀態卡不收合時，頂端列照舊。手機把指令列收成右下角圓鈕時，畫面框一路延伸到螢幕底部，圓鈕浮在框的右下角（此時沒有按鍵面板，先展開）；展開指令列後恢復。
- **狀態文字**：正常時畫面框上方不顯示任何狀態文字；讀不到畫面、連線中斷或按鍵可能沒送到時，才在框上方寫出原因。
- **多久更新**：終端分頁開著時，看板每十分之一秒讀一次畫面（窗格一直在輸出時約每 0.3 秒），按鍵送出後立刻再讀，畫面沒變就不重送；按鍵到畫面跟著變通常在一眨眼內。沒有頁面開著終端分頁時，看板不去讀畫面。幾台裝置同時開著，看到的畫面相同；斷線後連回來會自動接上最新畫面。
- **密碼與金鑰**：看起來像密碼、API 金鑰或 token 的字串，在看板主機上就換成同樣寬度的 `*` 才送到瀏覽器。只看字串長相判斷，可能漏掉少數密碼，也可能把不是密碼的長字串遮住。
- **手機與電腦**：以裝置的主要輸入方式判斷，不看螢幕寬度。手機與平板（手指觸控為主，接了實體鍵盤也算）用按鍵面板按鍵；電腦（滑鼠或觸控板）用直接操作。畫面上的文字可以選取複製。
- **按鍵面板（手機）**：手機終端分頁開著時，在底部指令列向左滑，整個指令列換成按鍵面板，向右滑換回輸入框。面板放 Esc、Tab、⇧Tab（Shift+Tab）、1、2、Enter、Ctrl+C、3、4 和 ↑、←、↓、→ 共 13 個鍵，佔用指令列的位置與高度（指令列只有一行高的寬版面、例如手機橫放時，這一排改為至少放得下兩排鍵的高度，13 個鍵都完整看得到、點得到），不蓋住畫面框，面板上方有兩個小圓點標示現在是指令列（左）還是按鍵面板（右）。跟手滑動、面板隨手指 1:1 移動，放開時滑過寬度約四分之一，或快速甩動（約 0.3px/ms 以上）即使距離短也會切換，不夠就彈回；水平移動約 10px 內判定方向，以垂直為主的拖動不觸發。輸入框有焦點（螢幕鍵盤開著）時，從輸入框起的左右拖曳留給選字與游標，從指令列其他地方滑才切換。畫面框裡的左右滑動照舊捲動長行，不切換。按一下就把那個鍵送進窗格，畫面隨即跟著變，面板維持開著；按鍵不會把焦點搶走。切到其他分頁或重新載入，指令列恢復成輸入框，不記憶上次停在哪一個。指令列收成右下角圓鈕時沒有按鍵面板，先點圓鈕展開指令列。電腦沒有按鍵面板。
- **直接操作（電腦）**：點一下畫面就進入直接操作，內容區頂端出現一條強調色細線，「終端」分頁標籤也變成強調色，離開後恢復；進入與離開時版面不會移動；之後按的鍵直接送進窗格，包括字母、數字、空白、Enter、Esc、Tab、Shift+Tab、Backspace、方向鍵、Ctrl+字母、Alt+字母，以及 Home、End、Insert、Delete、PageUp、PageDown。Esc 是送給 Agent，不會離開（某些瀏覽器或擴充功能會攔下 Esc，網頁收不到，這時用指令列選項裡組合鍵的 Esc）；Tab、Backspace 也只送給 Agent，不會移動焦點或回上一頁。點畫面以外的地方就離開；在畫面上拖曳選取文字也會離開，選取的文字可以照常複製。用輸入法打中文時，選好字才送出那幾個字。按到送不出的鍵（例如 F1～F12）會跳出「這個鍵目前送不出」，不會送出。直接操作時指令列照常可用。⌘ 開頭的組合鍵仍交給瀏覽器。
- **組合鍵（電腦）**：瀏覽器自己會用掉 Ctrl+W、Ctrl+T、Ctrl+N，直接按送不到 Agent；某些瀏覽器或擴充功能也會攔下 Esc，所以 Esc 也放在這裡。終端分頁開著時，指令列的選項按鈕一定可以點，選單裡的「組合鍵」段依序有 Esc、Ctrl+W、Ctrl+T、Ctrl+N，點一下送進畫面上這個窗格；指令列用 `@名稱` 指定了別人也一樣送給畫面上這個。手機沒有這一段。
- **打字**：照舊用指令列，送出時連同 Enter 一起送，和平常傳話一樣。
- **按鍵沒送到時**：看板不會自動重送，還沒送出的按鍵一併取消，跳出「按鍵可能沒送到，請看畫面確認」並說明原因，按鍵面板的鍵、直接操作與組合鍵都停用；等看板重新讀到一次畫面（畫面沒變也算）才能再按。重新讀不到時維持停用，畫面上方寫明原因，之後照常一直再試。網路斷線時按的鍵也一樣：連回來、看板重新讀到畫面後才能再按，中途切到別的分頁再回來也還在等。
- **讀不到畫面時**：例如窗格不在或 Herdr 沒回應，畫面上方寫「讀不到畫面：」加原因，按鍵面板的鍵、直接操作與組合鍵都停用；先前讀到的畫面留著。
- **按鍵不會悄悄不見**：剛打開終端分頁、畫面還沒出現時按的鍵照常送出。因為上面的原因不能送時，按下去會跳出「按鍵沒有送出：」加原因，不會什麼都沒發生。
- **已關閉的 Agent**：終端分頁顯示「已關閉，先接回才能看畫面」。
- **看板自己所在的窗格**：看得到畫面，但不接受從終端分頁按鍵。
- **操作紀錄**：從終端分頁按的鍵記在該 Agent 的操作紀錄，種類是「終端按鍵」；幾秒內連續按的合併成一筆，只記按了哪些鍵、各幾次（Home、End 等也記鍵名），打的文字只記字數，不記內容。
- **留意**：畫面是每十分之一秒讀一次的快照，不是真正的終端機，vim 這類全螢幕程式畫面變動大時可能略慢。能看畫面又能按鍵，等於能操作主機上的 Agent，看板只適合在家裡或私人網路使用。

## 在看板回答 Agent 的提問

一般 Claude Agent 用選單問你問題（AskUserQuestion）時，題目會出現在看板上它自己的頁面，你在看板點選作答，答案直接填回去，它接著做，不必回到終端機。Claude 與 Codex 跳出權限確認時（包括你直接召喚、沒接 LAT 的 Codex，以及 Codex 執行 MCP 工具前的核准），看板同樣顯示一張權限確認卡讓你「允許」或「拒絕」，見下面「權限確認」。

- **在哪裡作答**：「Herdr」分頁裡這個 Agent 那一筆的狀態改成「等你回答」；點開它的頁面，題目卡在對話紀錄裡它提問的時間點（剛問的就在最上面、最新的位置），之後的訊息排在它上面，卡片不會一直停在最上面；對話紀錄還在讀取時先顯示在最上面。題目卡和待決題卡片一樣：單選題點一個選項，複選題可以勾多個，也可以選「其他」自己打字；沒有備註欄。一次問好幾題時全部一起顯示，每一題都答了才能送出。卡片上顯示還剩多久。
- **送出後**：Agent 收到答案接著做，卡片變成唯讀並標「已填回」，你的選擇以 ✓ 標在選項上。複選題的答案是各選項以逗號連接，自填文字照你打的送出。每次作答都記在它的「操作紀錄」，種類是「看板提問」。
- **兩台裝置同時作答**：只有先送到的算數；另一台跳出通知，卡片標「已有人作答」，那份答案不會送出。
- **等多久**：Agent 問完原地等你最多 10 分鐘，等待期間它的終端機顯示「正在等看板作答，按 Esc 可中斷改在終端機回答」。時間到還沒作答時，它先結束這一回合（終端機會寫明你會從看板回答、答案會以訊息傳給它），不會自己猜答案。
- **逾時之後再作答**：卡片仍留著，標「已逾時，作答會當訊息傳給它」，照樣可以作答。送出時看板重讀 Herdr 的清單：清單上有它，答案就當成你打的一則訊息打進它的輸入框（和其他傳話排同一個隊伍），訊息開頭附原本的題目，說明這是對先前逾時題目的回答，卡片標「已傳話」，操作紀錄記下這則訊息。兩台裝置同時作答時同樣只有一則送出，另一台標「已有人作答」。
- **Agent 已經不在時**：Herdr 的清單讀得到、但上面已經沒有它（就算 hcom 的清單還有它），卡片標「Agent 已不在，無法送出」，答案不會送到任何地方。只是暫時讀不到 Herdr 的清單時，通知寫「無法確認這個 Agent 仍在 Herdr 的清單上」，卡片維持已逾時、你選的內容還在，之後再送一次就好。
- **看板在傳話途中停掉**：重啟後那張卡片標「結果不明，請看對話紀錄」，看板不會自己重送，以免它收到兩個答案。卡片上有「再送一次」按鈕，旁邊註明「可能已送過，請先看對話紀錄」：先看它的對話紀錄，確定沒收到再按，會用同樣的方式把原本的答案再送一次，並記在操作紀錄；兩台裝置同時按時只會送出一則，另一台標「已有人作答」。
- **在終端機中斷**：等待中你在終端機按 Esc（或 Agent 被關掉）時，看板下一次更新就把卡片標「已在終端機中斷」（Claude 的權限確認例外，見下面「權限確認」），不能再送。
- **保留多久**：已填回、已逾時、已傳話、結果不明、已中斷、Agent 已不在的提問，結束滿 7 天後連同題目卡從看板與共用目錄刪除；已逾時的從逾時那一刻算起。操作紀錄裡的那筆照原本的 30 天保留。
- **看板沒開的時候**：看板沒在執行（約 90 秒沒有心跳）時，Agent 照舊在終端機跳出原本的選單，不會等。不在 Herdr 裡執行的 Agent 看板上沒有它的頁面，Claude 的 Task 子 Agent 也不攔，都照舊在終端機問。看板在等待途中重新啟動，題目卡仍在，截止前照樣可以作答。
- **LAT 主控用選單問你**：會被擋下，主控看到一則英文提醒，要它改用待答面板（`question upsert`）寫題並以 DECIDE 結尾；看板上不出現題目卡，待辦也不會多一筆看板提問，你照舊在待辦裡回答它重問的題目。hook 用輔助工具查面板的綁定登記，session 有綁定就是主控；查不到、輔助工具壞了或看板沒在執行時，當一般 Agent 處理。
- **你要留意**：等待期間 Claude 的選單提問與 Codex 的權限確認在終端機不會出現原本的畫面，你人在終端機時要按 Esc 中斷這一回合，才能在終端機自己處理。Claude 的權限確認則兩邊同時看得到，見下面「權限確認」。
- **安裝 hook**：要先把看板附的 hook 裝進 Claude 與 Codex 的全域設定。先預覽，確認無誤再安裝；安裝前會備份設定檔，保留你原本的其他 hook，重跑不會重複，移除只拿掉這幾筆：

  ```bash
  uv run --no-project python board/hooks/board-ask.py install --client claude --preview
  uv run --no-project python board/hooks/board-ask.py install --client claude
  uv run --no-project python board/hooks/board-ask.py uninstall --client claude
  uv run --no-project python board/hooks/board-ask.py install --client codex --preview
  uv run --no-project python board/hooks/board-ask.py install --client codex
  uv run --no-project python board/hooks/board-ask.py uninstall --client codex
  ```

  Claude 裝的是選單提問與權限確認兩筆（`settings.json`）；Codex 裝的是權限確認、回合結束與工具執行完三筆（`hooks.json`）。要裝到別的設定檔時，Claude 加 `--claude-settings <路徑>`，Codex 加 `--codex-home <資料夾>`。已在執行的 Claude 要重開才生效。Codex 裝好後，每個 Codex 都要在 `/hooks` 信任這個 hook 一次，已在執行的 Codex 要重開才生效；還沒信任或還沒重開的 Codex 照舊在終端機問。

### 權限確認

- **在哪裡作答**：一般 Agent 的權限確認卡在它自己的頁面，和題目卡在同一個位置；LAT 主控的權限確認卡在主控資訊頁，以及「Herdr」分頁裡主控的那一頁。卡片寫出工具名稱與內容：指令全文、要改的檔案與內容，或 MCP 工具的名稱與參數，以等寬字顯示，太長時先摺起來，按「展開全部」看完整內容。下面是選填的拒絕理由與「允許」「拒絕」兩個按鈕。
- **送出後**：按「允許」它就執行；按「拒絕」它不執行，你寫的理由會傳給它。每次作答都記在它的操作紀錄。
- **Claude：終端機與看板兩邊都能答**：Claude 等你在看板作答時，終端機同時也顯示它原本的確認畫面，哪一邊先答就算哪一邊。看板照 Claude 實際採用的結果標示：
  - 你在終端機先答了：選允許時卡片標「已在終端機回答：允許」；選 No 或按 Esc 時都標「已在終端機拒絕」（Claude 對這兩種的紀錄完全相同，看板分不出來，兩者都算拒絕）。之後都不能再從看板送，也不會傳訊息給它。
  - 你在看板送出後，卡片先標「已送出」，等看板從它的對話紀錄確認它採用了哪個答案：和你在看板的選擇一樣就標「已填回」；你其實已經在終端機選了相反的答案時，標「已在終端機回答：允許」或「已在終端機拒絕」，並註明「你在看板的選擇沒有被採用」，操作紀錄也照實記下。
  - 送出後 1 分鐘內看不出它採用了哪個答案（例如對話紀錄裡有兩筆一模一樣的請求分不出來）時，標「結果不明，請看對話紀錄」。
- **Claude 逾時**：10 分鐘沒作答時，Claude 先結束這一回合，卡片標「已逾時，作答會當訊息傳給它」。之後按「允許」，看板傳一則訊息請它重試（「使用者允許你執行剛才被擋下的操作，請重試」，附上工具與內容）；按「拒絕」則傳一則拒絕的訊息，附你寫的理由。送不送得到的規則和逾時後的選單提問相同：Herdr 的清單上已經沒有它（主控也一樣，例如已關閉）時標「Agent 已不在，無法送出」，看板不會為了送這則訊息喚醒或接回它。
- **Codex 逾時**：10 分鐘沒作答時，Codex 不會結束回合，而是把終端機原本的確認畫面交還給你；卡片標「已交回終端機」，之後不能再從看板回答，看板也不傳訊息、不替你按 Esc。
- **Codex 自己先停下這一回合**：Codex 有時在等你核准的期間先結束這一回合。這時卡片照常可以按，上方註明「它已經停下這一回合，按允許後指令仍會執行」。按「允許」後指令會執行，卡片標「已允許，等它執行・還沒看到它執行」，這時還不傳訊息，這一筆也留在待辦；看板看到它真的執行了（失敗也算），才傳一則訊息告訴它「你剛才請求的〈工具與內容〉已在看板允許並已執行，請檢查結果後接著做」，卡片標「已允許並已執行，已通知」。允許後 7 天內都沒看到它執行時不傳訊息，卡片改標「已允許，7 天內沒看到它執行，沒有通知它」；看到的執行分不出是不是這一筆時也不傳，標「已允許，看板無法確認是哪一次執行，沒有通知它」。按「拒絕」和平常的拒絕相同，不另外傳訊息。
- **保留多久**：已交回終端機、已在終端機回答、已在終端機拒絕、結果不明、已允許並已通知、以及上面兩種沒有通知它的權限確認，算已結束，結束滿 7 天後從看板與共用目錄刪除；「已允許，等它執行」的會留著，最長到允許滿 7 天。
- **不會出現權限確認的情況**：用略過權限模式執行的 Agent 本來就不問權限，看板上也不會出現權限確認卡。Codex 規劃模式裡的提問（`request_user_input`）不處理，照舊只在終端機出現。

## 額度分頁

中間欄的「額度」分頁列出 Claude 與 Codex 的每一個帳號和它們的額度，只能查看：看板不切換帳號、不要求更新額度，也不兌換 reset。左欄（展開或收合）不放任何額度數字，手機上也用這個分頁看。

- **資料從哪來**：Claude 讀 claude-swap 的 `cswap list --json --cached-only`，Codex 直接讀 codex-multi-auth 的帳號檔與額度快取（位置見 [board/README.md](../board/README.md)）。這兩種讀法都不連網、不刷新登入，所以數字是 `cswap auto` 或 Codex 上次記下的值。看板伺服器每 30 秒讀一次，所有已登入的瀏覽器共用；憑證與檔案原文不會送到瀏覽器。
- **每組的標題**：寫使用中帳號的資料是幾分鐘前更新的（沒有使用中帳號時看最新的一個）；超過 Claude 3 分鐘、Codex 15 分鐘時間文字就變黃（只寫「N 分鐘前更新」，不另加字）。其他帳號的卡片各自寫自己的更新時間，過舊同樣變黃。
- **每張卡片**：使用中的帳號排最前面並加框。第一行是 email 與方案：使用中的 Claude 帳號（claude-swap 切換到它時記下的就是目前方案）與 Codex 帳號（方案隨每次用量一起記下，和卡片上的更新時間一樣新）直接顯示；其他 Claude 帳號只有上次使用時記錄的方案，顯示較淡，滑鼠停留說明「上次使用時記錄（N 天前）」；沒有紀錄的不顯示方案。下面每個時段一行（5 小時、7 天，以及 Fable 等模型專屬時段，有才顯示）：剩餘百分比（例如「89%」，滿額 100%、用完 0%）與重置時間，沒有長條；20% 以下黃、5% 以下紅。
- **沒有資料時**：帳號沒有用量紀錄寫「沒有紀錄」，不顯示 0%；重置時間已過的舊數字變淡並註明「等待新資料」。讀不到資料（找不到帳號檔或額度快取、版本不符、claude-swap 出錯，或安裝的 claude-swap 還沒有唯讀額度指令）時，那一組寫出原因（只寫看板自己的說明，不轉貼外部指令的輸出），另一組和看板其他部分照常。

## 自動化分頁

中間欄的「自動化」分頁（在額度之後）列出看板管理的每月、每週、每天任務。每張卡片寫名稱、本期狀態（等待中、執行中、本期已完成、失敗、本期錯過、已暫停）、種類與執行期間（例如「每月 1–5 日 10:00」「每週一至三 09:00」「每天 03:00」）、下次自動執行的時間與上次結果。點一張卡片在右邊欄看設定與執行紀錄；手機上點任務進入獨立頁，左上「←」回到清單。

- **新增與編輯**：表單選每月（起訖日 1–31）、每週（起訖星期，一週從星期一到星期日，不能跨過星期日）或每天，只顯示所選類型的欄位；再填時間、最久跑多久（分鐘）與種類。「跑一個指令」填指令、工作資料夾與固定檢查（檔案存在、輸出含某字，可多條）；「請 Agent 做」填 Claude 或 Codex、模型、強度、工作資料夾與任務說明檔（可先存，由看板執行 Agent 任務的功能之後才加）。「這期成功後就不再跑」是固定規則，表單只寫明，不能關。儲存時看板逐欄檢查（日期、星期、時間、上限、必填欄位、資料夾與說明檔是否存在），有錯就在該欄下方寫出原因，什麼都不寫入。
- **排程**：看板每分鐘檢查一次，日期、星期與時刻一律照台灣時間（Asia/Taipei）判斷，不看主機設定的時區；紀錄裡的時間存 UTC。今天在執行期間內（期間最後一天算到當天結束）、已過設定時刻、今天還沒自動試過、本期（這個月、這一週〔星期一到星期日〕或這一天）還沒成功、任務沒暫停時，自動跑一次。一天最多自動試一次，失敗了等隔天；本期有任何一次成功（自動、手動或沿用原紀錄，預覽不算）就不再跑，之後手動執行失敗也不會讓本期變回未完成。每一次執行算在它開始的那一期，跨過半夜、週末或月底才結束，或中途看板重啟，都不改。卡片與內容頁的「下次」是看板照這些規則算出的時間。目前只排指令任務；Agent 任務由看板執行 Agent 的功能加入後才排。
  - **看板重啟後**：只要今天在期間內、今天還沒自動試過、本期還沒成功，一啟動就馬上試一次，不必等到設定時刻。
  - **還在跑**：到點時同一個任務還在跑（例如手動執行還沒結束），這次自動嘗試跳過，紀錄寫「↷ 跳過：上一次還在跑」，算是今天試過了。
  - **執行上限**：從開始時間算，超過就停掉，記「逾時」。
  - **本期錯過**：整段期間結束時這一期完全沒有自動或手動執行（例如看板整段沒開），標「本期錯過」，卡片寫「11/8–11/10 看板沒開，這期沒跑」；看板停了好幾個月才開，會逐期記下每一期，卡片寫錯過幾期，內容頁列出前三期與總數。每個任務每次只發一則通知（目前寫在看板日誌 `automation periods missed`，紅卡與推播之後加入）。不會自動補跑：內容頁上方的框裡有「立即執行」與「這期就算了」，按其中一個框就收起，不再提醒；之後的自動執行不會讓它消失。暫停中的期別、任務新增當期已經開始的那一期都不算錯過。
  - **沿用原紀錄**：搬遷任務時，用 API 加一筆本期成功紀錄，附上專案原本的完成標記路徑，本期就算已完成；頁面上沒有這個按鈕。例如在已登入的瀏覽器主控台執行 `fetch('/api/automation/<任務>/carried', { method: 'POST', headers: { 'content-type': 'application/json' }, body: JSON.stringify({ marker: '~/iipp/state/2026-11.done' }) })`。
- **立即執行**：只有指令任務能按。指令在工作資料夾以 `bash -c` 執行，結束碼 0 且每一條固定檢查都通過才算成功，超過上限就停掉算逾時。同一個任務正在跑時按鈕停用，另一台裝置還沒更新而送出時，看板拒絕並寫出「正在跑（幾點開始），等這次結束再執行」。立即執行不算當天的自動嘗試。
- **執行紀錄**：每一次寫觸發方式（自動、手動、預覽、沿用原紀錄）、開始與結束時間、結果、原因（例如「結束碼 2」或哪一條檢查沒過）、固定檢查逐條結果，以及輸出存放的位置；「看指令輸出」打開保留的輸出，太長時只留最後約 32,000 字並在開頭註明省略多少。
- **暫停與恢復**：暫停後清單顯示「已暫停」、下次寫「暫停中不會自動跑」；恢復後回到原本的狀態。編輯不改變暫停與否。
- **存放位置**：每個任務一份 JSON，放在看板狀態目錄的 `automation/` 裡，寫入時先寫暫存檔再改名，寫到一半中斷不會留下壞檔；執行紀錄是 `automation/runs/<任務>.jsonl`，每次開始與結束各追加一行；錯過的期別記在 `automation/missed/<任務>.jsonl`，排程上次檢查的時間在 `automation/checked-at.txt`（看板啟動時從這個時間到現在之間結束的期別都會檢查）；輸出在 `automation/output/<任務>/<執行>.txt`。讀不出來的任務檔在清單最上方以紅框寫出檔名與原因，不會被當成空任務。看板重啟時，上一個看板程序還沒跑完的指令記為失敗（看板重啟中斷）。
- **即時更新**：新增、編輯、暫停、執行狀態變化都即時推到所有開著的看板頁面。測試用登入的裝置不能改任務或執行任務。

## pd 待核准

有安裝 pd（把 Bitwarden 密碼交給 Agent 用的工具）時，等你核准的 pd 請求會出現在一個浮動視窗裡，不管中間欄正在看待辦、Herdr 還是額度都在。視窗一開始蓋在中間欄的位置（最窄 360px，中間欄拉得很窄時也不會跟著擠）；拖標題列可以移到任何地方，拖右下角可以調整大小，位置和大小記在這個瀏覽器裡，下次打開還在原處；視窗移出畫面或比畫面大時會自動拉回畫面內。請求多時在視窗裡捲動。手機上不能拖，改成從下方升起、和螢幕一樣寬的面板，蓋在目前的畫面上；正在看某一則內容或某個 Agent 的對話時按「稍後」，上方標題列下面會留一條「● pd 待核准 N　查看 ›」，不蓋住內容，點它再打開。有請求在等時，瀏覽器分頁標題前面也會加上「(N) 」。清單每 5 秒更新。每筆請求最前面有標籤標明動作：讀取、新增、修改、刪除、上傳附件、取代附件或刪除附件（舊版 pd 沒有給動作時照讀取顯示；看板不認得的動作照 pd 給的字顯示，當成寫入標示，不會顯示成讀取）。刪除的標籤是紅色，卡片預設展開，只列項目類型與呼叫者（刪除是移到 Bitwarden 垃圾桶）。新增與修改的卡片預設展開，列出項目類型、要寫的非機密值（帳號、網址、備註），以及每個機密欄位的來源（「自動產生，20 字元」或「指令輸出：gh auth token（資料夾）」），機密本身不在 pd 的清單裡，頁面與看板伺服器都不會有；這兩種沒有指令與工作目錄。附件動作：上傳附件列出附件名稱、大小（指令輸出要執行後才知道，寫「執行後才知道大小，上限 1 MB」）與來源（檔案路徑，或指令與工作目錄）；上傳到已有同名附件時標籤改成取代附件，標題下另有一行紅底醒目的「會取代既有附件（大小 N），舊檔永久消失」；刪除附件列出附件名稱與大小，標籤與卡片都寫「永久刪除，無法復原」。這行警語在詳細內容收合時也看得到。新增項目並附檔時，新增卡片多列附件名稱、大小與檔案路徑；讀取時要了附件，讀取卡片多列每個附件的名稱與大小。有新請求時的瀏覽器通知標題也標明動作，例如「pd 請求 #2（新增）等你核准」。核准與拒絕的做法每種動作都一樣。每筆請求顯示要的項目、請求編號、剩餘時間（剩 2 分鐘內變橘、30 秒內變紅；舊版 pd 不提供剩餘時間，改顯示已等待多久）與「核准」「拒絕」，中間一行是呼叫者，再下一行是縮短的指令（例如「python3 npm_login.py」，路徑只留最後一段）。呼叫者寫成「dahe（claude，主控）✓」或「dahe-t09-vafu（codex，群組 dahe-t09）未通過查證」：✓ 表示 pd 服務從程序樹查證過呼叫的程式，但這只是比對，擋不住同一個帳號的程式刻意偽造；群組與「主控」取自 HCOM 的紀錄，不是查證過的身分；手動指定名稱的會註明「手動」。舊版 pd 沒有這份資料時，寫成對方自稱的名稱加「（自稱）」，例如「codex（自稱）」。呼叫者一行放不下時先截短名稱，「✓」等標記保持完整，完整的呼叫者在展開後看得到。點這兩行展開要的欄位、完整指令、工作目錄與呼叫者。標記代表什麼不寫在卡片上：滑鼠移到呼叫者那一格（手機上長按）會跳出說明，例如 pd 的「程序樹查證，非防竄改」或「對方自稱，未驗證」。

- **核准**：在看板這一頁直接用 passkey 核准：按下後瀏覽器會請你用裝置本身的解鎖驗證（通常是指紋或臉部辨識，也可能是裝置 PIN），不用換頁，也不用輸入 pd 的確認碼。看板只把 pd 給的一次性挑戰值與你的簽章轉給 pd，由 pd 服務驗證；沒有你的 passkey，看板（或主機上的 AI）不能核准。看板上不再放連到 pd 核准頁的連結，核准都在這個視窗裡做。
- **稍後**：按右上角的「稍後」把它收成中間欄最上面的一行「pd 待核准 N」（手機看內容時是標題列下那一條）；請求仍在等你，按這一行就再展開。收起來之後又有新的待核准請求，會自動再展開。
- **瀏覽器通知**：按視窗標題列「稍後」旁的「開啟通知」，瀏覽器才會問你要不要允許通知；看板不會自己跳出這個詢問。允許後，看板在背景（切到別的分頁，或切到別的視窗、別的 App）時有新的請求就發一則通知，點通知會回到看板並打開這個視窗；看板分頁已經關掉時點通知會開一個新的看板分頁。你正看著看板時不發通知，視窗會自己打開。手機（Android Chrome）也收得到。瀏覽器不支援時就不發通知，視窗照常可用。關掉看板後就不會再有新的通知。
- **查看對話**：呼叫者是名冊上的主控或 Herdr 清單上的 Agent 時，卡片右邊有「查看對話」，按了打開它的對話紀錄，捲到發出這個請求的那一步（`pd run`）並標亮。比對方式是請求建立的時間（現在減去已等待多久）前後幾分鐘內、執行 pd 的那一步，指令看得到時優先挑指令相同的；對話紀錄把指令藏起來（只顯示 `cd …` 這類程式名）的步驟也算，排在後面。找不到時改顯示最新的部分，並說明原因（更早的對話讀不到，或前後幾分鐘內沒有執行 pd 的步驟）。pd 沒有查證呼叫者時，標亮的那一步旁邊會寫「可能不準」。手機上按了會先收起視窗。
- **拒絕**：按一下就拒絕，不需要確認碼；所有開著的看板跟著拿掉這一筆。請求已經被核准、拒絕或逾時時，看板會說它已不在清單上。
- **沒有待核准的請求時**：視窗和收起的那一行都不顯示。**用不到 pd 時**：只在待辦清單上方留一行小字，例如「pd 待核准：這台主機沒有安裝 pd」或「pd 待核准：連不上 pd 服務」；看板其他部分照常。
- **要從 https://lat.ouob.net 開**：passkey 只在加密、網址屬於 ouob.net 的頁面能用（passkey 綁 ouob.net，第一次要在 pd.ouob.net 重新登記）。直接用內網位址、http 或其他網域開看板時，視窗標題列會出現一個 ⚠，滑鼠移上去或點一下會說「這個網址不能用 passkey 核准，請從 https://lat.ouob.net 開看板。」，按「核准」也會這樣說。看板本身沒有加密，lat.ouob.net 的加密由前面的反向代理負責（見「[連線來源與反向代理](#連線來源與反向代理)」）。

## 語音輸入

隱藏功能，畫面上沒有開關：連按「待辦」分頁 5 次（每兩下間隔 1.5 秒內）打開，記在這個瀏覽器；再連按 5 次關閉。打開後指令列、新建主控的第一句話，以及看板提問與待答題的「其他」、待答題的「答覆」與「備註」、權限詢問的拒絕理由、已關閉主控接回的第一則訊息、預先授權的每條規則旁會出現麥克風：按一下開始錄音、再按一下停止，辨識出的文字放在該框的游標處；框停用（例如送出中）時麥克風也不能按。

- **需要設定**：看板主機要設定語音辨識服務，沒設定時按麥克風只會提示未設定；約 3 分鐘的錄音超過預設的請求大小上限，要把 `BODY_SIZE_LIMIT` 設成 `2M`（變數見 [board/README.md](../board/README.md) 的設定表）。
- **放入的文字**：辨識結果只把簡體字轉成台灣正體字，不換用語（例如「软件」變成「軟件」、「视频」變成「視頻」，不會改成「軟體」「影片」）；20 個字以內直接放到游標處，更長的先交給 Codex 修錯字、去掉口誤與贅字再放入（會用到 Codex 額度）。Codex 失敗、看不懂或逾時就放轉換後的原文，並以通知說明原因。
- **放入方式**：只取代選取的文字，其餘內容保留。
- **錄音限制**：最長約 3 分鐘，錄音時按鈕上顯示剩餘時間，到時自動停止並送出辨識。麥克風只在 HTTPS 或 localhost 的網址可用；權限被拒時以通知說明。
- **畫面重畫時**：錄音中提問卡或權限卡從頁面頂端移進對話，或手機寬度跨過 760px 再切回，錄音照常繼續、倒數不重來，停止後文字放進同一個框（卡片移動後框是重畫過的，文字放在框的最後）。框真正消失（例如改選其他選項、卡片答完）時錄音停止並放開麥克風，不會送出辨識。

## 附件

指令列左邊的迴紋針可以附加圖片、影片或任何檔案，也可以直接貼上截圖或把檔案拖進輸入框；手機按迴紋針可以選相簿或開相機。

- **上傳**：選好就開始上傳，輸入框上方顯示預覽（圖片縮圖、影片可直接播放、其他檔案顯示檔名與大小）和上傳進度，送出前可以移除。還在上傳或有上傳失敗的附件時不能送出。單一檔案最大 250MB。
- **送出**：訊息最後會自動接上每個附件在看板主機上的完整路徑，主控或 Agent 自己去開。只有附件、沒有打字也可以送。Claude 與 Codex 看得懂圖片（Claude 也能讀 PDF），影片要它們自己先擷取畫面。
- **事後查看**：對話紀錄裡你的訊息與送出紀錄，附件直接顯示成圖片縮圖、可播放的影片或檔名：
  - 點圖片縮圖，或點文字檔（.txt、.md、.json、.py、.ts、.js、.svelte、.css、.html、.yaml、.toml、.csv、.log 等常見文字副檔名），會在面板上開一個視窗：圖片一打開就整張顯示在視窗內，觸控裝置可用雙指放大、放大後用手指拖曳查看細節；Markdown 照對話紀錄的樣式排版；其他文字用等寬字原樣顯示，保留換行與縮排。檔案裡的 HTML 與程式碼只當文字顯示，不會執行。文字檔只讀開頭 200KB，更長時視窗裡會註明「只顯示開頭 200KB」。
  - 視窗標題列有檔名、「下載」與「關閉」。檔名是上傳時的原名（不含看板加的上傳編號），只佔一行，太長時省略中間、保留開頭與副檔名；滑鼠停留可看到完整路徑。下載的檔案也用原名。按 Esc、點視窗外或按「關閉」都能關掉，回到原本的位置。視窗開著時背後的看板不會跟著捲動。手機上視窗佔滿畫面。
  - PDF 在新分頁用瀏覽器內建的檢視器開啟；Word、Excel、壓縮檔等其他檔案點了直接下載。
- **存放位置**：預設在 `/tmp/lat-board-uploads`，只有看板的帳號能讀；看板不會自己刪除，主機重開機或系統清理 `/tmp` 後，紀錄裡會改寫「檔案已不在」。位置與大小上限的變數見 [board/README.md](../board/README.md) 的設定表。
- 附件跟著輸入框裡的草稿走：所有主控共用同一份草稿與附件，每個 Agent 各有自己的；重新整理頁面後尚未送出的附件會消失。新建主控與 Herdr 分頁「開新 Agent」的第一句話可以附檔（迴紋針、貼上、拖放，附件列在框上方），兩個表單各有自己的附件；送出規則同上，成功後附件清空，失敗時附件與文字都保留；開新 Agent 要等 Agent 出現在 Herdr 才清空。

## 預先授權

「設定」對話框的「預先授權（全域）」區塊可以查看並修改全域設定檔（`~/.config/lat/preauth.toml`，依 `XDG_CONFIG_HOME`），不必請主控代改：五種動作選允許或要問（沒寫的動作視同要問），合併與推送可改分支清單，也可逐條增刪改參謀可自行定案與仍要問的範圍。

主控頁面的「預先授權」分頁每個動作一列：專案設定（允許、要問、沿用全域）與結果。修改的是這個主控所屬主工作區的 `.lat/preauth.toml`，同一專案的多個主控看到同一份；部署測試版另可填測試環境。結果寫最後會怎樣：「不問直接做」或「會問你」，小字是授權來自專案、全域、沒有設定，或缺分支清單、缺測試環境；分支與測試環境另標各自的來源。實際執行時仍要符合固定條件（測試通過、分支清單等）。來自全域的值可以點，會打開「設定」對話框並捲到該動作。參謀範圍只看全域，專案檔寫了 `[advisor]` 會標示不生效。

- **自動儲存**：每改一項就寫入，存好顯示「已儲存」：按鈕一按就存，分支標籤在新增（Enter）或點 × 時存，文字欄在離開或按 Enter 時存（參謀範圍用 Shift+Enter 換行）。按錯了會立刻生效，改回來即可。
- **能登入看板就能放寬授權**，包括讓主控不問你直接更新正式版看板。想「只有這一輪不用問」就在這裡切換，做完再切回來。
- **設定檔有錯**（包括兩層合併後時段或時區只寫了一個）時兩處都顯示錯誤，所有查詢都會要問，直到手動修好並按「重新載入」；有錯的那個檔案不能修改。「設定」對話框不看專案設定，全域只寫了時段或時區時，提醒專案要補上另一個。
- **別處改過**：讀取後檔案被改過（另一個分頁或手動編輯），這次修改會被拒絕並改回原值，按「重新載入」再改。
- **紀錄**：每次寫入都會留紀錄，主控交付回報的「設定寫入」會列出本輪開始以來的看板寫入。紀錄寫不進去時設定會還原，畫面顯示失敗並改回原值。

## 無人模式

無人模式下主控照你給的目標自己把這一輪做完，要你決定的事先擱置，不發題問你。所有讀寫都經 LAT 的無人模式工具（`lat-unattended.py`），規則見技能的 `references/unattended.md`。

- **設定**：「設定」對話框「全局設置」最上面是新主控一開始的模式（人工確認或無人模式）、參謀可以替你決定的三件事與時間上限；下面「各專案」列出看板上有主控的每個專案，可選跟全局、人工確認或無人模式。每按一下就寫入，其他開著的頁面會跟著更新。
- **開啟**：主控輸入框旁的「選項」選單有「無人模式」段，寫著現在的模式與來自哪一層。按「開啟無人模式…」從右邊（手機從下面）滑出表單，預先填好主控從你第一句話擬的目標與做完條件；目標或做完條件空白時不能送出。按「確認開啟」才生效；按「取消」、點表單外面或按 Esc 都會關掉表單，什麼都不寫，打到一半的內容也不留。
- **狀態卡**：無人模式時主控頁上方顯示「無人模式（來自全域預設／這個專案／這個主控）」、「關掉」與一行目標；點目標展開完整目標、做完條件、何時停、各層設定與「修改」。「修改」打開同一張表單，送出成為新版本並立即生效。預設就是無人模式而主控還沒擬目標時，顯示「等主控擬目標」，這時還沒有生效的授權。名冊上的主控卡標「無人」。
- **紀錄**：表單送出、修改與關掉都記在那個主控的「操作紀錄」；送出時看板先把表單內容寫進紀錄，工具核對有這一筆才建立授權。測試用登入不能改這些設定，也不能開關。

## 版面與外觀

- **名冊與待辦**：電腦版面（寬度超過 760px）的名冊從視窗頂端延伸到底，指令列只在待辦與內容欄下方。名冊與待辦的右邊界都可以拖曳調整寬度（連按兩下還原），名冊 170 到 440px、待辦 260 到 720px；視窗較窄時另外不超過視窗寬度的 30% 與 42%。名冊頂端第一行最左邊的按鈕把名冊收成窄直條，收合方式見[名冊收合](#名冊收合)。直條上每個主控一個狀態標記與待決題數，各組之間有短線，新建、重新整理與設定按鈕固定在直條底部；點標記開啟該主控且維持收起，滑鼠停留或手機長按標記會顯示專案、主控名稱、狀態與目前階段。
- **設定按鈕**（電腦在名冊頂端，手機在頂端列）：切換深色與淺色主題，調整整體大小（80% 到 150%，文字與間距一起縮放，可還原預設）與最小字體（10 到 24px，比它小的字一律放大到這個大小，預設不限），以及終端字體（10 到 28px，每格 1px，預設 16px，有還原預設；只改終端分頁的文字，不受整體大小與最小字體影響，調整後終端分頁立刻套用，手機在終端分頁沒有設定按鈕，到其他分頁調整後回來即生效），以及用量列的詳細或精簡樣式、對話翻譯的自動翻譯或手動切換。淺色主題是白底黑字、不用半透明，狀態靠形狀分辨：▲ 等你、● 進行中、■ 已交付、○ 閒置、◇ 已關閉；Herdr 分頁上狀態不明的 Agent 是 □。
- **返回與重新整理**：開著的畫面寫在網址裡，返回照層級走，不照看過的順序走：手機頂端列的「←」與系統返回（電腦是瀏覽器的上一頁）都往上一層，順序是中間欄、Agent 或主控頁、項目。在 Agent 或主控頁按返回一律回中間欄，不管中途看過多少個其他 Agent 或主控；從它們的頁面打開的項目（Agent 頁是在同一頁就地打開，不在待辦時會往前讀已處理的項目，都找不到就只顯示 Agent 頁）先回那個頁面，再按一次回中間欄；從中間欄直接打開的項目回中間欄；從項目或 Agent 頁跳到另一個 Agent 或主控後也回中間欄；新增 Agent 與新主控表單同樣回中間欄。回到中間欄時是離開時的分頁（待辦、Herdr、額度）和捲動位置，再按一次才離開看板。跳到另一個 Agent 或主控後，瀏覽器的「下一頁」也回不到之前看過的畫面。重新整理後開回同一個畫面，返回路徑照舊；從別處直接打開畫面的網址時，返回同樣照層級走；找不到那一則或那個主控時顯示「已不存在」（待辦沒有、已處理也讀不出來時，改為提示重新整理再試）。
- **從別的網頁回到看板**：從網址列或外部連結整頁載入看板，再按瀏覽器的「上一頁」回到看板時，頁面會重新載入，捲動位置與展開狀態重設，即時更新照常，指令列草稿仍在。
- **記在各自裝置的設定**：待辦的排序方式、中間欄的分頁（待辦或 Herdr）、名冊收合、兩欄寬度、主題、整體大小、最小字體、終端字體、資訊頁「詳細資料」的開合、手機指令列的收起與還沒送出的文字，都記在各自裝置的瀏覽器裡；瀏覽器不允許儲存時一切照常運作，只是不記憶。用量列樣式與對話翻譯偏好不在其中，由看板統一保存、所有裝置共用。

## 資料怎麼更新

看板監看面板綁定登記、各主控的問題檔與回報紀錄目錄，有變動才重讀，正常在 5 秒內推到所有開著的頁面。漏掉變動時由保底重讀補上，最慢 60 秒；畫面上的重新整理按鈕與每次載入頁面都會立即重讀，重讀時圖示轉圈，至少一圈。連線中斷時重新整理按鈕變紅，並自動重連；連上後變回原色。

操作結果與讀取錯誤都以浮動通知顯示（電腦在指令列上方，手機在頂端列下方；手機的終端分頁隱藏頂端列時在頁面最上方），不插進頁面內容，所以不會推動版面。成功的通知幾秒後自動消失，失敗的要按 × 關掉。持續中的狀況（讀取錯誤、送出紀錄讀寫失敗、作答途中題目被改版）的通知在狀況解除後自動消失，按 × 只是暫時收起。連線中斷時頁面自己讀不到資料不發通知，連上後會再讀一次，仍讀不到才顯示；這時點開回報沒能標為已讀也不發通知，那一筆維持未讀。

回報內容、題目說明、選項內容與推薦、對話紀錄以 Markdown 顯示：文字裡的 HTML 一律當成文字顯示，不安全的連結與圖片不顯示，連結在新分頁開啟。時間不顯示年份。表格每欄至少五個字寬，長的格子約三行內放得下、欄位相應加寬；表格比版面寬時只在表格自己的範圍內橫向滑動，頁面不會跟著捲。

## 自訂樣式

把自己的樣式寫在設定目錄的 `user.css`。設定目錄預設是 `$XDG_CONFIG_HOME/lat/board`，沒設定 `XDG_CONFIG_HOME` 時是 `~/.config/lat/board`；也可用 `LAT_BOARD_CONFIG_DIR` 直接指定。它在內建樣式之後載入，所有已登入裝置重新載入頁面就會套用；刪掉檔案就恢復預設，不需要重啟看板。

顏色、圓角與字型都是 CSS 變數，例如：

```css
:root {
	--accent: #ff8a3d;
	--radius: 2px;
}
```

| 變數 | 用途 |
| --- | --- |
| `--bg`、`--surface`、`--line` | 底色、卡片底色、邊框 |
| `--text`、`--muted` | 文字、次要文字 |
| `--accent`、`--warn`、`--ok`、`--danger` | 強調、待決與求助、交付、錯誤 |
| `--status-waiting`、`--status-working`、`--status-delivered`、`--status-ended` | 狀態標記的顏色（閒置與已關閉共用 `--status-ended`） |
| `--selected-bg`、`--selected-text` | 選中的控制項 |
| `--radius`、`--radius-pill` | 圓角 |
| `--sans`、`--mono` | 字型，例如 `--sans: 'Noto Sans TC', sans-serif;` |

變數寫在 `:root` 對深色與淺色主題都生效；只想改其中一個主題時，用 `:root[data-theme='light']` 或 `:root[data-theme='dark']`。內建淺色主題的顏色在白底上的對比都不低於 7:1；自己覆蓋的顏色不會被檢查。

## 更新

1. 在專案目錄 `git pull`。
2. 重新安裝技能（指令見 [README](../README.md#本地開發) 的安裝腳本），看板才會用到新版的面板輔助工具。
3. 在 `board` 目錄執行 `bun install`。
4. 部署：有跑背景服務時執行 `bash scripts/deploy.sh`（在 `board` 目錄），它只用已提交的 `HEAD` 建置（設環境變數 `LAT_DEPLOY_COMMIT=<提交>` 則改部署那個提交，也用來退回舊版），不帶工作資料夾裡未提交的修改：在臨時的 git worktree 建置到 `build-new`，換成 `build`（舊版暫存為 `build-prev`），重啟 `lat-board`，等 `http://127.0.0.1:7100/login` 回 200 後丟掉舊版與臨時資料夾，最後印出待辦與已處理的現況。建置失敗時正在用的 `build` 不動；換上後重啟失敗或登入頁一直不回 200，會把舊版放回去、重啟並再確認登入頁，結束碼為 1。服務名稱、連接埠與等待秒數可用環境變數改（見 [board/README.md](../board/README.md#部署)）。沒有背景服務時，在 `board` 目錄執行 `bun run build`。
5. 想確認主機上的真實資料：在 `board` 目錄執行 `bun run board inbox`，不需登入，只讀不寫。它列出待辦的每一筆、已處理的筆數與各種提問結果；有資料讀不到時會寫明原因，結束碼為 1。它看不到畫面長什麼樣，也不是問正在跑的服務，而是用目前資料夾裡的程式讀資料。

技能更新後，正在跑的主控要從它的下一個回合才開始留下回報紀錄，更新前的訊息不會補上。

## 疑難排解

- **新建或喚醒後 Herdr 沒有開新分頁，最後顯示 hcom 逾時或「仍在啟動」**：看板呼叫 hcom 時會要求它在 Herdr 開新分頁（`--no-run-here`），否則 hcom 會把主控跑在看板自己的程式裡，看不到也不能用。看板是舊版時請更新；hcom 太舊、不認得這個選項時（實測 0.7.29 可用），更新 hcom。之後到 Herdr 查看有沒有留下沒用的分頁，有就手動關掉。

## 連線來源與反向代理

看板在處理任何請求之前，先看連線是從哪個位址來的。兩個設定（都是環境變數，可以寫 IP 或 CIDR 範圍，多筆用逗號或空白分開）：

| 設定 | 作用 | 不設定時 |
| --- | --- | --- |
| `LAT_BOARD_ALLOWED_SOURCES` | 可以直接連到看板的位址。不在清單上的連線一律回 403，連登入畫面都看不到 | 只有主機自己（`127.0.0.0/8`、`::1`） |
| `LAT_BOARD_TRUSTED_PROXIES` | 信任的反向代理。只有連線來自這些位址時，看板才相信它轉來的 `X-Forwarded-For`（瀏覽器真正的位址）與 `X-Forwarded-Proto: https`（瀏覽器用的是 HTTPS） | 不信任任何代理 |

清單裡寫錯（不是 IP 或範圍）時，看板與主機指令都不會啟動，並說是哪一項。

**放在反向代理後面**（例如代理在 `192.168.1.10`，經 HTTPS 轉給看板）：

```ini
Environment=LAT_BOARD_ALLOWED_SOURCES=127.0.0.1,::1,192.168.1.10
Environment=LAT_BOARD_TRUSTED_PROXIES=192.168.1.10
```

- 代理要同時列在兩個清單裡；只列在信任代理而不在允許來源時，它的連線一樣被拒。
- 經代理連入時，輸錯密碼的鎖定與服務紀錄用的是瀏覽器真正的位址。看板從 `X-Forwarded-For` 的最右邊往左找，取第一個不是信任代理的位址；內容格式不對時改用代理自己的位址。`X-Real-IP`、`CF-Connecting-IP` 一律不看。代理應該把 `X-Forwarded-For` 設成它看到的連線位址，不要接在瀏覽器自己送來的值後面。
- 代理說瀏覽器用 HTTPS 時，登入 cookie 只走加密連線（`Secure`），回應另加 HSTS。在主機上用 `http://127.0.0.1:7100` 開照常可以登入。
- 舊版用來讀代理位址的 `ADDRESS_HEADER`、`XFF_DEPTH` 已經沒有作用，可以從服務設定移除。

**從其他機器直接連**：把那台機器的位址（或整個網段）加進 `LAT_BOARD_ALLOWED_SOURCES`。這樣連線沒有加密，只應在你信任的網路這樣做（見「安全」）。

**更新後打不開**：從其他機器或經代理開看板只看到 `Forbidden` 時，表示連線位址不在允許清單上；服務紀錄（`journalctl --user -u lat-board`）裡的 `source_refused` 那一行有被拒的位址（`peer`）。把它加進清單後重啟看板。

## 安全

看板本身沒有加密連線（沒有 HTTPS）。登入後能對主控下指示、開新 Agent，等於主機上的遠端操作，所以預設只接受主機自己的連線。要從其他機器用，放在提供 HTTPS 的反向代理後面，並照「[連線來源與反向代理](#連線來源與反向代理)」設定允許來源與信任代理；不經代理、直接以 http 從其他機器連時，密碼、回報全文與 pd 待核准的請求內容都以明文傳送，同一個網路上能監看流量的人看得到。登入要密碼加上 passkey 或手機驗證器 App 的數字，只知道密碼的人進不來；但拿到 TOTP 金鑰（`totp.json`、設定時的 QR code）的人等於有了第二道驗證，拿到密碼與還沒用掉的 passkey 登記碼的人可以登記自己的 passkey。

看板的每個回應都帶安全標頭：不准其他網站用框架嵌入看板、不准瀏覽器猜檔案類型、連到外部網站時不送出看板網址，並禁止外掛物件與改寫基準網址；經 HTTPS 代理開時另外要求瀏覽器一年內只用 HTTPS 連這個網址。
