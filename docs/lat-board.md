# LAT 看板：安裝與使用

LAT 看板是跑在主機上的網頁服務。電腦與手機用同一個網址，就能看到所有專案的 LAT 主控目前做到哪、收它們的交付與求助回報、回答待決題、看完整的對話紀錄、直接傳話給主控，也可以新建主控、喚醒閒置或已關閉的主控，並切換主控的模型與思考強度。

它不顯示終端畫面，也不做手機推播。LAT 主控以外的 Agent 在「Herdr」分頁查看清單與對話紀錄，也可以傳話、中斷與關閉，有接 HCOM 的還可以切換模型與思考強度。Herdr 的待答面板照舊可用，兩邊可以同時使用。開發者與設定細節見 [board/README.md](../board/README.md)。

## 需要什麼

- 一個執行環境，Bun 或 Node 擇一即可，兩個都有也行：
  - **Bun**（實測 1.3.14）：安裝、建置、啟動、設定密碼都只用 Bun，主機不需要 Node。
  - **Node 22.17 以上**（實測 22.17.0）：用 npm 安裝與建置；`board` 指令改用 `node --experimental-strip-types src/cli.ts <指令>`（Node 22.18 以上可省略 `--experimental-strip-types`）。以下的 `bun install` 換成 `npm install`、`bun run build` 換成 `npm run build`、`bun run board <指令>` 換成上面那行。
  - 兩者都有時，伺服器用 Node 執行；只有 Bun 時由 Bun 執行。
- 已安裝的 LAT 技能，以及它一直在用的 `uv` 與 Python：看板不自己讀寫問題檔，一律呼叫技能裡的面板輔助工具。
- 傳話要用到 `hcom`。新建主控與喚醒還要用到 `herdr`（新建另需 `git`），而且看板要連得到正在執行的 Herdr（它的 socket）。

## 安裝與建置

```bash
git clone https://github.com/ouob-tw/LoopAgentTeams.git   # 已有本地工作區就略過
cd LoopAgentTeams/board
bun install
bun run build
```

## 啟動

```bash
bun run board start
```

預設監聽 `0.0.0.0:7100`。用 `--host`、`--port` 改位址與連接埠，例如 `bun run board start --host 127.0.0.1 --port 7200`；也可以用環境變數 `HOST`、`PORT`。之後用 `http://<主機位址>:7100` 開啟。其他設定（狀態目錄、技能位置等）都是環境變數，見 [board/README.md](../board/README.md) 的設定表。

在某個 Agent 的終端機或 Herdr 窗格裡啟動看板也可以：看板新建、喚醒或接回主控時，不會把那個 Agent 的身分（hcom 名稱、client 的 session 等環境變數）和那個窗格的位置傳給 hcom，所以新主控不會變成那個 Agent 的子 Agent，第一則訊息也不會多出「把結果回傳給它」的句子，新主控也不會被記成跑在看板所在的窗格，效果與背景服務相同。萬一 hcom 記的主控窗格就是看板所在的窗格，切換 Codex 模型時看板會拒絕停止主控，不會關掉看板自己的窗格。

## 登入

看板用一組密碼登入。沒登入的瀏覽器只看到登入畫面，什麼資料都拿不到。

**設定密碼**：在主機的 `board` 目錄執行

```bash
bun run board password
```

輸入時畫面不顯示，要輸入兩次且一致才生效。還沒設定密碼時，登入畫面會提示這個指令，任何人都無法登入。

**登入**：在任何瀏覽器打開看板、輸入密碼即可。登入後這個瀏覽器保持登入 400 天，重新載入或關掉瀏覽器再開都不必再輸入；換瀏覽器或清掉網站資料後要重新輸入密碼。

**變更密碼**：再執行一次 `bun run board password`。新密碼立即生效，舊密碼不能再登入，不必重啟看板。已登入的裝置不會因此登出；要讓某台登出，用下面的 `revoke`。

**忘記密碼**：看板不能從登入畫面重設密碼，也查不回原本的密碼（只存加鹽的雜湊）。到主機上執行 `bun run board password` 設一組新的即可。

**輸錯密碼**：同一個來源位址連續輸錯 5 次後，1 分鐘內一律拒絕（密碼正確也一樣），畫面會顯示要等幾秒；期滿後恢復。這個計數只存在記憶體，重啟看板會清除。看板放在反向代理後面時，所有連線看起來都來自代理的位址，會共用同一個計數；要以真正的來源計算，啟動時設定 `ADDRESS_HEADER`（例如 `X-Forwarded-For`，代理須設定這個標頭），並視代理層數設定 `XFF_DEPTH`。設定後，不經代理、沒帶這個標頭的連線會登入失敗，所以只在所有連線都經過代理時才設定。

**管理已登入的裝置**：

```bash
bun run board devices            # 列出已登入的裝置（ID、登入時間、瀏覽器）
bun run board revoke <裝置 ID>   # 撤銷一台裝置，它會回到登入畫面
```

**從配對碼版本升級**：之前已配對的裝置升級後照常使用，不必輸入密碼，也會出現在 `devices` 清單中。`bun run board pair` 已移除；狀態目錄裡留下的 `pairing-codes.json` 不再使用，可以刪掉。升級後記得先設定密碼，新裝置才登入得了。

## 在背景常駐

範例檔 [board/lat-board.service](../board/lat-board.service) 是 systemd 使用者服務，登出與重開機後都會自動恢復。

1. 先確認 `bun run build` 已完成，並用 `command -v node uv hcom herdr git` 查出這些指令所在的目錄（只有 Bun 的主機把 `node` 換成 `bun`，並把範例檔的 `ExecStart` 改成 `/usr/bin/env bun build/index.js`）。
2. 複製範例檔並把 `<...>` 換成實際值：`WorkingDirectory` 填專案裡的 `board` 目錄；`PATH` 要含上面查到的目錄，因為服務的 PATH 很短，找不到 `uv` 或 `hcom` 時，待決題與傳話會失敗；找不到 `hcom`、`herdr` 或 `git` 時，新建主控會失敗。Herdr 的 socket 不在預設位置時，另外加一行 `Environment=HERDR_SOCKET_PATH=<socket 路徑>`（在 Herdr 分頁裡執行 `echo $HERDR_SOCKET_PATH` 可以查到）。

   ```bash
   mkdir -p ~/.config/systemd/user
   cp lat-board.service ~/.config/systemd/user/   # 在 board 目錄執行
   ```

3. 啟用，並讓它在沒登入時也跑：

   ```bash
   systemctl --user daemon-reload
   systemctl --user enable --now lat-board
   loginctl enable-linger "$USER"
   ```

4. 查狀態與紀錄：`systemctl --user status lat-board`、`journalctl --user -u lat-board`。

要改位址或連接埠，改已複製的 `~/.config/systemd/user/lat-board.service` 裡的 `HOST`、`PORT`（改專案裡的範例檔不會生效）；其他設定用同樣方式加一行 `Environment=`，改完 `systemctl --user daemon-reload && systemctl --user restart lat-board`。

用背景服務時，主機上的 `password`、`devices`、`revoke` 仍照「登入」一節手動執行。若你改了狀態目錄（`LAT_BOARD_STATE_DIR`）或其他設定，這些指令要用相同的環境變數，否則改到另一份資料。

## 待辦與已處理

待辦只列還要你處理的：還沒回答的待決題、還沒讀過的交付與求助回報，以及還沒結束的看板提問（見「在看板回答 Agent 的提問」）。

- 點開一筆交付或求助回報，會打開該主控的資訊頁、停在對話紀錄裡那則訊息（以回報的樣式顯示，上下標出較新、較早的訊息）；主控已不在名冊上時照舊只顯示回報內容。
- 點開一筆回報就算已讀，所有裝置一起同步；畫面還停在它時它留在待辦，打開別項或回到列表後才移到「已處理」。想晚點再處理時，按回報下方的「標為未讀」，它就回到待辦；畫面還停在這筆回報時它會維持未讀，下次點開才又變成已讀。
- 按待辦上方的「已處理 N」切換到已處理清單，新到舊列出已讀的回報、發出滿 7 天的回報（不論已讀未讀）與答過的題目，依處理的時間排。未滿 7 天的回報可以在這裡「標為未讀」移回待辦；滿 7 天的仍可打開看全文，但不能再改已讀狀態，也不能移回待辦。
- 答過的題目以卡片顯示：選的選項打勾並標上顏色，「其他」與備註另外列出；主控的對話紀錄裡也是同樣的卡片。
- **看板提問**：每筆還沒結束的看板提問是待辦的一筆，等待中的與已逾時、還沒作答的都在。標題寫 Agent 名稱、種類（提問／權限確認）、第一題（權限確認寫工具名稱），等待中的另顯示剩餘時間。點開到該 Agent 的頁面，停在那張題目卡；主控的權限確認點開是主控資訊頁。在待辦點進去作答與在 Agent 頁面作答是同一份狀態，任一邊作答另一邊跟著變。已填回、已傳話、結果不明、已中斷、Agent 已不在的提問移到「已處理」並標結果，與其他項目一起依結束時間排，滿 7 天連同提問紀錄一起消失。
- 待辦可以依時間或依專案排序，選擇記在各自裝置的瀏覽器裡。看板提問依時間排時，還能作答的排在最前面；依專案排時，排在 Agent 工作資料夾所屬的專案底下（查不到資料夾的歸「（未知）」）。
- 清單一次載入 50 筆，捲到底會自動載入更早的，也可以按「載入更早」；載入失敗時按這個按鈕重試。
- 只保留一個月：發出滿 30 天的回報、提問滿 30 天的題目不再列出；一個對話的回報最新一筆也滿 30 天時，看板會把整個回報檔刪掉，**刪掉的回報救不回來**。閒置或已關閉的主控回報被刪掉後，就不會再出現在看板上，也無法從看板喚醒；還在運作的主控照常顯示。

## 回答待決題

在待辦點開待決題，直接在內容區作答：單選、複選、純文字，選擇題可改填「其他」，每題都可以加備註。送出後由看板寫入問題檔並通知主控，效果與在 Herdr 待答面板作答相同；兩邊可以同時使用，同一題先送出的答案算數。

- **題目怎麼顯示**：進入該主控的對話紀錄，題目卡片出現在主控提問的那則訊息的位置，依序是說明、選項、推薦與詳細資訊，畫面停在被打開的那一張。同一則訊息一次問了好幾題時，那則訊息的位置會一張接一張顯示所有仍在待辦的題目，其他題同樣可以作答，答過的以唯讀卡片顯示。主控還在提問的那一回合、訊息還沒出現時，卡片先放在對話最新的位置。實在找不到提問的訊息時，只顯示卡片並註明「找不到提出這題的原訊息」。
- **送出後**：該題顯示「已送出，等主控記錄」；主控記錄後從待辦移到「已處理」，標「已回答」。在主控的送出紀錄裡，狀態會變成「已記錄」；送出後題目被主控改版則顯示「題目已改版」。在 Herdr 面板作答的不在這份紀錄裡。
- **答過的題目**（唯讀卡片）：選中的選項加勾號與強調色（複選每個選中項都有），答「其他」時多一列「其他：<內容>」，純文字題的答覆也是一列，備註顯示在選項下方的淺色框「你的備註：…」（沒有備註就不顯示），「已處理」與對話紀錄用同一個版面。
- **題目被改版**：你開始作答後主控改了題目（升版或改內容），畫面改顯示目前的版本並提示，送出會被拒絕、問題檔不會被寫入；你填的文字與備註保留，選項要重選。
- **不能作答的情況**：已經送出過的題目（例如在 Herdr 面板）、閒置與已關閉主控的待決題都不能作答。答覆不符合題型或寫入失敗時，畫面顯示原因，你填的內容留著。
- **通知主控失敗**：答案已寫入但通知主控失敗時，顯示「已送出，但通知主控失敗」與「重新通知」按鈕，所有裝置都看得到。按下才會重送，看板不會自己重送，重送也不會改寫答案；仍送不到時，請在聊天告訴主控。
- **主控停用 LAT 後**：還在等記錄的答覆，看板會再讀一次它留下的問題檔，顯示「已記錄」、「題目已改版」、「主控已停用 LAT，沒有記錄這份答覆」，讀不到時顯示「主控已停用 LAT，無法確認這份答覆有沒有被記錄」。

## 傳話給主控

在底部的指令列輸入文字（`@名稱 訊息`；不寫名稱時送給目前開著的主控）。名稱帶 tag 的主控（hcom 名稱如 `dipo-latpstack-tevu`）在看板各處只顯示最後一段 `@tevu`，滑鼠停留可看到完整名稱；`@tevu` 與 `@dipo-latpstack-tevu` 都能指定它，實際傳話仍用完整名稱。最後一段對到不只一個主控時不送出，提示「名稱重複，請打完整名稱」並列出候選。看板把文字打進該主控 client 的輸入框並送出，不經過 HCOM 訊息，所以主控把它當成你本人在那個分頁打的字。

- **對象與失敗**：送出前看板會重讀資料、確認主控仍啟用；對象是閒置或已關閉的主控時改為喚醒（見下節）。失敗時以通知顯示原因，文字留在輸入框，不會自動重試，也不會改走別的管道。
- **不要同時在那個分頁打字**：兩邊的文字可能混在一起送出。
- **多行**：多行文字以一則訊息送出。
- **Enter 與送出鈕**：畫面寬度 760px 以下，或只有觸控、沒有滑鼠或觸控板的裝置，Enter 換行、按按鈕送出；其他情況 Enter 送出、Shift+Enter 換行。輸入法選字時的 Enter 不會送出。
- **skill 名稱提示**：對象是 Claude 時，在行首或空白後打 `/`；對象是 Codex 時打 `$`，就會跳出它能用的 skill（它已安裝的，加上它工作資料夾裡的專案 skill；不列 `/model` 這類 client 內建指令，也不混列另一種 client 的），每項附描述的第一句，依打的字篩選。上下鍵移動、Enter 或 Tab 插入（Claude 寫成 `/名稱`、Codex 寫成 `$名稱`）、Esc 關閉且不改文字，手機直接點選。對象依指令列的 `@名稱`、開著的主控或 Agent 判斷。路徑或字中間的 `/`、輸入法選字中都不會跳出；讀不到清單時只是不提示，照樣可以送出。Claude Code 內建的 skill（如 `/simplify`）與 claude.ai 帳號帶來的 skill 沒有可讀的檔案，不會出現在清單裡。
- **手機**：同一個指令列固定在畫面底部（在螢幕鍵盤上方），分成兩行：第一行只有輸入框（送出鈕在框內右側）；第二行由左到右是模型與思考強度、迴紋針、麥克風、喚醒選項（喚醒時才有），最右邊的 ▾ 把指令列收成右下角的圓鈕，選擇記在裝置上。手機不顯示收件對象，只有用 `@名稱` 指定開著的主控以外的對象時，輸入框上方顯示「→ @名稱」。
- **紀錄**：每次傳話不論成敗都記下來，在該主控的資訊頁可以看到，所有已登入裝置看到的相同。

## 名冊收合

電腦版面（寬度超過 760px）的名冊可以收成窄直條：收起時點直條的空白處展開（游標變成 `→|`）；展開時點名冊的空白處收起（游標變成 `|←`）。點在主控卡片、按鈕、彈出框、欄寬拖曳條上，或剛選取完文字時不會收起。手機版面不受影響。

## 主控職責

主控記下自己負責做什麼之後，看板在這些地方顯示：

- **名冊卡片**：目前階段下面多一行職責，放不下時截斷；手機的名冊標籤顯示在名字下面。
- **說明框**：滑鼠停在名冊卡片或收起名冊的圓點上，或在手機上長按名冊標籤，會跳出說明框：上面是狀態與目前階段，下面是完整職責與結果。長按不會打開主控，輕點才會。
- **主控資訊頁**：「詳細資料」的第一列。
- **Herdr 分頁**：卡片上不顯示。滑鼠停在卡片上會跳出說明框（取代原本瀏覽器的小提示），主控的會加上職責；按右鍵或長按跳出的選單最上面也有。

結果一欄在交付前是主控寫的「預期結果」；記下職責之後有了交付（DONE）回報，就換成最近一則的摘要，標「已交付結果」。還沒記下職責的主控照舊顯示，不會出現「未填」。

主控啟用 LAT 時會拿到記錄指令（`lat-session.py duty`），任務改變時再執行一次就會覆蓋。還沒記下就發出 DECIDE、HELP 或 DONE 時，回合結束檢查會攔下一次，提醒它先記下。職責存在回報紀錄目錄的 `<session>.duty.json`，回報檔滿 30 天刪除時一起刪。

## 新建主控

按名冊頂端的「新建」（收起的名冊是底部的 ＋ 圖示），表單由上而下是資料夾、Herdr 工作區、第一句話、一列設定（client：Claude 或 Codex、模型、思考強度）、送出鈕，最下面是最近新建的紀錄。資料夾預先帶入最近用的那個，只打第一句話就能送出。看板會在該專案的 Herdr 工作區開一個新分頁，用 hcom 在那個資料夾啟動 client，第一則訊息是 LAT 啟動指令加上你的話：Claude 是 `/lat 你的話`，Codex 是 `$lat 你的話`。「模型」「思考強度」兩欄的第一項寫出不選時會用的值（例如「預設：Opus 5.5（claude-opus-5-5）」「預設：medium」），是看板從該 client 的設定檔讀到的，Claude 會疊上所選資料夾的專案設定；讀不到時寫「讀不到 client 設定，交給 client 內建預設」。不選就不帶參數，用該 client 平常的設定（選項見[模型與思考強度](#模型與思考強度)）。主控啟用後會自動出現在名冊上。從看板新建的 Claude 主控會以 `--dangerously-skip-permissions`（bypass permissions）啟動。喚醒、換模型或從「已關閉」接回 Claude 時，看板保持它接回前的權限模式（以對話紀錄最後一則使用者訊息的模式為準），不在看板啟動的主控也一樣。以 `--dangerously-skip-permissions` 啟動（例如從看板新建）、後來在對話裡改成別的模式的主控，接回後維持那個模式，但這段對話之後就不能再用 Shift+Tab 切回免確認模式。Codex 不受影響。

- **skill 名稱提示**：第一句話（開新 Agent 是第一則訊息）的輸入框和指令列一樣會提示 skill，對象是表單選的 client 與資料夾（見[傳話給主控](#傳話給主控)的「skill 名稱提示」）。
- **資料夾**：一個輸入框，輸入完整路徑（`~` 代表執行看板的使用者的家目錄）。還沒改過時點進去，下拉列出最近用過的 5 個專案（從主控回報紀錄整理）。一開始打字就即時列出：名稱或路徑含有輸入文字的已知專案，以及輸入路徑所在那一層、名稱含有最後一段的子資料夾（不分大小寫，開頭符合的在前；最後一段以「.」開頭時才列隱藏資料夾；指向資料夾的符號連結也列出）。每列寫出名稱、路徑、是否在 Git 專案裡，已知專案另寫最近使用時間，或「資料夾已不存在」。上下鍵移動、Tab 把該資料夾補進輸入框並加上 `/` 繼續往下一層找、Enter 或滑鼠點選選定、Esc 關閉下拉；選定不會送出表單。
- **資料夾還不存在時**：輸入框下方寫「這個資料夾還不存在，送出時會建立並 git init」，送出時看板建立它（中間缺的層一起建），再 `git init`、啟動主控（建在既有 Git 專案裡也一樣，新資料夾自成一個專案）。只會建在家目錄底下，以真實路徑判斷，經符號連結跑出家目錄也不行；家目錄以外的路徑不能送出，並寫明原因。建立失敗時不啟動主控，這次建出的空資料夾會移除；資料夾建好但 git init 失敗時，資料夾留著、不啟動主控。紀錄會標示「已新建資料夾」。
- **不在 Git 專案裡的資料夾**：主控在那裡不能啟用，所以選定這種現有資料夾時才出現「不在 Git 專案裡：先 git init 再開」，勾選才能送出。勾選後看板先在該資料夾執行一次 `git init`，成功才啟動主控；失敗會顯示原因，不會啟動。Git 專案裡的子資料夾可以直接開，主控在該子資料夾啟動。
- **開在哪個 Herdr 工作區**：資料夾下方的「Herdr 工作區」選單預設「自動」，也可以改選 Herdr 目前列出的任一工作區，或「新建工作區…」：選了會出現名稱欄，預設是所選資料夾的名稱、可以改，送出時才建立並把主控開在裡面。選了的工作區在送出前被關掉、或新建失敗時，通知寫明原因、表單內容保留，不會改開到別的工作區。「自動」以專案為準，Git 專案看整個專案（根目錄），不在 Git 專案裡的看資料夾本身。看板找出已經有分頁停在這個專案裡的工作區，有好幾個時取分頁最多的、再取編號最小的；都沒有就以專案資料夾的名稱新建一個工作區（不會切換你的畫面）。
- **送出後**：新建主控頁下方列出最近的新建紀錄與狀態，所有已登入裝置看到的相同，重新載入後仍在。狀態有：啟動中、已啟用、「已開分頁，但主控尚未啟用，請到 Herdr 分頁查看」（等了 3 分鐘還沒啟用時）、「結果不確定，請到 Herdr 分頁查看」（看板沒拿到新主控的名稱時），以及失敗與原因。新主控的分頁一出現在 Herdr，這筆紀錄就多一個「看這個 Agent →」按鈕，按下打開看板上這個 Agent 的頁面，不必等主控啟用；主控啟用、出現在名冊上後，按鈕改成「看主控資訊 →」。看板不會自動換頁，也不會切換 Herdr 的焦點。主控啟用後，這筆紀錄也會出現在它的資訊頁的送出紀錄。新主控出現在 Herdr 的清單上後，看板會把它的分頁移到該工作區最前面；移動失敗不影響主控啟動，紀錄裡會寫明原因。同一時間只跑一個新建（與 Herdr 分頁的開新 Agent 共用），後送的會等前一個出現在 Herdr 或逾時後才開始。
- **失敗時**（資料夾無法建立、讀不到面板綁定登記、Herdr 或 hcom 執行失敗）：畫面顯示原因，表單內容保留，可以修正後再送。看板不會自動重試。
- **要留意**：每次新建都會在 Herdr 多開分頁，主控開始後就會用到額度。第一次在某個資料夾開 Claude 時，Claude 可能先問「是否信任這個資料夾」，這要到 Herdr 分頁按；看板只會在等太久時提示你去看。

## 喚醒閒置或已關閉的主控

不在工作的主控依「對話還在不在」（看 hcom 的 Agent 清單）分兩種：

- **閒置**（名冊上的標記是空心圓）：LAT 這一輪已停用，對話還開著。
- **已關閉**（空心菱形）：對話已經不在 hcom 清單上，不論 LAT 有沒有正常停用。

兩者處理方式相同：只在還有發出未滿 7 天的回報（已讀的也算）時留在名冊，待決題不再列出也不能作答，送話都走以下的喚醒。名冊依「等你、進行中、已交付、閒置、已關閉」分組，組內最近回報的在前；閒置或已關閉、最後回報超過 1 天的收在名冊最後的「閒置／已關閉 N ›」，點開依最後回報時間分成 3 天內、1 週內、更早。看板每次重讀資料時才判斷，主控關掉後最慢要等保底重讀（預設 60 秒）才會改成已關閉；LAT 還沒停用的主控之後又在 hcom 清單上出現（例如你在終端機接回）就恢復為啟用中，已停用的則回到閒置。hcom 清單讀不到時會跳出錯誤通知，並沿用上一次讀到的結果；看板剛啟動、還沒讀到過時，LAT 還沒停用的照常顯示為啟用中，已停用的顯示為閒置。

閒置的主控在主控資訊頁有「關閉」按鈕，進行中的主控有「關閉 Agent」，作用都與 Herdr 分頁的「關閉 Agent」相同：先確認一次，關掉它的對話與 Herdr 分頁，成功或失敗都跳出通知；之後它顯示為已關閉，仍可從資訊頁喚醒接回。按鈕只在 Herdr 的清單上找得到它時出現；看板自己所在的分頁不能關，HCOM 連線無法確認時按鈕停用。看板不會自己關掉主控。

進行中的主控若在 Herdr 的清單上、而且有接 HCOM，主控資訊頁在「關閉 Agent」旁還有「暫停通訊」（暫停中變成「恢復通訊」）與說明圖示，作用與 Herdr 分頁的相同（見下方 Herdr 分頁的說明）。暫停中的主控在名冊與資訊頁標「暫停通訊」，仍算進行中、不會變成已關閉，待決題照常列出可以作答；你從看板傳的話照樣打進它的輸入框。

用底部的指令列（電腦與手機相同）：對象是閒置或已關閉的主控時（開著它的資訊頁，或用 `@名稱` 指定），送出按鈕會變成「喚醒」，旁邊多一個選項按鈕，裡面有「開新一輪 LAT」勾選框（預設不勾，送出後也不會記住）與額度提醒；模型與思考強度在指令列的模型標籤上選。

- **不勾**：照你打的原文送出，適合問問題。主控仍不在工作（對話還在就顯示閒置），送出紀錄記「已喚醒」。
- **勾選**：看板在前面加上 LAT 啟動指令（Claude 是 `/lat 你的話`，Codex 是 `$lat 你的話`），讓主控開新一輪；送出紀錄記「已喚醒，等主控啟用」，主控重新啟用後在名冊上變回啟用中，回覆與待決題照常回到看板。
- **怎麼送**：看板先問 hcom 這段對話的 client 還在不在。還在（分頁還開著）就像傳話一樣打進它的輸入框；不在（分頁已關）就用 hcom 把同一段對話接回來，在該專案的 Herdr 工作區開新分頁，你的話當作第一則訊息，只送一次。工作區的選法與新建主控相同。
- **接回的結果**：hcom 回報就緒時記「已喚醒」；hcom 還在等啟動或指令逾時，記「已開始接回，結果尚未確定，請到 Herdr 分頁查看」，不算失敗也不會自動重試；其他失敗顯示原因，文字留在輸入框，可以再按一次。接回 3 分鐘後還沒出現時，那筆紀錄補上「接回後仍未出現，請到 Herdr 分頁查看」。
- **不會接回兩次**：前一次接回還沒確定結束時，再按喚醒會先查證：對話已經回來就改成打進輸入框；hcom 還看得到它，或前一次開的分頁還在，就擋下並說明「前一次接回還沒結束，請到 Herdr 分頁查看」；確定前一次的分頁已經不在，才再接回一次。看板重啟後也照樣擋。
- **放棄前一次接回**：看板連前一次開在哪個分頁都不知道時，會擋下並出現「放棄前一次接回」按鈕。按下後會先跳出確認：請先到 Herdr 關掉前一次的分頁；這個按鈕不會幫你關，沒關就再接回可能出現兩份對話。確認後那筆接回記為「使用者放棄」，之後就能再喚醒；取消則什麼都不變。
- **無法確認時不送**：讀不到 hcom 的 Agent 清單時，看板不接回也不送出，顯示「無法確認主控是否還在，沒有送出」，文字留在輸入框。
- **順便換模型**：看板確認主控的 client 已經不在時，指令列的模型標籤（例如「Opus 5.5・M」）可以點開選模型與思考強度，預設「保持目前」；選了就在接回時一起帶上。client 還在時標籤停用並說明原因。當初指定過模型的 Codex 主控，模型同樣停用、只能改思考強度。
- **切換沒完成時不喚醒**：這個主控有一次切換還沒確認已經停掉時，喚醒會被擋下，請先按模型標籤旁的 ⚠ 再按「繼續切換」，以免同一段對話跑出兩份。
- **新分頁的位置**：接回開的新分頁會移到該工作區的最前面，其他分頁的先後順序不變；移不動時留在最後面，不影響喚醒。
- **要留意**：接回會在 Herdr 多開分頁，也會開始消耗額度。

## 中斷主控這一回合

在 Herdr 有窗格、而且這一回合正在跑的主控，指令列的送出鈕左邊會多一顆和 Herdr 分頁 Agent 頁面相同的紅色停止鈕，有沒有打字都一樣，可以中斷它這一回合：按一次就直接對它的窗格按一次 Esc，等同在終端機按 Esc，沒有確認框；送出還沒有結果前停止鈕停用，連按不會送第二次。通知會寫出中斷的是哪個主控。回合有沒有在跑看的是 HCOM 的狀態（工作中或等待輸入才算在跑；HCOM 沒有這個主控時改看 Herdr 的狀態，和一般 Agent 相同），不是名冊上的處理中、等你、已交付：回合自然結束、主控閒著等回報時，停止鈕在 5 秒內消失、只剩送出鈕，不用重新整理，名冊上的狀態照舊。按 Esc 中斷（在看板或在終端機按都一樣）的情況，HCOM 常常不知道回合已經結束、一直回報工作中，所以看板在 HCOM 說工作中、Herdr 卻連續兩次讀取（相隔約 1 秒）都說閒置或已完成時，改當作閒置，停止鈕在 5 秒內消失；只有一次讀到閒置（例如回合剛開始、Herdr 還沒跟上）不會讓停止鈕消失。打字不會讓停止鈕消失，按停止鈕也不會清掉打好的文字；停止鈕只中斷目前頁面的這個主控，指令列用 `@名稱` 指定別人時照樣如此。閒置、已關閉的主控沒有停止鈕。按 Esc 失敗（窗格已不在、Herdr 指令出錯或逾時）時通知寫出原因，看板不會重試。成功或失敗都記在它的送出紀錄裡。中斷後看板不會自動傳話或喚醒。

## 模型與思考強度

底部指令列送出按鈕旁的標籤顯示對象主控上一回合使用的模型與思考強度，以縮寫表示（例如「Opus 5.5・M」，強度 L／M／H／XH／MX；滑鼠停留看完整名稱），是從主控自己的對話紀錄讀出來的；讀不到時顯示「模型」「強度」。

- **選項**：Claude 有 `claude-opus-5-5`、`claude-sonnet-5-5`、`claude-haiku-5-5`、`claude-fable-5-1`，Codex 有 `gpt-6.1-sol`、`gpt-6-astra`，思考強度都是 `low`、`medium`、`high`、`xhigh`。清單可用環境變數 `LAT_BOARD_MODEL_OPTIONS` 改（見開發者說明）；看板只照清單顯示選項，不檢查模型是否真的能用。
- **修改**：點標籤的模型或思考強度選新值，改過的部分變成強調色，再按 ✓ 一次套用（模型與強度一起改只會重開一次），✕ 取消。只改你選的那一項，不能選「回到 client 預設」。
- **怎麼換**：Claude 與 Codex 主控都一樣：看板會停掉它（`hcom kill`，原本的 Herdr 分頁會被關掉），確認停掉後再用新設定把同一段對話在新分頁接回來（Claude 用 `--model`、`--effort`，Codex 用 `-c`），和傳話排在同一個隊伍。只有 hcom 顯示它在等待（`listening`）時才會動手，正在工作、等你處理或狀態不明時，看板會請你等這回合結束再改。
- **不在對話裡打指令**：看板不會在 Claude 對話裡打 `/model` 或 `/effort`，因為 Claude Code 會把這兩個指令的選擇存成你之後新對話的預設，還可能跳出確認框。用接回時的參數換，只影響這一個主控，不會改你的設定檔。
- **只換模型時**：思考強度選「保持目前」時，看板會把上一回合用的思考強度一起帶上，免得換模型後變回該模型的預設；切換與喚醒都一樣。讀不到上一回合的思考強度時就不帶，送出前會提示「無法確認目前的思考強度，換模型後可能改用該模型的預設」。
- **主控不在時**：有沒切完的切換時，標籤旁出現 ⚠，點開有那筆切換與「繼續切換」「放棄切換」；沒有的話標籤停用並提示「主控目前沒有在跑，請在喚醒時一起選」。
- **當初指定過模型的 Codex 主控**：啟動參數裡有 `--model`、`-m` 或 `--oss` 時，接回後模型換不過去，所以標籤的模型會停用並說明原因，只能改思考強度。看板讀不到當初的啟動參數時，會提示「無法確認這個主控能否換模型」，照樣讓你試，再以下一回合核對結果。
- **沒切完的切換**：停止失敗、停止逾時，或停止後還看得到主控或原本的分頁，看板都不會接回，這筆「切換嘗試」會讓模型標籤旁出現 ⚠（看板重啟後也在），點開寫著舊設定、新設定與目前卡在哪一步。到 Herdr 看過後按「繼續切換」，看板會先查證：確定已經停掉就接回；主控還在而且在等待就重新停止；主控還在而且正在工作就拒絕；仍無法確認就保留並請你到 Herdr 查看。接回失敗時同樣按「繼續切換」再接回一次；接回後主控出現在 hcom 清單上，這筆嘗試就結束。不想繼續時按「放棄切換」，先確認一次，會結束這整次切換，看板之後不會再停止或接回它，放棄本身也不執行任何指令。
- **有沒有換成**：送出後標籤先顯示新設定並加虛線底線（「已送出切換，等下一回合確認」；主控資訊頁與 Herdr 分頁的 Agent 頁面都一樣），等新設定實際送出（打入或接回）之後的下一個回合再比對：和你選的一樣就清掉提示（隨模型一起帶上的思考強度不算你選的，不比對）；不一樣就在標籤旁出現 ⚠，點開顯示「切換沒有生效」和實際使用的值。Codex 的規劃模式另有自己的思考強度設定，看板不改。
- **要留意**：切換會關掉原本的分頁、再開一個新分頁（移到該工作區最前面），也會用到額度。

## 對話紀錄

點開主控（啟用中、閒置或已關閉都可以），標頭一行顯示狀態、專案、名稱與最後回報時間（還沒有回報時不顯示；client 與模型看指令列的模型標籤），職責、專案路徑與 Herdr 位置收在「詳細資料」；有待決題時標頭下方出現黃色提示條，點「作答」直接打開題目。下方分成「對話紀錄」「回報」「送出紀錄」三個分頁，預設是對話紀錄，最新的在最上面，列出你打的每句話和主控的每段文字回覆，包括回合中途的回答；文字以 Markdown 顯示。

- 待辦裡的交付或求助回報在對話中那則訊息加上綠框與「完成／求助」標籤。
- 主控在兩段文字之間做的事合成一行灰字「⋯ 做了 N 個操作」，點一下展開成每個操作一行的摘要，例如「🔧 執行指令：git status」；失敗的操作前面有「✗」。不會顯示指令輸出或檔案內容。
- hcom 通知、hook 提示這類自動塞進對話的內容不算你說的話，只算成操作（「📨 收到 hcom 通知」「🪝 hook 提示」）。
- 一開始顯示最近 50 段，往下捲到底會自動再往前取 50 段，也可以按底部的「載入更早」。
- 頁面開著時，主控寫下新內容 5 秒內會出現。剛開的 session 還沒有紀錄時只顯示「還沒有對話」，不跳通知；其他讀不到紀錄的情況會跳出通知說明原因，其他區塊照常。
- 紀錄來自 Claude 或 Codex 自己存的對話檔。你改過 `CLAUDE_CONFIG_DIR` 或 `CODEX_HOME` 時，背景服務也要加上相同的 `Environment=`。
- 讀不出來的行會略過，這一區上方註明「有 N 行紀錄讀不出來，已略過」；client 還在寫的最後一行不算。
- 操作摘要只顯示安全的內容：寫檔與改檔只顯示路徑，讀檔與搜尋顯示路徑或搜尋字串，讀網頁只顯示網址（不含 `?` 之後的參數）；指令只有整段是一行、而且只用英文字母、數字、空白與少數符號時才完整顯示（最多 80 字），其他指令只顯示程式名稱（例如「git …」），連程式名稱都看不出來時只顯示「執行指令」。

### 對話翻譯

分頁列（對話紀錄／回報／送出紀錄／操作紀錄）最右邊的翻譯圖示：按下亮起，畫面上的英文回覆顯示成繁體中文，再按一下回到原文。只在選中「對話紀錄」分頁時出現（已關閉 Agent 的頁面放在「對話紀錄」標題列最右）；主控資訊頁與 Herdr 分頁的 Agent 頁都有。分頁放不下時（例如手機上把最小字級調大），分頁列可以左右滑動，選中的分頁會自動捲到看得見的位置，翻譯圖示固定在最右邊。

- **設定**：設定裡的「對話翻譯」可選「自動翻譯」或「手動切換」（預設手動），所有已登入裝置共用。自動翻譯時打開對話就顯示中文；手動切換時顯示原文，圖示不亮。
- **圖示只改目前這個對話**：換到別的對話或重新整理後，又回到設定的偏好；沒按過圖示的對話會跟著偏好的變更即時改變，按過的維持按的結果。手動切換且沒按圖示時，看板不會翻譯任何內容，關閉翻譯時還沒回來的翻譯也會中止。手機寬度時分頁照樣平分寬度，圖示固定在最右。
- **翻哪些**：只翻主控或 Agent 的文字回覆，而且要是英文為主（程式碼、行內程式碼、網址與路徑不算）。你的訊息、操作行、以題目卡或回報卡顯示的訊息都不翻（列在對話紀錄裡、帶「完成／求助」標記的回報照常翻）；只翻已載入到畫面上的段落。
- **顯示**：還沒翻好的段落顯示原文並在標頭標「翻譯中」，翻好原地換成中文，下方「看原文」可展開或收起英文原文。程式碼區塊、行內程式碼、網址與路徑與原文完全相同。
- **失敗**：留著原文，下方小字「翻譯失敗，顯示原文（原因）」，不跳通知；換到別的對話再回來、重新整理，或關閉再開啟翻譯會重試，同一段失敗後 5 分鐘內再被要求會得到同一個失敗。
- **花費與存放**：翻譯由主機上的 Codex 執行，會用到 Codex 額度；譯文存在看板的狀態目錄、所有裝置共用，同一段文字只翻一次，30 天沒用到的清掉。

### 用量與快取

主控還在跑時，目前階段下方有一行小字，例如 `上下文已用 62% • 5 小時額度剩 40% • 7 天額度剩 25% • 快取命中 70% 20 分鐘後失效 • 權限：自動模式`：上下文已用多少、訂閱額度還剩多少、快取命中率與幾分鐘後失效、權限模式。Claude 主控的數字跟它終端機的狀態列相同。設定裡的「用量列」可改成「精簡」，這行改用狀態列的英文縮寫，例如 `Ctx 62% • 5h 40% • 7d 25% • Cache 70% ⏳ 20 min • Auto mode`（Codex 權限寫成 `approval on-request`）；隱藏與變色規則不變，資訊圖示的說明與「詳細資料」裡的執行狀況仍是中文全稱。預設「詳細」；這個設定存在看板的狀態目錄，所有已登入裝置共用，在任一台改了其他裝置立刻跟著變，不必重新整理。

- **只顯示需要留意的**：在安全範圍的項目會隱藏：上下文已用 10% 以下、5 小時額度剩超過 45%、7 天額度剩超過 30%、快取命中超過 80%、倒數超過 30 分鐘、權限是免確認。全部都隱藏時整行（連同資訊圖示）不顯示。快取還沒建立時顯示 `快取尚未建立`，已失效顯示紅色的 `快取已失效`，這兩個一定會顯示。
- **看全部數值**：行尾的資訊圖示，滑鼠停留或手機點一下，會列出所有數值；點別處關閉。主控資訊頁的「詳細資料」裡也有一列「執行狀況」，是完整的一行、什麼都不隱藏。
- **變色**：上下文已用到 80%、額度剩不到 20%、快取剩 5 分鐘以內會變黃；倒數每分鐘自動更新，主控有新回合後整行也會自動更新。Codex 主控沒有失效倒數，額度依它回報的期間標示（例如只有週額度時只有 `7 天額度剩`）。
- **權限模式**：放在最後。Claude 取自對話紀錄裡最後一則使用者訊息當時的模式，所以用 Shift+Tab 切換後，要等下一則訊息才會更新；Codex 顯示 rollout 裡的核准與沙箱設定。

Claude 主控的這些數字只有狀態列拿得到，要先在 `~/.claude/settings.json` 的 `statusLine.command` 原本的指令前面串上看板附的記錄程式，沒裝之前 Claude 主控不顯示這一行（Codex 主控不需要）。它需要 `bash` 與 `jq`，只記下用量數字，不存訊息、路徑或憑證，記錄失敗時不影響狀態列。

**安裝**：在原本的指令前面加上 `bash <看板目錄>/scripts/usage-recorder.sh `，其餘不動。例如原本是

```json
"statusLine": { "type": "command", "command": "bash ~/.claude/statusline-command.sh" }
```

改成

```json
"statusLine": { "type": "command", "command": "bash /path/to/LoopAgentTeams/board/scripts/usage-recorder.sh bash ~/.claude/statusline-command.sh" }
```

後面的指令照樣由 shell 拆成程式與參數，引號寫法不用改。但原本的指令若以環境變數設定開頭（例如 `FOO=1 cmd`），或用了 `|`、`&&`、`;` 這類組合，要整段包成 `bash -c '<原指令>'` 再接在後面，否則狀態列會變空白。只想記錄、不要狀態列時，後面可以不接指令。新的設定在下一次狀態列更新時生效，不用重啟 client。你改了 `LAT_USAGE_DIR` 時，狀態列與看板服務都要設定相同的值（見 [board/README.md](../board/README.md) 的設定表）。

**移除**：把 `statusLine.command` 前面加上的那段刪掉，再視需要刪除 `$XDG_STATE_HOME/lat/usage`（沒設定 `XDG_STATE_HOME` 時是 `~/.local/state/lat/usage`）。

## Herdr 分頁

中間欄上方有「待辦」「Herdr」與「額度」三個分頁（額度見下方「額度分頁」），點「Herdr」（舊稱「所有 Agent」）改列出 Herdr 所有工作區裡的每一個 Agent，包括 LAT 主控、主控派出的 Agent，以及你在其他專案自己開、沒有接 HCOM 的 Claude 與 Codex。看板記得你上次看的是哪一個分頁；主控名冊、待辦與主控資訊頁不受影響。這個分頁可以開新 Agent、檢視、傳話、中斷、關閉、切換模型，以及調整 Herdr 的分頁順序與改分頁名稱。

- **列出哪些**：以 Herdr 的 Agent 清單為準，依 Herdr 工作區分組，組內照 Herdr 裡的分頁與窗格順序排列，狀態改變不會讓位置移動。Herdr 的每個工作區都會列出標題，沒有 Agent 的工作區在標題下寫「沒有 Agent」。只在 hcom 裡、不在 Herdr 裡的 Agent（例如 tmux 裡的或子 Agent）不列出；Agent 從 Herdr 消失後也會從清單消失。
- **每一筆顯示什麼**：標題是 Herdr 分頁名稱，後面以小字接著 HCOM 名稱（例如「2 · sema」；分頁名稱已含 HCOM 名稱時省略，分頁名稱太長放不下時也省略），以及狀態、client 種類與專案資料夾；LAT 主控（綁定中，包括 client 已關閉、回報都已封存而不在主控名冊上的；或已停用 LAT 但還有未封存回報）旁標「主控」，點開是主控頁。沒有分頁名稱時用 HCOM 名稱，沒接 HCOM 的只顯示分頁名稱（沒有時用終端機標題）。Agent 頁面的標題是名稱，後面以小字接著「· 分頁名稱」。
- **狀態從哪裡來**：有接 HCOM 的 Agent 顯示 HCOM 回報的狀態，沒接的顯示 Herdr 回報的狀態，因為 Herdr 對接了 HCOM 的 client 回報的狀態有時不準。
- **HCOM 連線無法確認**：讀不到 hcom 的 Agent 清單時，看板沿用上次讀到的結果，原本有接或沒接的照舊顯示。看板剛啟動還沒讀到過，或讀不到期間才出現的 Agent，會標「HCOM 連線無法確認」，名稱與狀態暫用 Herdr 的；之後讀到清單就恢復正常。
- **讀不到 Herdr 的清單時**：會跳出錯誤通知說明原因，畫面沿用上一次讀到的清單。
- **什麼時候更新**：只要有頁面開著，看板預設每 2 秒（閒置與工作中相同）單獨讀一次 HCOM 與 Herdr 的 Agent 清單，狀態有變才推到畫面，所以 Agent 的狀態（工作中、閒置）、Herdr 分頁清單、Agent 卡片與停止鈕通常 5 秒內更新；從看板傳話或中斷後約 2 秒內會多讀一次。沒有頁面開著時不讀，一次讀不到或太慢（超過 4 秒就放棄）時沿用上次的結果，不影響其他資料。Agent 開啟、關閉等其他變化與其他資料仍照整批重讀（保底預設最慢 60 秒），按重新整理會立即整批重讀。
- **點進 Agent**：版面與主控資訊頁相同：上方一行是狀態、名稱、專案資料夾與 HCOM 連線，下面是和主控一樣的用量小字；專案路徑、Herdr 位置（例如「LAT（工作區#1）・2（分頁#2）」）、狀態來源與 Session ID 收在「詳細資料」裡，開合與主控資訊頁共用同一個設定。再下面是對話紀錄，顯示方式與主控相同：最新的在最上面，往下捲到底載入更早的內容，頁面開著時自動接上新內容。剛開的 session 還沒寫下紀錄時只顯示「還沒有對話」，寫下後自動出現；其他讀不到的情況跳出通知說明原因。
- **點進主控**：標「主控」的 Agent 點開後仍留在 Herdr 分頁，顯示的是主控資訊頁的全部內容：狀態與目前階段、詳細資料、用量、每個待答題目的提示列，以及對話紀錄、回報、送出紀錄分頁；另外多了「關閉 Agent」與「操作紀錄」分頁，分頁順序是對話紀錄、回報、送出紀錄、操作紀錄。對話紀錄裡，DECIDE 與 HELP 題目在提出它的訊息處顯示題目卡，可以直接作答；DONE 回報顯示回報卡，可以標已讀或標未讀；NO REPLY 照舊是一般文字。作答與已讀狀態和待辦分頁是同一份，在哪一邊做另一邊都會跟著變。點待答題目的提示列或回報分頁裡的一則，會切到對話紀錄並捲到那張卡片，不會離開 Herdr 分頁；和待辦一樣，點開未讀的回報就會標為已讀。指令列的模型與思考強度用主控那一套（與主控資訊頁相同）。模型切換未完成、已不在 Herdr 裡的主控，照下面「切換未完成」的方式顯示。
- **還不能點開的 Agent**：Herdr 還沒回報 session ID 的 Agent 照樣列出，但不能點開，清單上會註明原因；等 Herdr 回報後就能開啟。
- **傳話**：開著 Agent 頁面時，畫面下方的指令列就是傳給這個 Agent 的輸入框（以 `@名稱` 開頭的仍傳給那個主控；每個 Agent 的草稿分開保存）。打字送出後，文字會打進它的輸入框並送出，效果跟你在終端機親手打字一樣，Agent 會當成是你本人說的話。失敗時跳出通知說明原因，文字留在輸入框，看板不會自動重送。沒接 HCOM 的 Agent 正停在需要核准的確認畫面時，Herdr 會拒收，通知裡是 Herdr 給的原因。HCOM 連線無法確認時指令列停用並說明原因，讀到 hcom 清單後恢復。開著主控頁時，指令列和主控資訊頁完全相同：執行中的主控把文字打進它的輸入框，閒置或已關閉的就喚醒它（送出鈕變成「喚醒」，也有喚醒選項），都記在它的送出紀錄裡；草稿是所有主控共用的那一份，所以在這裡打到一半、換到待辦分頁的主控資訊頁還在。看板升級前在 Herdr 分頁打給主控、還沒送出的草稿，第一次在這裡打開該主控時會移進共用草稿：共用草稿是空的就直接帶入，兩邊都有字就接在後面、中間空一行；移過一次就不再移，也不會自動送出。
- **中斷**：一般 Agent 正在工作時，指令列送出鈕左邊會多一顆紅色的停止鈕，有沒有打字都一樣，按停止鈕不會清掉打好的文字；按一次就直接對它按一次 Esc，沒有確認框，送出還沒有結果前停止鈕停用，等同在終端機按 Esc；有沒有接 HCOM 都可以，HCOM 連線無法確認時也可以。開著主控頁時照主控的規則（見[中斷主控這一回合](#中斷主控這一回合)），記在它的送出紀錄裡。
- **關閉**：按「關閉 Agent」，確認後看板關掉這個 Agent 和它的 Herdr 分頁。確認畫面會寫明關閉後能不能接回：LAT 主控可以從主控資訊頁喚醒；有接 HCOM 的其他 Agent 有對話紀錄的話，7 天內可以從清單底部的「已關閉」接回；沒接 HCOM 的看板沒辦法把那段對話接回來，只能你自己在終端機操作。關閉成功時跳出通知，Agent 隨即從清單消失，操作紀錄也不再提供；開著的頁面在它列入「已關閉」後換成已關閉 Agent 的頁面；失敗或結果不明時通知說明原因，請到 Herdr 查看。看板不會關閉它自己所在的分頁；HCOM 連線無法確認時關閉按鈕停用。
- **暫停通訊**：有接 HCOM 的 Agent（含主控）在「關閉 Agent」旁有「暫停通訊」，再旁邊是說明圖示：點一下（手機輕觸）列出暫停的重點，再點一次或點別處收起。按下「暫停通訊」就執行、不再確認，處理中按鈕顯示「處理中…」；看板讓它離開 HCOM，但視窗與對話都保留，不是關閉；暫停沒成功時通知寫明原因，看板讀不到 HCOM 清單而無法確認時標「HCOM 連線無法確認」，讀到後自動判斷。暫停中它標「暫停通訊」，按鈕變成「恢復通訊」；這段期間其他 Agent 傳給它的訊息會直接傳送失敗、不會排隊等它回來，LAT 監控也不會往它的輸入框打字。你在看板傳的話照常送進它的輸入框，不會因此自動恢復。按「恢復通訊」也是按下就執行，看板在它的輸入框打入接回指令，它會因此跑一個很短的回合；用原本的名稱接回後才算成功。它正在工作或停在確認畫面時不能恢復，要等它停下再按；恢復失敗時通知寫明原因，暫停狀態保留，可以再按一次。看板自己所在的分頁不能暫停；HCOM 連線無法確認時兩個按鈕都不顯示；暫停中不能切換模型。
- **已關閉**：清單底部摺疊的「已關閉 N」列出 7 天內關掉、有對話紀錄可以接回的 Agent，展開後依停止時間分今天、昨天、近 7 天。點一列就在右側（手機是新的一頁）打開它的頁面，網址與返回和一般 Agent 頁相同：資訊卡寫「已關閉」、分頁名稱與 HCOM 名稱、資料夾、原工作區與停止時間；資訊卡下方是「接回」，下面是它關閉前的對話紀錄，可以往前翻頁。一般 Agent 按「接回」就在原工作區開新分頁接回同一段對話；主控按「接回」先展開喚醒選項（模型與思考強度、開新一輪 LAT、第一則訊息，前一次接回卡住時另有「放棄前一次接回」），再按「喚醒接回」。接回中與失敗原因顯示在按鈕上方，清單那一列也會顯示；接回成功、它出現在 Herdr 後，頁面自動換成一般 Agent 頁（主控則是主控頁）。開著已關閉 Agent 的頁面時，指令列停用並說明「已關閉，先接回才能傳訊息」。
- **切換模型**：在指令列送出鈕旁的模型與思考強度，和主控一樣顯示它最近一回合的設定（還沒做完第一回合時顯示「模型／強度」）。只有接 HCOM 的 Agent 可以切換，選項與切換主控相同；沒接 HCOM 或 HCOM 連線無法確認時停用，滑鼠停留可看原因。選好後按 ✓，確認後看板停止它，再以新設定在新分頁接回同一段對話，原分頁會關掉。Agent 還在工作時不能切換，要等它這一回合做完。還沒有對話（開好後一則訊息都還沒送）的 Agent 沒有可接回的內容，看板改成以新設定重新啟動它：同樣的資料夾、工作區與啟動參數，新分頁沿用原分頁的名稱與位置，HCOM 名稱會換新（原分頁名稱若就是舊 HCOM 名稱，新分頁也沿用它）。接回或重新啟動後，要看到它真的在 Herdr 分頁裡執行才算切換完成；一啟動就結束、或一直沒出現時，切換會標為失敗並寫明原因，Agent 留在清單上標「切換未完成」，可以繼續切換或放棄。當初以 `--model`、`-m` 或 `--oss` 指定模型啟動的 Codex 只能改思考強度，模型欄停用並說明原因；從看板新建時選的模型不受此限。
- **切換未完成**：切換做到一半失敗時（例如已停止但接回失敗），這個 Agent 會留在清單上並標「切換未完成」，即使已不在 Herdr 裡、看板重新啟動也一樣。按指令列模型旁的 ⚠ 可以「繼續切換」或「放棄切換」，兩者都先確認一次；在處理完之前不能傳話、中斷或關閉。從主控資訊頁切換到一半的主控也一樣列在這裡。繼續切換會先查證它停到哪裡，再停止或接回，不會重複接回。放棄切換會結束這整次切換，看板之後不會再停止或接回它，放棄本身也不執行任何指令；它若還在 Herdr 裡就照常列出，已不在就從清單消失。看板正在停止或接回它時，要等那個步驟做完才會放棄。
- **操作紀錄**：Agent 頁面的「操作紀錄」分頁列出從看板對它做過的傳話、中斷、沒關成的關閉、切換模型（含放棄的），以及在它的卡片上調整分頁順序與改分頁名稱，成功或失敗都記，所有登入的裝置看到的相同。Agent 從 Herdr 清單消失後，頁面與紀錄就不再提供（切換未完成的除外）。
- **調整分頁順序**：按住卡片最右邊的把手（六個點）拖到同一個工作區的另一張卡片上放開，Herdr 裡的分頁順序就跟著改；拖曳中會在卡片上方或下方畫一條線，標出會放在哪裡。往上拖會放在那張卡片的分頁前面，往下拖放在它後面；看板不顯示的一般終端機分頁也照樣算在 Herdr 的順序裡。只有按住把手才會拖曳，點卡片其他地方照舊開啟 Agent；手機上用手指按住把手拖曳。拖到別的工作區時卡片變淡並提示「不能拖到別的工作區」，放開後回到原位，什麼都不會改。拖到同一個分頁的另一張卡片上也不會動。工作區的卡片多到一個畫面放不下時，把卡片拖到清單的上緣或下緣（約 48 像素內），清單會自動往那個方向捲，越靠近邊緣捲得越快；離開邊緣、放開或捲到頭就停，畫出的位置線與放開後的結果仍然一致，手機上則捲整頁。排序失敗時跳出通知說明原因，清單照 Herdr 實際的順序顯示。
- **改分頁名稱**：在卡片上按右鍵（手機上長按約半秒）開選單，選「改分頁名稱」，卡片標題變成填好目前名稱的輸入框。按 Enter 儲存，按 Esc 或點別的地方取消；名稱空白不會送出。成功後清單顯示新名稱，失敗時跳出通知說明原因，名稱維持原樣。
- **排序與改名要留意**：作用在整個 Herdr 的分頁；你在 Herdr 把某個分頁切成多個窗格、裡面有好幾個 Agent 時，會一起移動或改名。看板自己所在的分頁也可以排序與改名，看板不會因此關掉。看板不提供分割窗格、搬到新分頁、搬到別的工作區或關閉整個分頁。
- **開新 Agent**：按工作區標題右邊的「＋」，右側（手機是新的一頁）出現「在 <工作區> 開新 Agent」表單。「Herdr 工作區」選單預設「當前工作區」，就是按下「＋」的那個；也可以改選「自動」、別的工作區或「新建工作區…」，選法與失敗處理和新建主控相同，表單標題跟著寫出要開的工作區。表單和新建主控相同：資料夾（預設是這個工作區裡 Agent 最常用的資料夾，沒有 Agent 時用最近用過的資料夾；點進還沒改過的輸入框時，這個工作區 Agent 在用的資料夾排在最前面，再補上最近的專案，共 5 個）、第一則訊息、設定列（client、模型、思考強度、分頁名稱），分頁名稱與第一則訊息都可以留空。和新建主控不同的地方：不送 LAT 啟動指令、不需要 Git 專案（看板不會 git init）；資料夾不存在時同樣在家目錄底下建立，但只建資料夾、不 git init。按「開新 Agent」後看板經 HCOM 在所選的工作區開一個新分頁（Claude 一樣略過權限確認），所以開好後就能在這裡看即時狀態、傳話與切換模型。下方「最近開新的 Agent」顯示進度：「啟動中」→「已出現在 Herdr」；Agent 出現在 Herdr 後，有填分頁名稱就改成那個名稱，再把分頁移到它所在工作區的最前面，清單上的新卡片也就在那一組最上面；紀錄寫出實際開在哪個工作區，新建的標「（新建）」。等了 3 分鐘還沒出現時顯示逾時與原因；開不成時表單內容保留著，可以改了再送。改名或移到最前面失敗時 Agent 仍然開好了，紀錄會寫明是哪一步失敗。同一時間只跑一個開新（與新建主控共用），後送的會等前一個出現在 Herdr 或逾時後才開始。每次開新都會留下紀錄，所有登入的裝置看到的相同。
- **留意**：直接對 LAT 派出的 Agent 傳話、中斷或關閉，可能打亂主控的安排，主控不會知道你做了什麼。

## 在看板回答 Agent 的提問

一般 Claude Agent 用選單問你問題（AskUserQuestion）時，題目會出現在看板上它自己的頁面，你在看板點選作答，答案直接填回去，它接著做，不必回到終端機。Claude 與 Codex 跳出權限確認時（包括你直接召喚、沒接 LAT 的 Codex，以及 Codex 執行 MCP 工具前的核准），看板同樣顯示一張權限確認卡讓你「允許」或「拒絕」，見下面「權限確認」。

- **在哪裡作答**：「Herdr」分頁裡這個 Agent 那一筆的狀態改成「等你回答」；點開它的頁面，題目卡在對話紀錄裡它提問的時間點（剛問的就在最上面、最新的位置），之後的訊息排在它上面，卡片不會一直停在最上面；對話紀錄還在讀取時先顯示在最上面。題目卡和待決題卡片一樣：單選題點一個選項，複選題可以勾多個，也可以選「其他」自己打字；沒有備註欄。一次問好幾題時全部一起顯示，每一題都答了才能送出。卡片上顯示還剩多久。
- **送出後**：Agent 收到答案接著做，卡片變成唯讀並標「已填回」，你的選擇以 ✓ 標在選項上。複選題的答案是各選項以逗號連接，自填文字照你打的送出。每次作答都記在它的「操作紀錄」，種類是「看板提問」。
- **兩台裝置同時作答**：只有先送到的算數；另一台跳出通知，卡片標「已有人作答」，那份答案不會送出。
- **等多久**：Agent 問完原地等你最多 10 分鐘，等待期間它的終端機顯示「正在等看板作答，按 Esc 可中斷改在終端機回答」。時間到還沒作答時，它先結束這一回合（終端機會寫明你會從看板回答、答案會以訊息傳給它），不會自己猜答案。
- **逾時之後再作答**：卡片仍留著，標「已逾時，作答會當訊息傳給它」，照樣可以作答。送出時看板重讀 Herdr 的清單：清單上有它，答案就當成你打的一則訊息打進它的輸入框（和其他傳話排同一個隊伍），訊息開頭附原本的題目，說明這是對先前逾時題目的回答，卡片標「已傳話」，操作紀錄記下這則訊息。兩台裝置同時作答時同樣只有一則送出，另一台標「已有人作答」。
- **Agent 已經不在時**：Herdr 的清單讀得到、但上面已經沒有它（就算 hcom 的清單還有它），卡片標「Agent 已不在，無法送出」，答案不會送到任何地方。只是暫時讀不到 Herdr 的清單時，通知寫「無法確認這個 Agent 仍在 Herdr 的清單上」，卡片維持已逾時、你選的內容還在，之後再送一次就好。
- **看板在傳話途中停掉**：重啟後那張卡片標「結果不明，請看對話紀錄」，看板不會自己重送，以免它收到兩個答案。卡片上有「再送一次」按鈕，旁邊註明「可能已送過，請先看對話紀錄」：先看它的對話紀錄，確定沒收到再按，會用同樣的方式把原本的答案再送一次，並記在操作紀錄；兩台裝置同時按時只會送出一則，另一台標「已有人作答」。
- **在終端機中斷**：等待中你在終端機按 Esc（或 Agent 被關掉）時，看板下一次更新就把卡片標「已在終端機中斷」（Claude 的權限確認例外，見下面「權限確認」），不能再送。
- **保留多久**：已填回、已傳話、結果不明、已中斷、Agent 已不在的提問，結束滿 7 天後連同題目卡從看板與共用目錄刪除；已逾時但還沒作答的會留著。操作紀錄裡的那筆照原本的 30 天保留。
- **看板沒開的時候**：看板沒在執行（約 90 秒沒有心跳）時，Agent 照舊在終端機跳出原本的選單，不會等。不在 Herdr 裡執行的 Agent 看板上沒有它的頁面，Claude 的 Task 子 Agent 也不攔，都照舊在終端機問。看板在等待途中重新啟動，題目卡仍在，截止前照樣可以作答。
- **LAT 主控用選單問你**：會被擋下，主控看到一則英文提醒，要它改用待答面板（`question upsert`）寫題並以 DECIDE 結尾；看板上不出現題目卡，待辦也不會多一筆看板提問，你照舊在待辦裡回答它重問的題目。hook 用輔助工具查面板的綁定登記，session 有綁定就是主控；查不到、輔助工具壞了或看板沒在執行時，當一般 Agent 處理。
- **你要留意**：等待期間 Claude 的選單提問與 Codex 的權限確認在終端機不會出現原本的畫面，你人在終端機時要按 Esc 中斷這一回合，才能在終端機自己處理。Claude 的權限確認則兩邊同時看得到，見下面「權限確認」。
- **安裝 hook**：要先把看板附的 hook 裝進 Claude 與 Codex 的全域設定。先預覽，確認無誤再安裝；安裝前會備份設定檔，保留你原本的其他 hook，重跑不會重複，移除只拿掉這幾筆：

  ```bash
  uv run --no-project python board/hooks/board-ask.py install --client claude --preview
  uv run --no-project python board/hooks/board-ask.py install --client claude
  uv run --no-project python board/hooks/board-ask.py uninstall --client claude
  uv run --no-project python board/hooks/board-ask.py install --client codex --preview
  uv run --no-project python board/hooks/board-ask.py install --client codex
  uv run --no-project python board/hooks/board-ask.py uninstall --client codex
  ```

  Claude 裝的是選單提問與權限確認兩筆（`settings.json`）；Codex 裝的是權限確認、回合結束與工具執行完三筆（`hooks.json`）。要裝到別的設定檔時，Claude 加 `--claude-settings <路徑>`，Codex 加 `--codex-home <資料夾>`。已在執行的 Claude 要重開才生效。Codex 裝好後，每個 Codex 都要在 `/hooks` 信任這個 hook 一次，已在執行的 Codex 要重開才生效；還沒信任或還沒重開的 Codex 照舊在終端機問。

### 權限確認

- **在哪裡作答**：一般 Agent 的權限確認卡在它自己的頁面，和題目卡在同一個位置；LAT 主控的權限確認卡在主控資訊頁，以及「Herdr」分頁裡主控的那一頁。卡片寫出工具名稱與內容：指令全文、要改的檔案與內容，或 MCP 工具的名稱與參數，以等寬字顯示，太長時先摺起來，按「展開全部」看完整內容。下面是選填的拒絕理由與「允許」「拒絕」兩個按鈕。
- **送出後**：按「允許」它就執行；按「拒絕」它不執行，你寫的理由會傳給它。每次作答都記在它的操作紀錄。
- **Claude：終端機與看板兩邊都能答**：Claude 等你在看板作答時，終端機同時也顯示它原本的確認畫面，哪一邊先答就算哪一邊。看板照 Claude 實際採用的結果標示：
  - 你在終端機先答了：選允許時卡片標「已在終端機回答：允許」；選 No 或按 Esc 時都標「已在終端機拒絕」（Claude 對這兩種的紀錄完全相同，看板分不出來，兩者都算拒絕）。之後都不能再從看板送，也不會傳訊息給它。
  - 你在看板送出後，卡片先標「已送出」，等看板從它的對話紀錄確認它採用了哪個答案：和你在看板的選擇一樣就標「已填回」；你其實已經在終端機選了相反的答案時，標「已在終端機回答：允許」或「已在終端機拒絕」，並註明「你在看板的選擇沒有被採用」，操作紀錄也照實記下。
  - 送出後 1 分鐘內看不出它採用了哪個答案（例如對話紀錄裡有兩筆一模一樣的請求分不出來）時，標「結果不明，請看對話紀錄」。
- **Claude 逾時**：10 分鐘沒作答時，Claude 先結束這一回合，卡片標「已逾時，作答會當訊息傳給它」。之後按「允許」，看板傳一則訊息請它重試（「使用者允許你執行剛才被擋下的操作，請重試」，附上工具與內容）；按「拒絕」則傳一則拒絕的訊息，附你寫的理由。送不送得到的規則和逾時後的選單提問相同：Herdr 的清單上已經沒有它（主控也一樣，例如已關閉）時標「Agent 已不在，無法送出」，看板不會為了送這則訊息喚醒或接回它。
- **Codex 逾時**：10 分鐘沒作答時，Codex 不會結束回合，而是把終端機原本的確認畫面交還給你；卡片標「已交回終端機」，之後不能再從看板回答，看板也不傳訊息、不替你按 Esc。
- **Codex 自己先停下這一回合**：Codex 有時在等你核准的期間先結束這一回合。這時卡片照常可以按，上方註明「它已經停下這一回合，按允許後指令仍會執行」。按「允許」後指令會執行，卡片標「已允許，等它執行・還沒看到它執行」，這時還不傳訊息，這一筆也留在待辦；看板看到它真的執行了（失敗也算），才傳一則訊息告訴它「你剛才請求的〈工具與內容〉已在看板允許並已執行，請檢查結果後接著做」，卡片標「已允許並已執行，已通知」。允許後 7 天內都沒看到它執行時不傳訊息，卡片改標「已允許，7 天內沒看到它執行，沒有通知它」；看到的執行分不出是不是這一筆時也不傳，標「已允許，看板無法確認是哪一次執行，沒有通知它」。按「拒絕」和平常的拒絕相同，不另外傳訊息。
- **保留多久**：已交回終端機、已在終端機回答、已在終端機拒絕、結果不明、已允許並已通知、以及上面兩種沒有通知它的權限確認，算已結束，結束滿 7 天後從看板與共用目錄刪除；「已允許，等它執行」的會留著，最長到允許滿 7 天。
- **不會出現權限確認的情況**：用略過權限模式執行的 Agent 本來就不問權限，看板上也不會出現權限確認卡。Codex 規劃模式裡的提問（`request_user_input`）不處理，照舊只在終端機出現。

## 額度分頁

中間欄的「額度」分頁列出 Claude 與 Codex 的每一個帳號和它們的額度，只能查看：看板不切換帳號、不要求更新額度，也不兌換 reset。左欄（展開或收合）不放任何額度數字，手機上也用這個分頁看。

- **資料從哪來**：Claude 讀 claude-swap 的 `cswap list --json --cached-only`，Codex 直接讀 codex-multi-auth 的帳號檔與額度快取（位置見 [board/README.md](../board/README.md)）。這兩種讀法都不連網、不刷新登入，所以數字是 `cswap auto` 或 Codex 上次記下的值。看板伺服器每 30 秒讀一次，所有已登入的瀏覽器共用；憑證與檔案原文不會送到瀏覽器。
- **每組的標題**：寫使用中帳號的資料是幾分鐘前更新的（沒有使用中帳號時看最新的一個）；超過 Claude 3 分鐘、Codex 15 分鐘時間文字就變黃（只寫「N 分鐘前更新」，不另加字）。其他帳號的卡片各自寫自己的更新時間，過舊同樣變黃。
- **每張卡片**：使用中的帳號排最前面並加框。第一行是 email 與方案：使用中的 Claude 帳號（claude-swap 切換到它時記下的就是目前方案）與 Codex 帳號（方案隨每次用量一起記下，和卡片上的更新時間一樣新）直接顯示；其他 Claude 帳號只有上次使用時記錄的方案，顯示較淡，滑鼠停留說明「上次使用時記錄（N 天前）」；沒有紀錄的不顯示方案。下面每個時段一行（5 小時、7 天，以及 Fable 等模型專屬時段，有才顯示）：剩餘百分比（例如「89%」，滿額 100%、用完 0%）與重置時間，沒有長條；20% 以下黃、5% 以下紅。
- **沒有資料時**：帳號沒有用量紀錄寫「沒有紀錄」，不顯示 0%；重置時間已過的舊數字變淡並註明「等待新資料」。讀不到資料（找不到帳號檔或額度快取、版本不符、claude-swap 出錯，或安裝的 claude-swap 還沒有唯讀額度指令）時，那一組寫出原因（只寫看板自己的說明，不轉貼外部指令的輸出），另一組和看板其他部分照常。

## pd 待核准

有安裝 pd（把 Bitwarden 密碼交給 Agent 用的工具）時，待辦上方列出等你核准的 pd 請求，每 5 秒更新：要的項目與欄位、要執行的指令、工作目錄、呼叫者（對方自稱，未驗證）與剩餘時間（30 秒內變紅；舊版 pd 不提供剩餘時間，改顯示已等待多久）。

- **核准**：在新分頁開啟 pd 的 passkey 核准頁裡的這一筆請求，在那裡用裝置本身的解鎖驗證（通常是指紋或臉部辨識）核准。看板本身不能核准，也不會要你輸入 pd 的確認碼。
- **拒絕**：按一下就拒絕，不需要確認碼；所有開著的看板跟著拿掉這一筆。請求已經被核准、拒絕或逾時時，看板會說它已不在清單上。
- **沒有請求或用不到 pd 時**：只留一行小字，例如「pd 目前沒有待核准的請求」、「pd 待核准：這台主機沒有安裝 pd」或「pd 待核准：連不上 pd 服務」；看板其他部分照常。
- 看板與瀏覽器之間的連線沒有加密（見「安全」），只應在內網或私人網路使用；核准頁本身另走 pd 自己的 HTTPS 網址。

## 語音輸入

隱藏功能，畫面上沒有開關：連按「待辦」分頁 5 次（每兩下間隔 1.5 秒內）打開，記在這個瀏覽器；再連按 5 次關閉。打開後指令列與新建主控的第一句話旁會出現麥克風：按一下開始錄音、再按一下停止。

- **需要設定**：看板主機要設定語音辨識服務，沒設定時按麥克風只會提示未設定；約 3 分鐘的錄音超過預設的請求大小上限，要把 `BODY_SIZE_LIMIT` 設成 `2M`（變數見 [board/README.md](../board/README.md) 的設定表）。
- **放入的文字**：辨識結果只把簡體字轉成台灣正體字，不換用語（例如「软件」變成「軟件」、「视频」變成「視頻」，不會改成「軟體」「影片」）；20 個字以內直接放到游標處，更長的先交給 Codex 修錯字、去掉口誤與贅字再放入（會用到 Codex 額度）。Codex 失敗、看不懂或逾時就放轉換後的原文，並以通知說明原因。
- **放入方式**：只取代選取的文字，其餘內容保留。
- **錄音限制**：最長約 3 分鐘，錄音時按鈕上顯示剩餘時間，到時自動停止並送出辨識。麥克風只在 HTTPS 或 localhost 的網址可用；權限被拒時以通知說明。

## 附件

指令列左邊的迴紋針可以附加圖片、影片或任何檔案，也可以直接貼上截圖或把檔案拖進輸入框；手機按迴紋針可以選相簿或開相機。

- **上傳**：選好就開始上傳，輸入框上方顯示預覽（圖片縮圖、影片可直接播放、其他檔案顯示檔名與大小）和上傳進度，送出前可以移除。還在上傳或有上傳失敗的附件時不能送出。單一檔案最大 250MB。
- **送出**：訊息最後會自動接上每個附件在看板主機上的完整路徑，主控或 Agent 自己去開。只有附件、沒有打字也可以送。Claude 與 Codex 看得懂圖片（Claude 也能讀 PDF），影片要它們自己先擷取畫面。
- **事後查看**：對話紀錄裡你的訊息與送出紀錄，附件直接顯示成圖片縮圖、可播放的影片或檔名：
  - 點圖片縮圖，或點文字檔（.txt、.md、.json、.py、.ts、.js、.svelte、.css、.html、.yaml、.toml、.csv、.log 等常見文字副檔名），會在面板上開一個視窗：圖片一打開就整張顯示在視窗內，觸控裝置可用雙指放大、放大後用手指拖曳查看細節；Markdown 照對話紀錄的樣式排版；其他文字用等寬字原樣顯示，保留換行與縮排。檔案裡的 HTML 與程式碼只當文字顯示，不會執行。文字檔只讀開頭 200KB，更長時視窗裡會註明「只顯示開頭 200KB」。
  - 視窗標題列有檔名、「下載」與「關閉」。檔名是上傳時的原名（不含看板加的上傳編號），只佔一行，太長時省略中間、保留開頭與副檔名；滑鼠停留可看到完整路徑。下載的檔案也用原名。按 Esc、點視窗外或按「關閉」都能關掉，回到原本的位置。視窗開著時背後的看板不會跟著捲動。手機上視窗佔滿畫面。
  - PDF 在新分頁用瀏覽器內建的檢視器開啟；Word、Excel、壓縮檔等其他檔案點了直接下載。
- **存放位置**：預設在 `/tmp/lat-board-uploads`，只有看板的帳號能讀；看板不會自己刪除，主機重開機或系統清理 `/tmp` 後，紀錄裡會改寫「檔案已不在」。位置與大小上限的變數見 [board/README.md](../board/README.md) 的設定表。
- 附件跟著輸入框裡的草稿走：所有主控共用同一份草稿與附件，每個 Agent 各有自己的；重新整理頁面後尚未送出的附件會消失。新建主控的第一句話不能附加檔案。

## 版面與外觀

- **名冊與待辦**：電腦版面（寬度超過 760px）的名冊從視窗頂端延伸到底，指令列只在待辦與內容欄下方。名冊與待辦的右邊界都可以拖曳調整寬度（連按兩下還原），名冊 170 到 440px、待辦 260 到 720px；視窗較窄時另外不超過視窗寬度的 30% 與 42%。名冊頂端第一行最左邊的按鈕把名冊收成窄直條，收合方式見[名冊收合](#名冊收合)。直條上每個主控一個狀態標記與待決題數，各組之間有短線，新建、重新整理與設定按鈕固定在直條底部；點標記開啟該主控且維持收起，滑鼠停留或手機長按標記會顯示專案、主控名稱、狀態與目前階段。
- **設定按鈕**（電腦在名冊頂端，手機在頂端列）：切換深色與淺色主題，調整整體大小（80% 到 150%，文字與間距一起縮放，可還原預設）與最小字體（10 到 24px，比它小的字一律放大到這個大小，預設不限），以及用量列的詳細或精簡樣式、對話翻譯的自動翻譯或手動切換。淺色主題是白底黑字、不用半透明，狀態靠形狀分辨：▲ 等你、● 進行中、■ 已交付、○ 閒置、◇ 已關閉；Herdr 分頁上狀態不明的 Agent 是 □。
- **返回與重新整理**：開著的畫面寫在網址裡，每開一個畫面記一筆瀏覽器歷史紀錄：手機頂端列的「←」與系統返回（電腦是瀏覽器的上一頁）都回到上一個畫面，退回待辦列表時回到離開前的捲動位置，再按一次才離開看板。重新整理後開回同一個畫面，返回路徑照舊；找不到那一則或那個主控時顯示「已不存在」（待辦沒有、已處理也讀不出來時，改為提示重新整理再試）。
- **從別的網頁回到看板**：從網址列或外部連結整頁載入看板，再按瀏覽器的「上一頁」回到看板時，頁面會重新載入，捲動位置與展開狀態重設，即時更新照常，指令列草稿仍在。
- **記在各自裝置的設定**：待辦的排序方式、中間欄的分頁（待辦或 Herdr）、名冊收合、兩欄寬度、主題、整體大小、最小字體、資訊頁「詳細資料」的開合、手機指令列的收起與還沒送出的文字，都記在各自裝置的瀏覽器裡；瀏覽器不允許儲存時一切照常運作，只是不記憶。用量列樣式與對話翻譯偏好不在其中，由看板統一保存、所有裝置共用。

## 資料怎麼更新

看板監看面板綁定登記、各主控的問題檔與回報紀錄目錄，有變動才重讀，正常在 5 秒內推到所有開著的頁面。漏掉變動時由保底重讀補上，最慢 60 秒；畫面上的重新整理按鈕與每次載入頁面都會立即重讀。連線中斷時畫面會提示，並自動重連。

操作結果、讀取錯誤與連線中斷都以浮動通知顯示（電腦在指令列上方，手機在頂端列下方），不插進頁面內容，所以不會推動版面。成功的通知幾秒後自動消失，失敗的要按 × 關掉。持續中的狀況（連線中斷、讀取錯誤、送出紀錄讀寫失敗、作答途中題目被改版）的通知在狀況解除後自動消失，按 × 只是暫時收起。

回報內容、題目說明、選項內容與推薦、對話紀錄以 Markdown 顯示：文字裡的 HTML 一律當成文字顯示，不安全的連結與圖片不顯示，連結在新分頁開啟。時間不顯示年份。

## 自訂樣式

把自己的樣式寫在設定目錄的 `user.css`。設定目錄預設是 `$XDG_CONFIG_HOME/lat/board`，沒設定 `XDG_CONFIG_HOME` 時是 `~/.config/lat/board`；也可用 `LAT_BOARD_CONFIG_DIR` 直接指定。它在內建樣式之後載入，所有已登入裝置重新載入頁面就會套用；刪掉檔案就恢復預設，不需要重啟看板。

顏色、圓角與字型都是 CSS 變數，例如：

```css
:root {
	--accent: #ff8a3d;
	--radius: 2px;
}
```

| 變數 | 用途 |
| --- | --- |
| `--bg`、`--surface`、`--line` | 底色、卡片底色、邊框 |
| `--text`、`--muted` | 文字、次要文字 |
| `--accent`、`--warn`、`--ok`、`--danger` | 強調、待決與求助、交付、錯誤 |
| `--status-waiting`、`--status-working`、`--status-delivered`、`--status-ended` | 狀態標記的顏色（閒置與已關閉共用 `--status-ended`） |
| `--selected-bg`、`--selected-text` | 選中的控制項 |
| `--radius`、`--radius-pill` | 圓角 |
| `--sans`、`--mono` | 字型，例如 `--sans: 'Noto Sans TC', sans-serif;` |

變數寫在 `:root` 對深色與淺色主題都生效；只想改其中一個主題時，用 `:root[data-theme='light']` 或 `:root[data-theme='dark']`。內建淺色主題的顏色在白底上的對比都不低於 7:1；自己覆蓋的顏色不會被檢查。

## 更新

1. 在專案目錄 `git pull`。
2. 重新安裝技能（指令見 [README](../README.md#本地開發) 的安裝腳本），看板才會用到新版的面板輔助工具。
3. 在 `board` 目錄執行 `bun install`。
4. 部署：有跑背景服務時執行 `bash scripts/deploy.sh`（在 `board` 目錄），它只用已提交的 `HEAD` 建置，不帶工作資料夾裡未提交的修改：在臨時的 git worktree 建置到 `build-new`，換成 `build`（舊版暫存為 `build-prev`），重啟 `lat-board`，等 `http://127.0.0.1:7100/login` 回 200 後丟掉舊版與臨時資料夾。建置失敗時正在用的 `build` 不動；換上後重啟失敗或登入頁一直不回 200，會把舊版放回去、重啟並再確認登入頁，結束碼為 1。服務名稱、連接埠與等待秒數可用環境變數改（見 [board/README.md](../board/README.md#部署)）。沒有背景服務時，在 `board` 目錄執行 `bun run build`。

技能更新後，正在跑的主控要從它的下一個回合才開始留下回報紀錄，更新前的訊息不會補上。

## 疑難排解

- **新建或喚醒後 Herdr 沒有開新分頁，最後顯示 hcom 逾時或「仍在啟動」**：看板呼叫 hcom 時會要求它在 Herdr 開新分頁（`--no-run-here`），否則 hcom 會把主控跑在看板自己的程式裡，看不到也不能用。看板是舊版時請更新；hcom 太舊、不認得這個選項時（實測 0.7.29 可用），更新 hcom。之後到 Herdr 查看有沒有留下沒用的分頁，有就手動關掉。

## 安全

看板沒有內建加密連線（沒有 HTTPS），密碼以明文在網路上傳送，同一個網路上能監看流量的人看得到密碼與登入後的資料。密碼只擋得住不知道密碼的人。回報全文可能含內網位址與本機路徑，看板又能對主控下指示，所以只應放在家裡或公司內網、私人網路；pd 待核准的請求內容（項目、指令、工作目錄）也走這條不加密的連線。需要加密時，自己在前面加反向代理。
