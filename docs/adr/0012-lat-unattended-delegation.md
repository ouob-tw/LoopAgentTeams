# LAT 無人模式：參謀在使用者事先給的授權內代決，代決永遠不算真人答覆

使用者不在電腦前時，一張明確的小票也會卡在「等你確認」；統計約七成待決題屬於規則明定只有真人能答的類別（需求見 ouob-tw/LoopAgentTeams-work#564，使用者決定見 `.lat/decisions/GEBU-FULL-1`～`GEBU-FULL-8`）。我們因此在 ADR 0002「參謀只能引用既有真人授權」與 ADR 0011 預先授權之上，新增第四種授權來源：使用者為一輪工作事先給的無人授權，並讓兩位參謀在這份授權內從「顧問」擴權為「代決者」。

## 決定

1. **無人授權是程式查得到的紀錄，屬於某個 session 的某一輪，由真人動作產生。** 每一版寫明目標、做完條件、可代決範圍、停止條件、來源與真人動作的證據；看板表單、聊天確認題（面板答題紀錄）與看板設定預設各有可核對的證據。關掉、一輪結束（交付、取消、換班）、額度用完或時間上限到期即結束；新一輪與接手主控不繼承，依當下的主控／專案／全域三層設定重新判斷。
   - 為什麼：使用者要「給一個明確的工作就去睡」，又不要授權悄悄延續到下一輪。綁在一輪上，讓每份代決都能對回某一版授權與它的生效期間。
   - 代價：預設就是無人模式時，目標由主控從使用者第一句話擬出，可能擬錯；以主控頁隨時可「修改」與「關掉」、回顧逐項可推翻來補救。

2. **參謀可代決的範圍固定且窄：只有兩位參謀一致時才成立。** 只限三種：短流程票代確認（拿使用者原話對照驗收條件，沒有多加或漏掉）、在固定清單內選預設並記成「假設」、對看得出結果的選擇做樣品再決定。固定清單只含不改驗收條件與範圍的細節，參謀不能自行擴充；需求討論、Spec 確認、花錢或帳號額度、刪使用者資料、推送 main 或對外發布、大改已確認需求、只有使用者帳號做得到的事、已經問過使用者的題目，一律擱置等使用者。兩位意見不同也擱置。（「擱置」已被下方〈修訂：要問使用者的事照常發題〉取代：這些事改為照常發題問使用者，可代決範圍不變。）
   - 為什麼：沿用 ADR 0011「不讓 Agent 推論什麼算可逆」的界線；擴權的是「誰來確認」，不是「什麼可以不經使用者」。
   - 代價：清單外的小事仍會擱置到隔天，無人模式省下的提問比理論上限少。（已被下方修訂取代：改為發題後等使用者，其他工作照做。）

3. **代決狀態永遠不等於真人答覆。** 代確認、假設、樣品決定與擱置（擱置已不再新寫，見下方修訂）是各自獨立的狀態，引用所依據的授權版本與兩位參謀的結論，不得含真人答覆段落；需要真人答覆的檢查（預先授權寫入、推送與部署、已問過的題目）都不接受代決紀錄。使用者事後推翻或回覆時，才記成真人答覆。
   - 為什麼：紀錄必須分得出哪些是使用者說的、哪些是 AI 替他猜的；否則一次猜錯會被後續流程當成使用者核准而一路放大。
   - 代價：代確認的票只能合併到整合分支，推送與部署仍照預先授權現行結果，隔天可能還要使用者按一次。

4. **授權結束只收回之後的代決權。** 已作成時合法的代決照常有效、可讀、可推翻；檢查依代決作成時間對照那一版的生效期間，不因授權後來結束而擋下後續回合或接手。
   - 為什麼：關掉無人模式是「之後回來問我」，不是「把昨晚做的都作廢」。

## 修訂：要問使用者的事照常發題（2026-11，ouob-tw/LoopAgentTeams-work#660）

取代決定 2 與 3 裡的「擱置」：無人授權有效時，原本要擱置的事改成跟人工模式一樣，以一般待決題問使用者（`DECIDE:`／`HELP:`），回合結束檢查不再因授權攔下提問；主控只停住相依的工作，其他工作照做。工作總表因審查反覆重開或 Spec 審查到上限而擱置一列時，同時對同一件事發題，真人答覆後才解除。無人期間發的題在待決紀錄帶 `- grant:` 行，回顧據此認定它屬哪一輪。不再新寫 `parked` 紀錄；改版前的擱置紀錄照舊可讀、可記答覆、可被等待。

- 為什麼：實際使用後，使用者回報擱置在回顧頁的題目不好讀、也沒有讓他更放心；他要的是跟人工模式一樣的問題卡片，醒來直接回答（`.lat/decisions/UNCARD-1` r3，答覆 A）。
- 不變：參謀可代決的三種範圍、固定清單與代決紀錄格式不變；代決仍永遠不算真人答覆；預先授權（合併、推送、部署）的判斷不變。
- 代價：主控在無人期間可能停在提問等使用者；相依的工作一直等到真人答覆，主控不能自己替使用者回答。

## 修訂：拿掉交付前核對與回顧裡的自動動作（2026-11，ouob-tw/LoopAgentTeams-work#662）

交付前不再派另一家模型核對回顧檔（刪除 `review verify`），回合結束與 deactivate 不再因回顧未核對而攔下；回顧不再收錄依預先授權自動做的合併、推送與部署，交付回報照舊附 `lat-preauth report`。

- 為什麼：回顧檔近六成項目是自動合併紀錄，寫給程式核對、使用者讀不下去；核對步驟讓每次交付多派一個 Agent，卻沒有讓使用者更放心（`.lat/decisions/UNCARD-1` r3）。
- 代價：回顧內容不再有第二家模型背書，正確性回到靠來源紀錄本身與程式重建。

## 刻意不寫進決定的事

- 設定鍵名、授權檔位置與子指令是實作細節，見 LAT 技能的無人模式參考文件。
- 回合結束檢查如何攔下代決、回顧頁的版面，見 ouob-tw/LoopAgentTeams-work#564 與其子票（核對方式已由上方 #662 修訂取代）。
