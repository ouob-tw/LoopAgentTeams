# 事件任務：自動化任務的第二種觸發方式，只經任務提案建立

LAT 主控等很久的工作（例如收 Log）時只能一直開著，佔著名冊與對話容量，也容易被停住監控催促或因額度中斷（Spec ouob-tw/LoopAgentTeams-work#758，共識 v4）。

## 決定

1. **事件任務是自動化任務的另一種觸發方式。** 任務多一個觸發方式：週期（既有排程欄位，舊資料不轉換）或事件（四種事件、期限、次數、接手方式）。沿用既有的每分鐘檢查、執行紀錄與 Agent 任務的執行方式。
   - 為什麼：另做一套排程與紀錄只會重複既有的部分。
   - 代價：事件任務帶著用不到的排程欄位，偵測最慢約一分鐘。

2. **只經任務提案建立，只收 LAT 主控。** 沿用 [ADR 0015](0015-board-task-proposals.md) 的查證與 passkey 核准；「新增任務」不提供，建立後不能修改。
   - 為什麼：接回原主控需要看板查證過的 session 身分；使用者核准的內容要和實際執行的一致。
   - 代價：要改就刪除、重新提案、再核准一次。

3. **看板停機期間不偵測，重新啟動時補判定。** 只依當下還看得到的證據：程序已結束、檔案修改時間已更新、Log 檔裡還在的新內容、時間已到。
   - 為什麼：另跑一支常駐偵測程式要多看管一個服務。
   - 代價：停機時寫入後又被輪替或刪掉的 Log 內容補不回來。

4. **接手中斷不自動重送。** 先寫接手紀錄再接回、傳訊或開 Agent；失敗記「接手失敗」；中斷而沒有這一次的送達證據記「接手結果不明」；兩者都等使用者按重試。
   - 為什麼：重送可能讓主控收到兩次或開出兩個 Agent。
   - 代價：要使用者自己處理。

5. **主控關閉期間用「事件等待」暫停紀錄。** 沿用看板與停住監控共用的暫停紀錄資料夾與格式，多帶原因與任務編號；看板「視窗不見就移除」的清理不處理它，接回成功、任務刪除或暫停中到期才移除，啟動時依任務紀錄補回。主控的 LAT session 保持 active。開新 Agent 的事件任務不寫這筆，主控要先照一般方式結束本輪。
   - 為什麼：停住監控不用改規則，工作總表與待答題原樣保留。
   - 代價：一個主控一次只能等一個接回原主控的事件任務；沒經指令關閉的主控接不回來。
