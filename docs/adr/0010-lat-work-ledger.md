# LAT 工作總表：流程狀態由程式維護，結案必須附可查證據

LAT 的流程進度原本由主控自己記，壓縮或對話一長就記錯、漏記，或把 Agent 自述的「做完了」當真（需求見 ouob-tw/LoopAgentTeams-work#297；使用者決定見 `.lat/decisions/TEVU-REG-7`～`TEVU-REG-9`）。

## 決定

1. **一個主控的一輪任務一份「工作總表」，只有程式能寫。** 路徑寫在 session 紀錄；新一輪新檔，compact／resume 沿用。每次寫入另記只追加的流水帳與整檔雜湊印記，讀取時印記不符就拒絕；格式合法的手改也擋。
   - 為什麼：手寫表格遲早格式亂掉、監控讀不到；雜湊印記讓「程式以外的修改」可被辨識，流水帳讓損壞可重建而不必憑空建表。
2. **結案一律要附程式查得到的證據，查不到就拒絕。** 證據種類只有 commit（Git 可達）、測試閘門紀錄（指紋查得到）、檔案（存在且非空）；沒有免證據的例外。`check` 在交付前重新核對，結案後證據消失也算失敗。
   - 為什麼：這是整個設計唯一能擋住「以為做完」的門；留成警告等於沒擋（使用者明確選擇拒絕，TEVU-REG-8）。
3. **下一步由依賴算、交付前由程式核對，主控只做判斷。** 程式只核對登記與證據存在，不判斷驗收是否通過；驗收仍依 LAT 既有規則。
4. **超時由既有停住監控讀總表檢查，不新增檢查 Agent。** 過自估時間催 Agent；過最晚期限通知主控；主控 10 分鐘未處理通知使用者。送達才去重，失敗重試；送達後存檔前中斷可能多送一次，不承諾整體最多一次。
   - 為什麼：監控是程式，不花額度、不會忘；與 ADR 0001 的催促與升級鏈一致。
5. **總表與任務卡並存。** 總表管狀態、時間、證據；任務卡管資源、現場額度、暫存路徑；兩邊互記位置，不一致以總表為準。
   - 為什麼：任務卡驅動現有監控找 Agent 的方式，一次換掉風險太大。

## 後果

- Agent 多三道登記指令（開工、更新、結案），派工訊息自動帶上。
- 主控宣告 `DONE:` 與 deactivate 都會被程式核對；強制停用須寫原因並留在紀錄。
- 總表檔不自動刪除，由清理指令列給使用者確認。
- 預先授權機制（哪些動作免問使用者）另立 Spec（TEVU-REG-10）。
