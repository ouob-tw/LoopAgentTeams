# 看板只接受清單上的連線，只相信信任代理轉來的位址與協定

看板登入後等於主機上的遠端操作，又要從 https://lat.ouob.net 經反向代理對外（ouob-tw/LoopAgentTeams-work#584）。原本服務綁在所有網卡、誰都能直連；放在代理後面時，輸錯鎖定只認得代理的位址，若改成無條件讀轉送標頭，能直連的人又可以自稱任何位址。

## 決定

1. **連線位址不在允許清單上，在任何路由之前就拒絕；清單沒設定時只有主機自己。** 位址取自連線本身，不受任何標頭或 adapter-node 的 `ADDRESS_HEADER` 影響。
   - 為什麼：內網其他機器若能繞過代理直連，代理上的地區限制與真實位址就都沒有意義；預設只開本機，更新後不會意外對外開放。
   - 代價：從其他機器直連的既有用法，更新後要自己把位址加進清單。

2. **只有連線來自信任代理時，才讀 `X-Forwarded-For` 與 `X-Forwarded-Proto`。** 真實位址照 ouob-ops ADR 0008：由右往左取第一個不是信任代理的位址；任何一項不是 IP 就整串不用，改用連線位址；`X-Real-IP`、`CF-Connecting-IP` 一律不讀。只有信任代理說 `https` 時才當作 HTTPS（cookie 加 `Secure`、回應加 HSTS）。
   - 為什麼：與 ouob-ops 其他服務同一套規則；由右往左只採信任代理自己加上的那一段，瀏覽器自己送的值放在左邊也沒用。
   - 代價：代理位址變了要同步改清單；代理若把訪客送來的值接在後面而不是覆寫，多層時仍要靠信任清單擋。

## 刻意不寫進決定的事

- 地區限制放在代理（NPM），不在看板；見 ouob-tw/LoopAgentTeams-work#584 需求 7。
- 設定名稱與實作位置見 `board/README.md`「連線來源」。
