# LAT 預先授權：程式查得到的分層常設授權，固定條件不能拿掉

主控在已確認 Spec 內可自動推進，但合併、推送、部署、更新主機技能這類動作 Spec 通常沒寫，只能每次問使用者；真的問到使用者的題目約八成是這類授權題（需求見 ouob-tw/LoopAgentTeams-work#310；使用者決定見 `.lat/decisions/FUBE-PA-1`～`FUBE-PA-14`、`FUBE-SPEC310-1`）。我們因此在 ADR 0002「參謀只能引用既有真人授權」的模型上，新增第三種程式化的授權來源：預先授權。

## 決定

1. **預先授權是設定檔加查詢工具，不是規則文字；只算明列的動作。** 動作清單固定（合併、推送、部署測試、部署正式、更新主機技能），不讓 Agent 推論什麼算可逆。修改或縮減已確認驗收、花錢或帳號額度、刪使用者資料或 shred、開新票擴大工作量四類永遠要問，工具不提供對應鍵。
   - 為什麼：使用者偏好用工具取代規則；先前說明檔版本只有參謀讀得到，程式查不到也擋不住。
   - 2026-10-30 補記：修改驗收與開新票的「永遠要問」只限制 `check` 的動作查詢。參謀能否自行定案這兩類，改依使用者在 `[advisor]` 段寫的 `may_settle`／`must_ask` 判斷；使用者認為模型已能處理小範圍的需求調整，想減少提問。花錢或帳號額度、刪使用者資料仍一律要問。
2. **三層由窄到寬：主控 > 專案 > 全域，窄層可放寬也可收緊；主控層只能由本輪真人答覆產生、該輪結束失效。** 全域放使用者設定資料夾，專案放不提交的 `.lat/`。
   - 為什麼：這是使用者原話的層次；「窄層只能收緊」被考慮過，但使用者要能針對單一專案放寬。
   - 2026-10-30 補記（ouob-tw/LoopAgentTeams-work#403）：移除主控層，只留專案 > 全域兩層。本專案 13 份預先授權紀錄裡主控層使用 0 次，而且使用者無法直接編輯、只能透過答題設定；想臨時放寬改為在看板上切換，做完再切回來。`[advisor]` 只取全域層，專案層寫了不生效。
3. **推送、部署、安裝的固定條件由工具強制，設定只能加嚴。** 推送：分支在清單、版本通過整套測試閘門、遠端沒有的提交含他人的票就問。部署與安裝：只從主工作區整合分支最新版、前後 HCOM 通知其他主控、版本通過閘門。
   - 為什麼：這些是過去授權題的主要理由；寫錯設定也不能放掉安全底線。
4. **一律依當下設定重查；已送到使用者面前的題目仍只由真人解除。** 檢查點在題目送出前（面板寫題、未綁定面板時的回合結束檢查）；設定後來改成允許，只提醒，不讓主控自行撤回。
   - 為什麼：保留 ADR 0002「問過使用者的題目只有真人能解除」的邊界，同時讓使用者改設定馬上生效。
5. **舊答覆只能補「允不允許」這一個決定。** 任一層寫了 `allow` 就以設定為準；都沒寫時，同專案同動作且未改口的真人答覆可補上，固定條件與分支清單照樣強制。
   - 為什麼：使用者要「反覆討論過的事不必再問」，但寫在設定裡的「要問」不能被舊答覆繞過。
   - 2026-10-30 補記（ouob-tw/LoopAgentTeams-work#403）：移除舊答覆（`check --precedent`、`record --kind precedent` 與 `report` 的對應一組），同樣使用 0 次。參謀的授權來源剩已確認 Spec、真人答覆待決紀錄、預先授權設定三種。同時刪除沒有作用的 `experiment` 鍵，寫了算未知鍵。
6. **Agent 寫設定只能透過工具，附上待決紀錄；工具只核對「有真人答覆」與「紀錄寫明的寫入內容相同」，答覆語意由主控判斷，每次寫入列入交付回報。**
   - 代價：工具無法證明真人答覆真的同意那一條；以事後可檢查取代事前證明。

## 刻意不寫進決定的事

- 檔案格式（TOML）、鍵名與子指令名稱是實作細節，見 LAT 技能的參考文件。
- 新機制與 ouob-tw/LoopAgentTeams-work#99 一樣標為實驗；實驗如何結束另行決定。
