# 整套測試閘門：在資源群組中執行，依實測高峰預約放行

ADR 0005 以固定的同時執行數決定能跑幾套整套測試，名額以測試工作階段判斷存活。主機閒時這個數字讓測試白白排隊，主機忙時又讓測試互相拖慢；各套測試大小差很多，又會分階段變重，放行後等固定秒數看負載也判斷不準。需求見 ouob-tw/LoopAgentTeams-work#241（使用者決定 RUGA-GATE-MODEL、RUGA-GATE-PRESSURE、RUGA-GATE-SPEC）。本 ADR 取代 0005 決定 3 的名額判斷，其餘決定不變。

## 決定

1. **每套整套測試在自己的 systemd 使用者 scope（cgroup v2）中執行；名額存活與中斷以資源群組為準，持有者紀錄仍保留測試主工作階段。**
   - 為什麼：工作階段看不到測試另開工作階段的背景程式；資源群組能完整量到 CPU 與記憶體，也能一次結束所有程序。
   - 代價：依賴 systemd 使用者服務；不可用時退回工作階段做法、不量測。測試正常結束後留在群組裡的程序只警告，不殺、不佔名額。

2. **放行依預約：每條指令以最近幾次實測的最高 CPU 與記憶體為預約量，執行中的測試保留「預約減目前用量」；主機剩餘量扣掉這些保留後放得下，排第一的測試才開跑。**
   - 為什麼：高峰預約不用固定等待時間，也能處理分階段變重；先來後到避免大測試一直被插隊。
   - 代價：沒跑過的指令先用保守預設；排第一的測試放不下時，後面較小的也要等。

3. **主機壓力（PSI）只當煞車，有高低兩道門檻；未滿下限一律放行，上限優先於下限。**
   - 為什麼：IO 等待常來自其他 Agent 與交換空間，當主要條件會一直卡住；下限保證主機再忙也不會全部卡死。
   - 代價：未滿下限時不看任何保護，主機極忙時仍會跑到下限套數。

4. **換版用「暫停後切換」，不長期支援新舊版混跑。**
   - 為什麼：舊版看不到資源群組，閘門被殺而只剩另開工作階段的程序時，會用舊規則提早清掉名額與鎖；查狀態指令也會改寫狀態。
   - 代價：安裝時要請共用主機的主控暫停所有閘門指令，以程序清單確認沒有任何舊版閘門程序後才安裝。
