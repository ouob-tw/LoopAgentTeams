# 主機虛擬機一律經 vm 技能借用，host-guard 擋繞過的指令

主機上的完整作業系統虛擬機（Docker 包的 Windows、macOS）由多個專案的 Agent 共用。原本靠一支開關腳本、一個共用到期檔和一支看守程式，Agent 互相覆寫到期時間、殺掉別人的看守程式、自建關機服務，沒有任何地方記錄誰在用（ouob-tw/LoopAgentTeams-work#668）。

## 決定

1. **借用登記制，不排隊。** 用機器前先借用，借用者取自呼叫者的 HCOM 實例名稱，不接受自報；借出去的機器只有借用者能延長、開機、歸還，只有使用者能強制收回。
   - 為什麼：先做到「看得到誰在用、別人動不了」；排隊等真的常撞車再加。
   - 代價：Agent 必須在 HCOM 下才能借用；同一系統帳號下刻意偽造環境變數仍擋不住。

2. **一個看守程式、一把鎖。** 借用指令與看守程式所有狀態轉換共用同一把鎖，看守在鎖內重讀才關機；看守以使用者層 systemd 服務常駐，取代所有各自的到期檔與關機服務。
   - 為什麼：兩套以上的看守會互相蓋掉期限，或關掉剛延長的機器。

3. **開機看記憶體，不看台數。** 可用記憶體扣掉開機中機器的需求後，夠「需求＋8G」就准開。
   - 為什麼：一次只准一台會讓用不同系統的 Agent 互相卡住，主機記憶體其實夠。

4. **程式在技能裡，資料在 `~/vm`。** 管理程式全部放在 vm 技能資料夾；`~/vm` 只放客體磁碟、客體安裝資料、借用紀錄、紀錄檔與連線設定。
   - 為什麼：程式有版本與測試，跨專案的 Agent 都裝得到；資料夾只剩資料，不會有人改出私人版本。

5. **host-guard 擋繞過，不當資安防線。** 擋 Agent 直接開關清單內容器、寫狀態檔、自建關機排程、未登記或非借用者建立 KVM 容器、任何掛 KVM 的 `docker run`，以及使用使用者專用動作。
   - 為什麼：只寫規則擋不住忙碌中的 Agent；工具攔截能在當下指出正確用法。
   - 代價：Codex 的檔案編輯工具與 Agent 自寫程式不在攔截範圍內。

## 刻意不寫進決定的事

- 一般測試容器不在範圍內，仍依任務卡登記資源歸屬。
- 指令名稱、檔案格式與參數見 vm 技能本身。
