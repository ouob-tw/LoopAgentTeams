# 整套測試閘門：主機共用、以程式內容指紋沿用通過結果、hook 強制走閘門

兩週紀錄顯示過度測試主要來自同一套整套測試被重複執行：每輪修正重跑、實作者／主控／QA 各跑一次、主機滿載超時後重跑。需求見 ouob-tw/LoopAgentTeams-work#188（使用者決定：重複時擋下並可寫原因重跑、套用到主機所有 Agent、同時最多 2 套）。

## 決定

1. **整套測試一律透過 three-tier-testing 技能的專用指令執行，hook 擋下沒走專用指令的整套測試。**
   - 為什麼：規則文字只在當下那段對話有效，主控承認重複後下一位又重來；hook 在執行指令前攔截，對 Claude 與 Codex 都有效。放在 three-tier-testing 而不是 LAT，因為閘門適用所有 Agent。
   - 代價：hook 只看得到指令文字，靠專案登記檔或「測試執行器且沒指定檔案」判斷整套測試，可能誤擋或漏擋；誤擋時寫原因即可重跑。

2. **沿用的依據是工作區內容指紋（追蹤檔與未忽略新檔的 tree 雜湊）加指令與執行目錄，不是 commit。**
   - 為什麼：合併 commit 或不同工作區的內容常常相同，以 commit 判斷會讓整合後的驗證全部重跑。
   - 代價：資料庫、外部服務、被忽略的設定檔不在指紋內；測試期間改了又改回偵測不到。只有結束碼 0 且執行前後指紋相同的紀錄可沿用。

3. **紀錄與名額主機共用；名額以測試工作階段（session）是否仍有程序存活來判斷，取得順序固定為先指紋鎖、後名額。**
   - 為什麼：多個專案同時跑整套才會塞滿主機；以工作階段判斷才不會在專用指令被殺、而測試子程序仍在跑時誤放名額；固定順序避免互相卡死。
   - 代價：只支援 Linux；測試自行另開新工作階段的背景程式不計入名額。
   - 名額判斷已由 [ADR 0007](0007-suite-gate-reservation-admission.md) 取代（資源群組＋預約放行）。
